= 顶点输入描述
:toc:
:toclevels: 3
:toc-title: 目录

== 介绍
在接下来的几章中，我们将用内存中的顶点缓冲区替换顶点着色器中硬编码的顶点数据。首先，我们将介绍最简单的方法：创建一个 CPU 可见的缓冲区，并通过 `memcpy` 直接将顶点数据复制到其中。之后，我们将学习如何使用暂存缓冲区将顶点数据复制到高性能内存中。

== 顶点着色器
首先，修改顶点着色器，使其不再在着色器代码本身中包含顶点数据。顶点着色器通过在结构体中按正确顺序声明来从顶点缓冲区获取输入。
[source,slang]
----
struct VSInput {
    float2 inPosition;
    float3 inColor;
};

struct VSOutput {
    float4 pos : SV_Position;
    float3 color;
};

[shader("vertex")]
VSOutput vertMain(VSInput input) {
    VSOutput output;
    output.pos = float4(input.inPosition, 0.0, 1.0);
    output.color = input.inColor;
    return output;
}

[shader("fragment")]
float4 fragMain(VSOutput vertIn) : SV_TARGET {
    return float4(vertIn.color, 1.0);
}
----
`inPosition` 和 `inColor` 变量是顶点属性。它们是在顶点缓冲区中为每个顶点指定的属性，就像我们使用两个数组手动为每个顶点指定位置和颜色一样。

== 顶点数据
我们将顶点数据从着色器代码移到程序代码中的一个数组中。首先，引入 GLM 库，它提供了与线性代数相关的类型，例如向量和矩阵。我们将使用这些类型来指定位置向量和颜色向量。
[source,c++]
----
#include <glm/glm.hpp>
----
创建一个名为 `Vertex` 的新结构体，其中包含我们将在顶点着色器中使用的两个属性：
[source,c++]
----
struct Vertex {
    glm::vec2 pos;
    glm::vec3 color;
}
----
GLM 方便地为我们提供了与着色器语言中使用的向量类型完全匹配的 C++ 类型。
[source,c++]
----
const std::vector<Vertex> vertices = {
    {{0.0f, -0.5f}, {1.0f, 0.0f, 0.0f}},
    {{0.5f, 0.5f}, {0.0f, 1.0f, 0.0f}},
    {{-0.5f, 0.5f}, {0.0f, 0.0f, 1.0f}}
};
----
现在使用该 `Vertex` 结构体来指定顶点数据数组。我们使用的位置和颜色值与之前完全相同，但现在它们被合并到一个顶点数组中。这称为交错顶点属性。

== 装订说明
下一步是告诉 Vulkan 如何将这种数据格式传递给顶点着色器，一旦数据上传到 GPU 内存中。传递这些信息需要两种类型的数据结构。

第一个结构是 `vk::VertexInputBindingDescription`，我们将向该 `Vertex` 结构添加一个成员函数，以用正确的数据填充它。
[source,c++]
----
struct Vertex {
    glm::vec2 pos;
    glm::vec3 color;

    static vk::VertexInputBindingDescription getBindingDescription() {
        return {
            .binding = 0,
            .stride = sizeof(Vertex),
            .inputRate = vk::VertexInputRate::eVertex
        };
    }
};
----
顶点绑定描述了从内存中加载数据到所有顶点的速率。它指定了数据条目之间的字节数，以及是在每个顶点之后还是在每个实例之后移动到下一个数据条目。

我们所有的顶点数据都打包在一个数组中，因此我们只需要一个绑定。该 `binding` 参数指定绑定在绑定数组中的索引。该 `stride` 参数指定相邻条目之间的字节数，并且 `inputRate` 可以具有以下值之一：

* `vk::VertexInputRate::eVertex`：在渲染完每个顶点之后移动到下一个数据条目
* `vk::VertexInputRate::eInstance`：每次操作后，移至下一个数据条目。

我们不会使用实例渲染，所以我们会坚持使用逐顶点数据。

== 属性描述
第二个描述如何处理顶点输入的结构是 `vk::VertexInputAttributeDescription`。我们将给 `Vertex` 添加另一个辅助函数来填充这些结构。
[source,c++]
----
#include <array>
...
static std::array<vk::VertexInputAttributeDescription, 2>getAttributeDescriptions() {
    return {
        {
            {
                .location = 0,
                .binding = 0,
                .format = vk::Format::eR32G32Sfloat,
                .offset = offsetof(Vertex, pos)
            },{
                .location = 1,
                .binding = 0,
                .format = vk::Format::eR32G32B32Sfloat,
                .offset = offsetof(Vertex, color)
            }
        }
    };
}
----
正如函数原型所示，这里会用到两个这样的结构体。属性描述结构体用于描述如何从绑定描述中提取顶点数据块中的顶点属性。我们有两个属性：位置和颜色，因此需要两个属性描述结构体。

该 `location` 参数引用 `location` 顶点着色器中的输入指令。顶点着色器中的位置输入 `0` 是位置信息，它包含两个 32 位浮点分量。该 `binding` 参数告诉 Vulkan 每个顶点的数据来自哪个绑定。

`format` 参数描述属性的数据类型。需要注意的是，格式的指定使用了与颜色格式相同的枚举。以下着色器类型和格式通常一起使用：

* `float`：`vk::Format::eR32Sfloat`
* `float2`：`vk::Format::eR32G32Sfloat`
* `float3`：`vk::Format::eR32G32B32Sfloat`
* `float4`：`vk::Format::eR32G32B32A32Sfloat`

如您所见，您应该使用颜色通道数与着色器数据类型中的组件数相匹配的格式。允许使用比着色器组件数更多的通道，但多余的通道将被静默丢弃。如果通道数少于组件数，则 BGA 组件将使用默认值 `(0, 0, 1)`。颜色类型（`Sfloat`）`Uint` 和 `Sint` 位宽也应与着色器输入的类型相匹配。请参见以下示例：

* `int2` ：`vk::Format::eR32G32Sint`，一个包含 32 位有符号整数的 2 分量向量
* `uint4`：`vk::Format::eR32G32B32A32Uint`，一个包含 4 个分量的 32 位无符号整数的向量
* `double`：`vk::Format::eR64Sfloat`，双精度（64 位）浮点数

该 `format` 参数隐式定义了属性数据的字节大小，`offset` 指定了从顶点数据起始位置开始读取的字节数。`Vertex` 绑定是逐个加载的，位置属性（`pos`）位于此结构体起始位置的偏移量处 `0`。该偏移量 `offsetof` 由宏自动计算。

颜色属性的描述方式也大致相同。

== 管道顶点输入
现在我们需要在 `createGraphicsPipeline` 设置图形管线，使其能够接受这种格式的顶点数据，方法是引用结构体 `vertexInputInfo`。找到该结构体并对其进行修改，使其引用以下两个描述：
[source,c++]
----
auto bindingDescription = Vertex::getBindingDescription();
auto attributeDescriptions = Vertex::getAttributeDescriptions();
vk::PipelineVertexInputStateCreateInfo vertexInputInfo{
    .vertexBindingDescriptionCount = 1,
    .pVertexBindingDescriptions = &bindingDescription,
    .vertexAttributeDescriptionCount = static_cast<uint32_t>(attributeDescriptions.size());
    .pVertexAttributeDescriptions = attributeDescriptions.data()
};
----
现在，流水线已准备好接收容器格式的顶点数据 `vertices`，并将其传递给顶点着色器。xref:创建顶点缓冲区.adoc[下一步]是创建顶点缓冲区，并将顶点数据移动到其中，以便 GPU 能够访问它。
