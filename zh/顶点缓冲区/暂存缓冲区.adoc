= 暂存缓冲区
:toc:
:toclevels: 3
:toc-title:目录

== 介绍
我们目前的顶点缓冲区工作正常，但允许我们从 CPU 访问它的内存类型可能并非显卡读取数据的最佳内存类型。最佳内存带有特定标志 `vk::MemoryPropertyFlagBits::eDeviceLocal` ，通常独立显卡的内存 CPU 无法访问。在本章中，我们将创建两个顶点缓冲区：一个位于CPU可访问内存中的暂存缓冲区，用于上传顶点数组中的数据；以及一个位于设备本地内存中的最终顶点缓冲区。然后，我们将使用缓冲区复制命令将数据从暂存缓冲区移动到最终的顶点缓冲区。

== 转运队列
缓冲区复制命令需要一个支持传输操作的队列族，这可以通过 `vk::QueueFlagBits::eTransfer` 来指示。好消息是，任何具有 `vk::QueueFlagBits::eGraphics` 或 `vk::QueueFlagBits::eCompute` 功能的队列族都已隐式支持 `vk::QueueFlagBits::eTransfer` 传输操作。在这种情况下，实现无需显式地在 `queueFlags` 中列出它。

如果你喜欢挑战，那么你可以尝试使用不同的队列族专门用于传输操作。这需要你对程序进行以下修改：

- 除了 `uint32_t transferQueueIndex`（现在可能应该重命名为 `uint32_t queueIndex`）之外，还引入一个 `graphicsQueueIndex`，并显式地查找具有 `vk::QueueFlagBits::eTransfer` 但非 `vk::QueueFlagBits::eGraphics` 的队列族。
- 修改 `createLogicalDevice` 以请求一个句柄 `vk::raii::Queue transferQueue`（并可能将 `queue` 重命名为 `graphicsQueue`）
- 创建第二个命令池，用于处理提交到传输队列族的命令缓冲区。
- 更改 `sharingMode` 资源类型 `vk::SharingMode::eConcurrent` ，并指定图形和传输队列系列。
- 将任何传输命令（例如本章中我们将使用的命令 `vk::raii::CommandBuffer::copyBuffer` ）提交到传输队列，而不是图形队列。

这需要花点功夫，但它能让你了解队列族之间是如何共享资源的。

== 抽象缓冲区创建
因为本章我们将创建多个缓冲区，所以最好将缓冲区创建操作移到一个辅助函数中。创建一个新函数 `createBuffer`，并将代码 `createVertexBuffer`（映射除外）移到该函数中。

[source,c++]
----
std::pair<vk::raii::Buffer, vk::raii::DeviceMemory> createBuffer(vk::DeviceSize size, vk::BufferUsageFlags usage, vk::MemoryPropertyFlags properties)
{
  vk::BufferCreateInfo   bufferInfo{.size = size, .usage = usage, .sharingMode = vk::SharingMode::eExclusive};
  vk::raii::Buffer       buffer          = vk::raii::Buffer(device, bufferInfo);
  vk::MemoryRequirements memRequirements = buffer.getMemoryRequirements();
  vk::MemoryAllocateInfo allocInfo{.allocationSize = memRequirements.size, .memoryTypeIndex = findMemoryType(memRequirements.memoryTypeBits, properties)};
  vk::raii::DeviceMemory bufferMemory = vk::raii::DeviceMemory(device, allocInfo);
  buffer.bindMemory(*bufferMemory, 0);
  return {std::move(buffer), std::move(bufferMemory)};
}
----
请务必添加缓冲区大小、内存属性和使用情况等参数，以便我们可以使用此函数创建多种不同类型的缓冲区。此 `std::pair` 函数会返回生成的缓冲区及其绑定的设备内存。由于 `vk::raii` 句柄无法复制，因此必须将其移出此函数。

现在您可以移除缓冲区创建和内存分配代码， `createVertexBuffer` 只需调用以下代码 `createBuffer` 即可：

[source,c++]
----
void createVertexBuffer()
{
  vk::DeviceSize bufferSize = sizeof(vertices[0]) * vertices.size();

  auto [stagingBuffer, stagingBufferMemory] =
      createBuffer(bufferSize, vk::BufferUsageFlagBits::eTransferSrc, vk::MemoryPropertyFlagBits::eHostVisible | vk::MemoryPropertyFlagBits::eHostCoherent);

  void *dataStaging = stagingBufferMemory.mapMemory(0, bufferSize);
  memcpy(dataStaging, vertices.data(), bufferSize);
  stagingBufferMemory.unmapMemory();
}
----

== 使用暂存缓冲区
现在我们将改 `createVertexBuffer` 为仅使用主机可见缓冲区作为临时缓冲区，而使用设备本地缓冲区作为实际顶点缓冲区。

[source,c++]
----
void createVertexBuffer()
{
  vk::DeviceSize bufferSize = sizeof(vertices[0]) * vertices.size();

  auto [stagingBuffer, stagingBufferMemory] =
      createBuffer(bufferSize, vk::BufferUsageFlagBits::eTransferSrc, vk::MemoryPropertyFlagBits::eHostVisible | vk::MemoryPropertyFlagBits::eHostCoherent);

  void *dataStaging = stagingBufferMemory.mapMemory(0, bufferSize);
  memcpy(dataStaging, vertices.data(), bufferSize);
  stagingBufferMemory.unmapMemory();

  std::tie(vertexBuffer, vertexBufferMemory) =
      createBuffer(bufferSize, vk::BufferUsageFlagBits::eVertexBuffer | vk::BufferUsageFlagBits::eTransferDst, vk::MemoryPropertyFlagBits::eDeviceLocal);

  copyBuffer(stagingBuffer, vertexBuffer, bufferSize);
}
----
我们现在使用一个新的 `stagingBuffer` 方法 `stagingBufferMemory` 来映射和复制顶点数据。在本章中，我们将使用两个新的缓冲区使用标志：

- `vk::BufferUsageFlagBits::eTransferSrc` 缓冲区可以用作内存传输操作中的源。
- `vk::BufferUsageFlagBits::eTransferDst` 缓冲区可以用作内存传输操作的目标位置。

现在，该缓冲 `vertexBuffer` 是从设备本地内存类型分配的，这通常意味着我们无法使用它 `vk::raii::DeviceMemory::mapMemory` 。但是，我们可以将数据从 `stagingBuffer` 复制到 `vertexBuffer`。我们必须通过指定传输源标志和传输目标 `stagingBuffer` 标志以及顶点缓冲区 `vertexBuffer` 使用标志来表明我们打算这样做。

现在我们要编写一个函数，将内容从一个缓冲区复制到另一个缓冲区，该函数名为 `copyBuffer`。

[source,c++]
----
void copyBuffer(vk::raii::Buffer & srcBuffer, vk::raii::Buffer & dstBuffer, vk::DeviceSize size)
{
}
----
内存传输操作与绘图命令一样，都是使用命令缓冲区执行的。因此，我们必须首先分配一个临时命令缓冲区。您可能需要为这类短生命周期缓冲区创建一个单独的命令池，因为实现可能能够应用内存分配优化。在这种情况下，您应该在生成命令池时使用相应的标志 `vk::CommandPoolCreateFlagBits::eTransient`。

[source,c++]
----
void copyBuffer(vk::raii::Buffer & srcBuffer, vk::raii::Buffer & dstBuffer, vk::DeviceSize size)
{
  vk::CommandBufferAllocateInfo allocInfo{ .commandPool = commandPool, .level = vk::CommandBufferLevel::ePrimary, .commandBufferCount = 1 };
  vk::raii::CommandBuffer commandCopyBuffer = std::move(device.allocateCommandBuffers(allocInfo).front());
}
----
立即开始记录命令缓冲区：

[source,c++]
----
commandCopyBuffer.begin({.flags = vk::CommandBufferUsageFlagBits::eOneTimeSubmit});
----
我们只会使用一次命令缓冲区，并且会等待函数执行完毕后再返回。使用 `vk::CommandBufferUsageFlagBits::eOneTimeSubmit` 来告知驱动程序我们的意图是一种良好的实践。

[source,c++]
----
commandCopyBuffer.copyBuffer(*srcBuffer, *dstBuffer, vk::BufferCopy(0, 0, size));
----
`vk::raii::CommandBuffer::copyBuffer` 命令用于传输缓冲区内容。`vk::BufferCopy` 接受源缓冲区和目标缓冲区作为参数，以及一个要复制的区域数组。这些区域在结构体中定义，包含源缓冲区偏移量、目标缓冲区偏移量和大小 `vk::WholeSize`。与 `vk::raii::DeviceMemory::mapMemory` 命令不同，此处无法指定。

[source,c++]
----
commandCopyBuffer.end();
----
此命令缓冲区仅包含复制命令，因此我们可以立即停止录制。现在执行命令缓冲区以完成传输：

[source,c++]
----
queue.submit(vk::SubmitInfo{.commandBufferCount = 1, .pCommandBuffers = &*commandCopyBuffer}, nullptr);
queue.waitIdle();
----
与绘制命令不同，这次我们不需要等待任何事件。我们只想立即执行缓冲区传输。同样，有两种方法可以等待传输完成。我们可以使用栅栏并等待 `vk::raii::Device::waitForFences`，或者直接等待传输队列空闲 `vk::raii::Queue::waitIdle`。栅栏允许您同时调度多个传输并等待它们全部完成，而不是一次执行一个。这可能会为驱动程序提供更多优化机会。

现在我们可以 `copyBuffer` 从 `createVertexBuffer` 函数中调用该函数，将顶点数据移动到设备本地缓冲区：

[source,c++]
----
copyBuffer(stagingBuffer, vertexBuffer, bufferSize);
----
将数据从暂存缓冲区复制到设备缓冲区后，RAII 缓冲区对象将清理自身并释放内存。

运行程序以验证是否再次看到了熟悉的三角形。改进可能现在还看不出来，但它的顶点数据现在是从高性能内存加载的。当我们开始渲染更复杂的几何体时，这一点至关重要。

== 结论
需要注意的是，在实际应用中，你不应该 `vk::raii::Device::allocateMemory` 为每个缓冲区都单独调用内存分配函数。同时进行内存分配的最大数量 `maxMemoryAllocationCount` 受限于物理设备的限制，即使是像 NVIDIA GTX 1080 这样的高端硬件，其限制也可能很低。为大量对象同时分配内存的正确方法是创建一个自定义分配器，利用 `offset` 我们在许多函数中看到的参数，将一次内存分配拆分成多个不同的对象。

你可以自己实现这样的内存分配器，也可以使用GPUOpen 项目提供的 https://github.com/GPUOpen-LibrariesAndSDKs/VulkanMemoryAllocator[VulkanMemoryAllocator] 库。不过，在本教程中，为每个资源单独分配内存是可以的，因为我们目前还不会遇到任何限制。
