== 介绍
我们目前的顶点缓冲区工作正常，但允许我们从 CPU 访问它的内存类型可能并非显卡读取数据的最佳内存类型。最佳内存带有特定标志 `vk::MemoryPropertyFlagBits::eDeviceLocal` ，通常独立显卡的内存 CPU 无法访问。在本章中，我们将创建两个顶点缓冲区：一个位于CPU可访问内存中的暂存缓冲区，用于上传顶点数组中的数据；以及一个位于设备本地内存中的最终顶点缓冲区。然后，我们将使用缓冲区复制命令将数据从暂存缓冲区移动到最终的顶点缓冲区。

== 转运队列
缓冲区复制命令需要一个支持传输操作的队列族，这可以通过 `vk::QueueFlagBits::eTransfer` 来指示。好消息是，任何具有 `vk::QueueFlagBits::eGraphics` 或 `vk::QueueFlagBits::eCompute` 功能的队列族都已隐式支持 `vk::QueueFlagBits::eTransfer` 传输操作。在这种情况下，实现无需显式地在 `queueFlags` 中列出它。

如果你喜欢挑战，那么你可以尝试使用不同的队列族专门用于传输操作。这需要你对程序进行以下修改：

- 除了 `uint32_t transferQueueIndex`（现在可能应该重命名为 `uint32_t queueIndex`）之外，还引入一个 `graphicsQueueIndex`，并显式地查找具有 `vk::QueueFlagBits::eTransfer` 但非 `vk::QueueFlagBits::eGraphics` 的队列族。
- 修改 `createLogicalDevice` 以请求一个句柄 `vk::raii::Queue transferQueue`（并可能将 `queue` 重命名为 `graphicsQueue`）
- 创建第二个命令池，用于处理提交到传输队列族的命令缓冲区。
- 更改 `sharingMode` 资源类型 `vk::SharingMode::eConcurrent` ，并指定图形和传输队列系列。
- 将任何传输命令（例如本章中我们将使用的命令 `vk::raii::CommandBuffer::copyBuffer` ）提交到传输队列，而不是图形队列。

这需要花点功夫，但它能让你了解队列族之间是如何共享资源的。
