= 传输队列与资产流式加载同步：非阻塞上传

== 简介

在现代的开放世界游戏或复杂的建筑可视化中，我们无法承受一次性加载全部资产。我们需要在玩家穿行世界时，于后台流式加载纹理、网格和动画数据。如果在主图形队列上做这件事，那么每次提交大批量上传时都可能引入「卡顿」（丢帧）。

解决方案是使用**专用传输队列**。大多数现代 GPU 都有一台专为把数据从 CPU 可见的暂存缓冲区搬运到 GPU 最优内存而设计的专用引擎。这台引擎可以完全独立于图形与计算单元运行，让我们流式加载数 GB 的数据而不影响帧率。

== 暂存管线

资产流式加载是一个多步骤的过程。首先，CPU 映射一个**暂存缓冲区**并写入原始数据（例如 PNG 或网格文件）。然后，用传输队列把数据拷贝到 **GPU 最优缓冲区或图像**中。最后，通知图形队列数据已就绪，以便它开始在着色器中使用这些数据。

挑战一如既往，是同步。我们必须确保：

1.  **CPU 到传输**：在 CPU 完成对暂存缓冲区的写入之前，传输队列不会开始拷贝。
2.  **传输到 GPU**：传输操作已完成，数据在 GPU 内存中可见。
3.  **传输到图形**：在传输队列完成工作并（如有必要）释放资源所有权之前，图形队列不会尝试采样该纹理。

== 我们将构建什么

在本章中，我们将实现一个健壮的非阻塞资产流式加载系统。我们会探讨：

1.  **非阻塞数据上传**：如何利用专用传输队列在后台流式加载纹理与缓冲区。
2.  **暂存同步**：协调**时间线信号量**，确保图形队列在采样新数据之前等待传输完成。
3.  **所有权握手**：实现我们在第 3 章学到的队列族所有权转移，但放在后台流式加载系统的语境中。

到本章结束时，你将拥有一个流式加载架构，让引擎能在后台加载海量数据，同时保持帧率完全平稳、毫无卡顿。
