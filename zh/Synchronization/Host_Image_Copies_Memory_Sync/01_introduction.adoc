= 主机图像拷贝与内存映射同步：直接访问

== 引言

在 Vulkan 历史的大部分时间里，如果你想往图像里搬数据，就必须遵循一套特定的仪式：创建暂存缓冲区、映射它、写入数据、录制 `copyBufferToImage` 命令，然后把该命令缓冲区提交到队列。对大型异步上传来说这很高效，但对简单直接的更新——比如更新一张小 UI 纹理或单个 mip 层级——开销就太大了。

随着 **Vulkan 1.4** 的到来，我们有了一个强大的新工具：**主机图像拷贝**（Host Image Copies，`VK_EXT_host_image_copy`）。这个特性让 CPU 可以直接把数据拷贝进 GPU 最优布局的图像，无需录制或提交任何命令缓冲区。这是在 CPU 与 GPU 内存之间搬数据最直接的方式。

[NOTE]
====
尽管主机图像拷贝在 Vulkan 1.4 中已提升为核心特性，对它的支持仍然是**可选的**。你必须检查 `VkPhysicalDeviceHostImageCopyFeaturesEXT`（或 1.4 中的等价物），确认你的硬件和驱动支持这条直接通路。
====

== 同步挑战

主机图像拷贝简化了搬数据的“怎么做”，但并不能豁免我们回答“什么时候”。因为我们是在主机（CPU）上直接搬数据，必须格外小心，确保我们写入图像时 GPU 没有在使用同一张图像。

这引入了另一种同步。我们同步的不再是两个 GPU 队列，而是**主机**与**设备**。我们需要确保主机写入对 GPU 是**可见的**，并且在我们开始主机拷贝之前，之前所有 GPU 工作都已**可用**。

== 本章内容

在本章中，我们会深入主机侧同步的世界。我们会探索：

1.  **CPU 直接访问图像**：如何利用 Vulkan 1.4 新的主机图像拷贝特性高效搬数据，避免命令缓冲区开销。
2.  **可见性与刷新**：专门针对主机映射内存掌握 `vk::MemoryBarrier2`。我们会学习如何确保数据在总线上的一致性，保证我们在 CPU 上写下的字节正是 GPU 看到的内容。
3.  **主机与设备握手**：用栅栏和时间线信号量协调，确保主机侧拷贝永远不会与正在进行的 GPU 渲染相撞。

学完本章，你会完整理解现代 Vulkan 中如何管理直接内存访问，从而拥有一种更快、更灵活的方式来保持资产更新。
