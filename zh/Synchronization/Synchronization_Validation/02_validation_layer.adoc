= 验证层：配置你的环境

== 启用同步验证

**LunarG 同步验证**层并非在所有平台上都默认包含在标准的 `VK_LAYER_KHRONOS_validation` 里。在许多环境中，你必须通过 `vk_layer_settings.txt` 文件或引擎的 `vk::InstanceCreateInfo` 显式启用它。

[TIP]
====
开发期间管理它更简便的方法是使用 **vkconfig**（LunarG Vulkan Configurator）。这个随 Vulkan SDK 一起提供的 GUI 工具允许你一键全局启用或禁用同步验证，而无需修改源代码或项目配置。
====

要通过实例启用它，你把 `VK_VALIDATION_FEATURE_ENABLE_SYNCHRONIZATION_VALIDATION_EXT` 标志加到 `vk::ValidationFeaturesEXT` 结构中，并把它作为 `vk::InstanceCreateInfo` 的 `pNext` 传入。

[,cpp]
----
auto syncValidationFeature = vk::ValidationFeaturesEXT{
    .enabledValidationFeatureCount = 1,
    .pEnabledValidationFeatures = &vk::ValidationFeatureEnableEXT::eSynchronizationValidation
};

auto instanceCreateInfo = vk::InstanceCreateInfo{
    .pNext = &syncValidationFeature,
    // ...
};

auto instance = vk::raii::Instance(context, instanceCreateInfo);
----

== 使用 vk_layer_settings.txt

更灵活的做法是：在应用程序的工作目录下创建 `vk_layer_settings.txt` 文件。这个文件让你无需重新编译代码就能配置验证层的许多方面。

----
# Example vk_layer_settings.txt
khronos_validation.enables = VK_VALIDATION_FEATURE_ENABLE_SYNCHRONIZATION_VALIDATION_EXT
khronos_validation.report_flags = error;warning;perf;info
----

== 该层实际做了什么

一旦启用，同步验证层就开始跟踪引擎中的每一个资源。它记录最后一个写入资源的阶段、当前正在读取它的阶段，以及排队中的下一个阶段。

如果它检测到两个阶段在没有恰当屏障的情况下访问同一块内存——例如片元着色器在传输拷贝完成之前就开始读取纹理——该层就会发出验证错误。

需要注意的是，同步验证层有**不小的性能开销**。它不适合留在生产或发布构建中。它应当只在开发与测试期间使用，以便在危险变成缺陷之前抓住它们。

== Simple Engine：开发工作流

在 `Simple Engine` 中，我们把同步验证直接集成进调试构建。当你用 `--debug-sync` 命令行标志运行引擎（或在 `renderer_core.cpp` 中启用它）时，我们会自动把 `vk::ValidationFeatureEnableEXT::eSynchronizationValidation` 加到实例创建中。

这是我们开发工作流的关键部分。每当我们新增一个渲染通道——比如最近的 **Forward+ 光照**或**光线查询阴影**——我们都会在启用同步验证的情况下运行引擎。这让我们能尽早抓住「读后写」（WAR）或「写后读」（RAW）危险，在它们表现为闪烁像素或间歇性 GPU 挂起之前就解决掉。让工具替我们找这些危险，我们就能多花时间优化引擎，少花时间追查难以捉摸的同步缺陷。
