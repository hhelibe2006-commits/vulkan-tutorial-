= 使用同步验证调试：找出你的危险

== 引言

Vulkan 同步是一个「信任但验证」的系统。你可以写出自认为完全正确的 `vk::DependencyInfo` 和 `vk::SubmitInfo2` 代码，但唯一能绝对确定的方法，是拿它去对照真实的硬件行为做测试。然而，同步缺陷出了名地难找。它们常常表现为细微的闪烁、偶发的崩溃，或者最糟糕的情况——在你的开发机上表现完美，到了客户的 GPU 上却彻底失败。

**LunarG 同步验证**层正是为此而生。它毫无疑问是你 Vulkan 调试武器库中最重要的工具。标准验证层检查的是 API 使用错误，而同步验证层会跟踪引擎中每个资源的状态，找出导致数据损坏的「写后读」（RAW）、「读后写」（WAR）和「写后写」（WAW）危险。

== 我们面对的危险

同步本质上就是管理这三类危险：

1.  **写后读（RAW）**：某个阶段试图读取资源，而之前的阶段尚未写完。这是「垃圾」数据最常见的成因。
2.  **读后写（WAR）**：某个阶段试图写入资源，而之前的阶段还在读它。这会导致前一阶段读到「更新到一半」的数据。
3.  **写后写（WAW）**：两个阶段试图同时写入同一资源。结果不可预测，几乎总是导致损坏。

== 我们将探索什么

本章我们会学习如何借助验证层让引擎变得完全健壮。我们将探索：

1.  **验证层**：如何在引擎的调试构建中配置并启用 LunarG 同步验证层。
2.  **解读 VUID**：Vulkan 验证唯一标识符（VUID）可能令人望而生畏。我们会学习如何破解这些复杂的错误消息，并把它们转化为可执行的代码修复。
3.  **识别危险**：我们会看到真实案例，了解验证层如何捕获那些靠人工检查几乎不可能发现的危险。

到本章结束时，你将拥有相应的工具与知识，确保你的同步代码不只是「大体正确」，而是「经 Vulkan 验证」的正确。
