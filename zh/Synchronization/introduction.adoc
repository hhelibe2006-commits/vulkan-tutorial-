= Synchronization 2：精通 GPU 与 CPU 的握手

== 简介

欢迎来到 **Synchronization 2** 教程系列！如果你在 Vulkan 上花过不少时间，很可能遇到过「同步之墙」。就是那一刻：你的代码在开发机上运行完美，在另一台机器上却闪烁；或者你意识到，你那块高性能 GPU 有一半时间都在等一个过于保守的屏障。

可以说，同步是 Vulkan 中最具挑战性的部分，但也是最强大的部分。它是我们用来精确告诉硬件数据如何在管线中流动的语言。在本系列中，我们将超越 Vulkan 1.0 那套遗留同步体系——那些碎片化的位掩码和二值信号量——转而拥抱现代标准：**Synchronization 2** 与**时间线信号量**。

=== 为什么需要新系统？

Vulkan 1.0 的同步在控制力上是一次突破，但它出了名地难以使用或理解。最初的管线屏障被拆分到多个结构体中，阶段掩码常常让人觉得是为十年前的硬件设计的；毕竟，它设计于十年前。写作本文时 Vulkan 已有 10 年历史，现代技术与现代硬件带来了一些更好的方式，同时保持了同等程度的控制力。

Synchronization 2 最初作为扩展出现，如今是 Vulkan 1.3 的核心部分。它把一切都统一到 `vk::DependencyInfo` 结构中，从而简化了这幅图景。它提供了一种更清晰、更直观的方式来定义依赖，使用 64 位掩码，能够以手术般的精度瞄准现代硬件单元——例如任务着色器与网格着色器。

当它与**时间线信号量**结合时，我们就从「二元」信号（开或关）的世界迈向单调计数器的世界。这让我们可以把整个 GPU/CPU 执行过程视为一条单一、统一的时间线，从而极大地简化多帧在途与异步工作的管理。

=== 你将学到什么

这不仅仅是一份 API 调用清单。我们要构建一套达到引擎级水准的同步架构。在本系列中，我们将：

1.  **解构依赖关系**：深入底层，看看 GPU 实际如何处理内存，以及为什么单靠「执行依赖」不足以防止数据损坏。
2.  **掌握新的屏障**：你将学会用 `vk::DependencyInfo` 取代旧的屏障，让代码更整洁、性能更好。
3.  **驾驭时间线**：我们将把时间线信号量实现为引擎的「主时钟」，用更健壮的单调计数器取代栅栏与二值信号量。
4.  **为并发而架构**：我们将重建主引擎循环，以支持多帧在途，并实现与主图形工作重叠的异步计算与传输操作。
5.  **利用现代 Vulkan**：我们将深入 Vulkan 1.4 的特性，包括**主机图像拷贝**以及**动态渲染**中的瓦片本地读取，以站在 API 的最前沿。

=== 前置条件

本系列被设计为「高级主题」，直接建立在我们主 Vulkan 教程所奠定的基础之上。我们假设你熟悉：

*   基本的 Vulkan 渲染循环（命令缓冲区、管线、描述符集）。
*   现代 C++（RAII、智能指针和基本模板）。
*   图形管线的基本概念（顶点/片元阶段）。

如果你是 Vulkan 新手，我们强烈建议先完成 xref:00_Introduction.adoc[主教程]。对于跟随我们引擎构建之旅的读者，本系列与 xref:Building_a_Simple_Engine/introduction.adoc[构建简易引擎：简介]教程完美互补，提供了打造真正专业级渲染器所需的深入同步知识。

=== 关于工具的说明

在本系列中，我们的所有着色器示例都将使用 **Slang**。Slang 的生产力特性以及面向 Vulkan SPIR-V 的能力，自然使它成为现代同步的完美搭档。我们还会大量依赖 **LunarG Synchronization Validation** 层——在找出「写后读」（WAR）和「读后写」（RAW）危险时，它是你最好的朋友，这类危险手动追踪起来极其困难。

让我们先从拆解一个依赖关系开始，看看它到底由什么构成。
