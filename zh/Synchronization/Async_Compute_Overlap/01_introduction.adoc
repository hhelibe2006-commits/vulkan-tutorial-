= 异步计算与执行重叠：让 GPU 并行起来

== 简介

在许多渲染架构中，工作是以线性事件序列的方式提交的。我们先画阴影，再画几何，然后运行一个基于计算的后处理通道。这种「串行」方式容易理解，却常常让 GPU 硬件的很大一部分闲置。现代 GPU 由多个相互独立的单元组成——图形管线、计算单元、传输引擎——它们能够、也应该同时工作。

**异步计算**是指在主图形队列忙于自己的工作时，把计算类工作负载（如物理、遮挡剔除或后处理）放到专用计算队列上运行。做得好的话，这能有效填补 GPU 执行时间线上的「空洞」，带来巨大的性能收益。

== 「气泡」问题

高性能的头号敌人是**管线停顿**，常被称为「气泡」。当 GPU 的某一部分完成了自己的工作，却因为等待一个尚未满足的依赖而无法开始下一项任务时，就会发生这种情况。如果你的屏障过于保守——比如你告诉 GPU 要等「所有命令」完成才能开始一个计算通道——即便计算工作本可以早得多就开始，你也等于强迫硬件进入串行模式。

== 为重叠而设计架构

要实现真正的执行重叠，我们需要超越简单的「管线顶端到管线底端」依赖。我们需要设计 `vk::DependencyInfo` 和**时间线信号量**，以精确表达数据就绪的时刻。

本章我们将探讨：

1.  **最大化吞吐量**：如何识别适合重叠的工作负载，以及如何组织提交，让 GPU 占用率尽可能高。
2.  **异步后处理**：我们会实现一个常见的真实模式：让基于计算的泛光或色调映射与下一帧的阴影或几何通道并发运行。
3.  **消除停顿**：我们会学习如何使用硬件性能分析器和同步验证来找出那些难以捉摸的「气泡」，并细化阶段掩码以消除它们。

到本章结束时，你将能把引擎从串行序列转为并行执行模型，确保没有硬件单元闲着。
