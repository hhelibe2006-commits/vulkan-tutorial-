= 性能分析、批处理与优化：榨取 GPU 性能

== 引言

恭喜！你已经掌握了 **Synchronization 2** 的核心机制、**时间线信号量**的单调世界，以及**异步计算**与**资产流式加载**的复杂性。你构建出了一个健壮、现代且通过验证的渲染器。

但在高性能图形的世界里，「正确」只是起点。最后的挑战是让你的同步尽可能高效。你录制的每个屏障、发出的每个信号量都有代价——无论是在驱动开销上，还是在潜在的硬件停顿上。

在这最后一章，我们将走出同步的「怎么做」和「为什么」，专注于「有多快」。我们会探索专业引擎开发者用来从 GPU 里榨出最后一丝性能的高级技巧。

== 优化的思维方式

同步中的优化是一种平衡艺术。一方面，你希望尽可能具体，以避免不必要的停顿；另一方面，你希望尽量减少调用驱动的次数。

关键在于以**批处理**和**可见性**的角度思考。不要孤立地考虑每个资源，而应把整帧当作一个整体：哪里可以合并依赖？哪里可以移动屏障让更多工作重叠？哪里可以用硬件性能分析工具找出那些拖住帧率的「隐形」瓶颈？

== 我们将探索什么

在这最后一章，我们会深入 Vulkan 优化的高级世界。我们将探索：

1.  **屏障批处理**：如何把多个全局、图像和缓冲区屏障合并进单次 `vkCmdPipelineBarrier2` 调用，以降低驱动开销。
2.  **可视化停顿**：我们会重温第 6 章的「气泡」问题，但这次重点放在用硬件分析器大规模地发现并消除它们。
3.  **最后的打磨**：我们会用一份最佳实践与常见陷阱清单来收尾本系列，确保你的引擎在成长过程中始终保持高性能。

到本章结束时，你将拥有把渲染器从「通过验证」推进到「经过优化」的知识与工具，确保你的同步代码既正确又快速。
