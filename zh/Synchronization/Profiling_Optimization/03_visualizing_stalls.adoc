= 可视化停顿：找出管线气泡

== 硬件性能分析器

优化同步代码最有效的办法，是看到 GPU 实际在做什么。我们用 **NVIDIA Nsight Graphics** 或 **AMD Radeon GPU Profiler** 这类硬件性能分析器来把管线可视化。

在这些工具里，你可以看到「时间线」视图，精确显示 GPU 的每个部分（图形核心、计算核心、传输引擎）何时忙碌。**管线气泡**就是这条时间线上的空隙——一段硬件因为等待尚未到达的依赖而空闲的时期。

== 定位原因

当你发现一个气泡时，必须确定它的成因。它是一个真实的依赖（例如光照通道在等 G-Buffer 完成）？还是一个过于保守的屏障造成的人为停顿？

一个常见错误是给每个屏障都用 `vk::PipelineStageFlagBits2::eAllCommands`。这等于告诉 GPU：「停下手头一切，直到之前所有命令都完成。」这是把巨大的「大锤」，可能制造出巨大的气泡。相反，你应当始终使用尽可能具体的阶段掩码（例如 `eColorAttachmentOutput`）。

== 实践中的精化

要精化你的掩码，按以下流程操作：

1.  **找出气泡**：在性能分析器的时间线里找到空隙。
2.  **确认依赖**：查看这个空隙之前的那个屏障。
3.  **精化阶段掩码**：检查该依赖是否可以用更早的阶段满足。例如，你的阴影通道能否在上一帧的顶点工作一完成就开始？
4.  **验证修复**：重新运行分析器，检查气泡是否缩小或消失。
