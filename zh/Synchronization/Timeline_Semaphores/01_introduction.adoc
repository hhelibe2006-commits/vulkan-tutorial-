= 时间线信号量：主时钟

== 简介

多年来，Vulkan 开发者不得不在两种截然不同的同步原语之间周旋：**二值信号量**与**栅栏**。二值信号量专用于 GPU 到 GPU 的同步（例如在采样某张图像之前等待它准备就绪），而栅栏用于 GPU 到 CPU 的同步（例如在复用某个命令缓冲区的资源之前等待它执行完毕）。

这种分裂迫使我们为本质上相同的问题——「工作完成了吗？」——编写两套不同的逻辑。它还导致复杂的「信号量链」，这类结构出了名地难以调试。

**时间线信号量**最初作为扩展引入，如今已是 Vulkan 1.2+ 的核心部分，它改变了一切。它提供单一、统一的原语，用一个简单的单调 `uint64_t` 计数器就能同时处理 GPU 到 GPU 和 GPU 到 CPU 的同步。

== 单调的世界

在基于时间线的系统中，进度由只会不断增大的值来衡量。当你向 GPU 提交一项工作时，你告诉它：「完成这项工作后，把信号量的值设为 10。」如果另一项工作需要那份数据，你就告诉它：「在信号量值至少达到 10 之前不要开始。」

这个简单的变化对我们如何架构引擎有着深远的影响：

1.  **统一的逻辑**：我们不再关心「等待者」是 CPU 还是 GPU。接口是一样的：等待某个特定的值。
2.  **信号前等待**：时间线信号量最强大的特性之一是，你可以向 GPU 提交一项等待某个尚未达到的值的工作。这让我们能把提交逻辑与执行逻辑解耦。
3.  **更好的调试**：由于值只是一个简单的整数，我们可以轻松记录它、在调试器中查看它，甚至用它为引擎的进度构建可视化性能分析器。

[NOTE]
====
有一个当前的限制需要留意：**窗口系统集成（WSI）**。截至当前的 Vulkan 规范，交换链的获取与呈现操作仍然需要传统的二值信号量，还不能直接等待时间线信号量，也不能由它直接发出通知。
====

在本章中，我们将探索如何把时间线信号量实现为渲染器的「主时钟」。我们会先看看如何替换掉旧的栅栏与二值信号量，然后深入单调计数器的实现，以及极其高效的信号前等待提交模式。
