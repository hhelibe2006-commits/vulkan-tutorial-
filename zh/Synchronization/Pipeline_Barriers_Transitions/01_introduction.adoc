= 管线屏障与布局转换：核心循环

== 引言

如果上一章讲的是理解 GPU 各阶段之间理论上的「握手」，那么这一章就是我们挽起袖子、动手实现细节的地方。在现代 Vulkan 1.3+ 的图景中，`vk::ImageMemoryBarrier2` 是我们同步工具箱里最常用的工具。我们用它来在布局之间转换图像、确保数据在不同硬件缓存之间可见，并管理高性能渲染所需的复杂状态变化。

我们常常把图像想成一块像素网格，但对 GPU 来说，它是一个可以针对不同访问类型进行优化的精细资源。适合作为颜色附件写入的布局，在片元着色器中采样时可能非常糟糕。高效地管理这些转换——并且只在严格必要时才转换——正是卡顿的渲染器与流畅的 60 FPS 体验之间的分水岭。

在本章中，我们将深入这些屏障的工作机制。我们先从图像屏障自身的结构讲起，尤其是在**动态渲染**的语境下——它已在很大程度上取代了旧的「渲染通道」体系。然后我们会处理 Vulkan 中最容易被误解的话题之一：**队列族所有权**。当你想在引擎的图形、计算和传输队列之间移动资源（比如纹理或缓冲区）时，需要显式地进行这种「交接」。

最后，我们会看看这些选择对性能的影响。Vulkan 允许我们使用**全局内存屏障**，或者更具体的、绑定到资源的屏障。我们会学习如何判断该用哪一种、什么时候用，从而给驱动程序恰到好处的信息，让硬件全速运转，又不引入不必要的停顿。

让我们先来看看现代 Vulkan 同步的主力军：图像内存屏障 2。
