= 你的 GPU 究竟在做什么

== 一个一直到底的档案柜

要理解 alpha 测试为什么昂贵，你需要一个心智模型：GPU 如何找出光线可能击中的那些三角形。对每条光线检查场景中的每个三角形会慢得灾难性——一个现代场景可能有上百万个三角形，而 4K 一帧有上百万像素，每个像素都投射阴影光线。暴力计算的代价将是每帧数万亿次运算。

GPU 通过一种叫**包围体层次结构**（**BVH**）的空间数据结构来避免这一点。想象一个档案柜。最上层的抽屉里放着一个包住整个场景的大盒子。这个大盒子里有几个更小的盒子，每个包住场景的一个主要区域——也许是左半边和右半边。每个小盒子里还有更小的盒子，继续细分下去。在层次结构的底部，每个叶节点包含少量真正的三角形。

当一条光线进入 BVH 时，它先测试最顶层的包围盒。如果没有相交，就结束了——这条光线在整个场景中什么都没击中。如果相交，它就打开那个盒子并测试子节点。它跟随相交的子节点，忽略未相交的。遍历在几何上不断收窄：光线不用测试上百万个三角形，只需测试几十个包围盒，最终触及少数几个候选三角形。这就是光线遍历能够实时完成的原因。

对于完全**不透明**的几何体，事情在三角形这一层就结束了。当遍历发现光线与某个三角形相交时，硬件会发出所谓的**已确认命中**——记录命中距离和表面数据，遍历随即可以终止（或者根据模式继续寻找更近的命中）。这中间不涉及任何着色器代码，完全由固定功能硬件处理。

== any-hit 着色器：一次必要的打断

带 alpha 测试的几何体打破了这个干净的故事。当 BVH 遍历在带 alpha 测试的网格上找到候选三角形时，它不能直接确认命中，必须先检查交点是否真的实心。为此，它必须调用一个可编程着色器——**any-hit 着色器**。

any-hit 着色器接收交点数据：具体来说，是命中点在三角形内的**重心坐标**。重心坐标描述光线究竟落在三角形内的哪个位置，用三个顶点的加权组合表示。根据重心坐标，着色器可以插值出命中点的 UV 纹理坐标。然后它在这些 UV 处采样 alpha 纹理并检查结果。如果 alpha 值高于材质的阈值，命中就是实心的——着色器允许默认的确认流程继续。如果 alpha 值低于阈值，着色器调用忽略函数，遍历继续，去寻找下一个候选。

这是一连串顺序操作——重心插值、UV 插值、一次纹理采样、一次比较、一次判断——必须全部完成，遍历才能继续。而且每出现一个候选命中，都得来一遍。

== 并行性问题：发散

GPU 不是顺序执行的机器。它同时在成百上千个并行执行单元上执行着色器代码。这些单元按称为**波前**（warp，NVIDIA 的术语）或 **wavefront**（AMD 的术语）的分组工作——通常是 32 或 64 个着色器线程锁步执行，同一时刻对不同数据运行同一条指令。正是这种大规模并行的执行模型，让 GPU 能在一帧里着色上百万像素。

锁步模型有一个关键弱点：**发散**。当同一个波前中的不同线程需要走不同的代码路径时——有些线程遇到不透明命中，另一些遇到透明命中——波前就无法继续锁步。它必须把两条代码路径都执行一遍，在每条路径上屏蔽掉不活跃的线程。一半波前等待，另一半跑自己的分支，然后再交换。有效并行度减半，甚至更糟。

alpha 测试是一台制造发散的机器。一个波前里的 32 条阴影光线，有的可能击中叶子三角形的不透明区域，有的击中透明区域，还有的根本没击中任何叶子。不同线程会在不同的三角形上触发 any-hit 着色器。有的线程很快完成 alpha 检查，有的因缓存行为而耗时更久。波前被串行化。执行单元空闲着等待掉队的线程。GPU 的并行吞吐优势，恰恰在最痛的地方蒸发掉了。

== 纹理缓存的灾难

还有第二项相关代价，会把第一项放大：**纹理缓存未命中**。GPU 为纹理数据配备了专用缓存，用来高效地服务纹理采样。在光栅化期间，纹理缓存工作得很好，因为屏幕上相邻的像素往往采样纹理空间中相邻的点——空间相关性意味着相邻线程读取同一批缓存行，缓存始终保持热态。

而在 BVH 遍历期间，光线来自屏幕上任意位置，可能在任意 UV 坐标处击中三角形。同一个波前里的十七条阴影光线，可能在测试十七个完全不同的叶子三角形，各自的 UV 坐标不同，散落在纹理图集各处。每次采样都可能落在纹理内存的不同区域。缓存一次又一次地返回冷未命中。纹理单元——原本是为具有一致性的光栅化访问而构建的——反复停顿，等待从显存取回数据。

纹理内存带宽是有限的，还要与 GPU 上同时进行的其它操作共享。any-hit 着色器中的缓存未命中会争抢这份带宽。在森林场景中，any-hit 着色器调用造成的纹理缓存抖动，可能占到整帧时间的相当大一部分。

== 算一算代价

让我们用具体数字来建立直觉。假设一个森林场景在阴影视锥内有 50,000 个可见的叶子三角形。阴影贴图方案每帧以低分辨率处理这些三角形一次。在我们的光线追踪系统里，1080p 下每像素投射 16 条阴影光线，于是约 3300 万像素乘以 16 条光线——大约 5.3 亿条阴影光线。每条阴影光线平均可能穿过 3 到 5 个叶子三角形，直到要么找到不透明命中，要么穿出树冠。这样每帧的 any-hit 着色器调用就在 15 亿到 25 亿次之间，每次都需要一次纹理采样，全都在争抢缓存，全都在引入发散。

一块现代 GPU 每秒大概能执行 500 亿到 1000 亿次简单运算。但 any-hit 着色器不是简单运算——它是带纹理采样、依赖内存做决策的分支着色器。现实一点说，每次调用要花几十纳秒。算出来的结果并不让人舒服。

== 根本洞见

这里的浪费不是算法意义上的计算浪费——就硬件所知的信息而言，any-hit 着色器做的正是它必须做的事。浪费是信息层面的。GPU 在运行时才发现那些在场景加载时就已可获得的信息。alpha 纹理在帧与帧之间不变。每个三角形与其 alpha 掩码之间的关系不变。每一次 any-hit 着色器调用，都在重新发现一件本来可以提前知道的事。

这就是问题的根源，而它直接指向了解法。如果 GPU 已经知道——并且这些信息直接编码在加速结构里——每个三角形的哪些子区域不透明、哪些透明，它就能在完全不运行着色器的情况下做出遍历决策，只有真正不确定的边缘区域除外。any-hit 着色器将从普遍存在变为偶尔出现。
