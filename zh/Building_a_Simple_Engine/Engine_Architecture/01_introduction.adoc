= 引擎架构：简介

== 简介

欢迎来到「构建简易游戏引擎」系列的「引擎架构」一章！本章中，我们将探讨构成现代 Vulkan 渲染引擎骨架的基础架构模式与设计原则。

虽然本系列主要聚焦于用 Vulkan 构建渲染引擎，但我们要讨论的架构概念既适用于渲染引擎，也适用于完整的游戏引擎。我们会说明哪些模式特别适合渲染导向的系统，哪些更适合更通用的游戏引擎开发。

我们先退一步，考察引擎的整体结构。一个设计良好的架构，对于构建灵活、可维护、可扩展的渲染系统至关重要。

=== 你将学到什么

本章将带你了解支撑有效引擎设计的基础概念。我们先探讨架构模式——游戏引擎和渲染引擎为管理复杂度、实现可扩展性所依赖的、经过验证的设计方法。理解这些模式，有助于你为不同的引擎子系统选择正确的结构方案。

接着，我们会深入组件系统，它提供了构建模块化、可复用代码的灵活性。你会看到基于组件的架构如何让引擎的不同部分协同工作，同时保持松散耦合，使代码库更易于维护和扩展。

资源管理是引擎架构的另一个关键支柱。我们会考察高效处理纹理、模型、着色器以及其他资产的策略，确保引擎能从简单场景扩展到资产繁重的复杂应用，而不出现性能瓶颈。

我们还会讲到渲染管线设计，向你展示如何创建一个能容纳各种渲染技术与效果的灵活系统。当你后续添加更高级的渲染特性时，这个基础会很有帮助。

最后，我们会实现事件系统，让引擎各组件之间能够清晰地通信。这种事件驱动的方式减少了紧耦合，使引擎在复杂度增长时仍然可维护。

=== 前置条件

本章直接建立在主 Vulkan 教程系列所打下的基础之上，因此完成那个系列是必要的。我们要讨论的架构概念，假定你已熟悉 Vulkan 的核心渲染概念，并且有动手实现的实践经验。

除了 Vulkan 知识之外，熟悉面向对象编程原则也会很有帮助，因为现代引擎架构大量依赖封装、继承与多态来管理复杂度。对 Observer、Factory、Singleton 等常见设计模式有经验，能帮助你认识到我们在引擎设计中何时、为何采用这些模式。

现代 {cpp} 特性在我们的实现方式中起着关键作用。智能指针帮助我们安全地管理资源生命周期，模板让组件灵活可复用，其他 {cpp}11/14/17 特性则让我们写出更具表现力、更易维护的代码。如果你对这些概念还不熟悉，建议先复习一下再继续。

=== 为什么架构很重要

一个仓促拼凑的渲染器与一个架构良好的引擎之间的差别，在你需要修改或添加特性时立刻就会显现。好的架构会打下支持你开发过程的基础，而不是处处与你作对。

可维护性源自清晰的关注点分离——当每个组件都有明确、聚焦的职责时，你就能单独更新或修复某一部分，而无需担心在整个系统中引发连锁影响。这在调试图形问题或实现新的渲染技术时尤为宝贵。

可扩展性自然地从模块化设计中产生。当你的架构提供了清晰的扩展点和接口时，添加新特性就变成了实现新组件的事情，而不是重写现有系统。这使引擎能随项目的需求一同演进。

可复用性会成倍放大你的开发投入。封装良好的组件可以在项目之间迁移，或在同一项目中承担不同用途。例如，一个精心设计的材质系统，可能同样适用于游戏对象和 UI 元素。

性能机会往往来自开发早期做出的架构决策。好的架构能支撑多线程（通过避免系统之间的紧耦合）、批处理（通过可预测的接口）和缓存（通过清晰的数据流模式）等优化。虽然过早优化是危险的，但过早的架构决策可能让后续优化变得不可能。
