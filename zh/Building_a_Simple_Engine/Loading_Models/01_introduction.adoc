= 加载模型：简介

== 简介

欢迎来到「构建简易引擎」系列的「加载模型」章节！在前面的章节中探索了引擎架构和相机系统之后，现在我们准备把重点转向在引擎框架中处理 3D 资产。

在本章中，我们会搭建一套健壮的模型加载系统，能够处理现代 3D 资产。在已建立的引擎架构和已实现的相机系统之上，我们现在要加入加载和渲染复杂 3D 模型的能力。在主教程的 xref:15_GLTF_KTX2_Migration.adoc[关于 glTF 与 KTX2 的一章]中，我们学习了从 OBJ 迁移到 glTF 格式，以及加载 glTF 模型的基础知识。现在，我们会把这些知识融入引擎结构，形成更完整的实现。

本章将把你对 3D 资产处理的理解，从简单的模型加载提升到精巧的引擎级系统。我们先构建场景图，它为复杂 3D 场景提供所需的层级组织。这一基础让你可以按逻辑给物体分组、在不同层级应用变换，并高效地管理场景复杂度。

动画支持是现代 3D 应用的关键部分。我们会实现一套能处理 glTF 骨骼动画的系统，通过平滑的角色运动、物体动画和复杂的多部件系统，让你的 3D 模型活起来。

我们将创建的 PBR 材质系统，弥合了前几章的光照概念与真实资产集成之间的差距。你会看到如何把 glTF 材质属性无缝映射到着色器，形成一套美术人员能够理解并有效使用的工作流。

渲染带有不同变换的多个物体会同时带来技术和组织上的挑战。我们会通过精心的引擎架构解决它们：既能高效地批处理相似物体，又能保留为每个物体处理独特材质和变换的灵活性。

在整个实现过程中，我们会用引擎级的思路而不是教程式的做法来组织代码。随着项目在复杂度和规模上增长，这种做法会让你受益，为创建带动画模型的复杂场景打下坚实基础。

== 前提条件

本章建立在主 Vulkan 教程打下的基础之上，尤其是第 16 章（渲染多个对象），因为我们会扩展那些概念来处理更复杂的场景组织和资产管理。渲染多个对象一章介绍了渲染不同几何体的基本概念，现在我们要把这些概念扩展到能处理带材质和动画的完整 3D 模型。

你需要扎实熟悉构成模型加载系统骨架的核心 Vulkan 概念。处理多个带不同材质的模型时，xref:03_Drawing_a_triangle/03_Drawing/01_Command_buffers.adoc[命令缓冲区]会变得更复杂，因为我们需要高效地管理描述符集和推送常量。理解 xref:03_Drawing_a_triangle/02_Graphics_pipeline_basics/00_Introduction.adoc[图形管线]至关重要，因为不同材质可能需要不同的管线配置。

对 xref:04_Vertex_buffers/00_Vertex_input_description.adoc[顶点缓冲区]和 xref:04_Vertex_buffers/03_Index_buffer.adoc[索引缓冲区]的经验可以直接迁移到模型加载：glTF 文件以特定格式包含顶点数据，我们需要解析并上传到 GPU 缓冲区。随着我们用 xref:05_Uniform_buffers/00_Descriptor_set_layout_and_buffer.adoc[统一缓冲区]存储变换矩阵、光照信息和材质属性，这方面的知识变得不可或缺。

xref:06_Texture_mapping/00_Images.adoc[纹理映射]技能尤其重要，因为 glTF 模型的每个材质通常包含多张纹理（漫反射、法线、金属度-粗糙度等），我们需要高效地加载和绑定这些纹理。

最后，基本的 3D 数学理解（矩阵、向量、四元数）对于处理模型变换、动画和场景层级至关重要。如果你需要复习，可以参阅 xref:Building_a_Simple_Engine/Camera_Transformations/02_math_foundations.adoc[相机与变换一章]，那里详细讲解了这些数学概念。
