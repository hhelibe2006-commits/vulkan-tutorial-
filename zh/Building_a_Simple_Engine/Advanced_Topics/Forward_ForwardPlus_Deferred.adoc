= 前向、Forward+ 与延迟——选择合适的路径

Vulkan 让你能构建许多种管线。实践中，大多数实时引擎会倾向于三种着色架构之一：前向（Forward）、Forward+ 或延迟（Deferred）。

本页解释它们各自是什么、本示例为什么选择 Forward+，以及相关部分在代码中的位置。

== 前向渲染

前向渲染在一次通道中绘制每个对象并计算其光照。它是最直接的模型：绑定材质，绑定光源（uniform 或纹理/SSBO），绘制。它易于理解，并且能与透明度和 MSAA 很好地集成。

优点：

* 简单且可预测。
* 适合透明对象和 MSAA。
* 非常适合光源数量少或使用烘焙光照的场景。

缺点：

* 随着光源数量增长，逐像素的光照循环会变得昂贵。
* 即使大多数光源不影响该像素，你也仍然要对它们求值。

== Forward+（我们用于动态光源的方案）

Forward+ 把屏幕划分为瓦片，并用一个计算通道把光源分配给这些瓦片。主通道随后只使用与该像素所在瓦片相关的光源进行着色。在本示例中，我们使用一个轻量的 Forward+，侧重自发光/简化光源，以保持代码易于理解。

优点：

* 可扩展到大量局部光源；你只对可能影响该像素的光源求值。
* 保留了前向渲染的优势（对透明度/MSAA 友好）。

缺点：

* 需要预通道或深度信息，以及一次计算派发来构建瓦片列表。
* 相比普通前向渲染有更多组成部分。

== 延迟着色（何时考虑它）

延迟着色在第一个通道中写入材质属性（G-Buffer），然后在第二个通道中对该缓冲区进行光照计算。这把光照开销变成「每个被光照像素的开销」，在光源很多时往往表现出色，但会让透明度和 MSAA 更棘手。

优点：

* 以高性能支持大量动态光源。
* 材质写入与光照求值清晰分离。

缺点：

* 透明对象必须单独处理（通常用一个前向通道）。
* MSAA 更复杂；显存带宽可能很高。

== 本示例使用什么（以及为什么）

我们对小型动态光源使用 Forward+，其余一切都使用前向材质路径。这让代码保持紧凑，同时仍允许你在场景中放置许多小光源。透明度（玻璃）在第二个前向通道中着色，以保证顺序和混合正确。

如果你的项目需要成百上千个带阴影的光源以及复杂的后光照处理，可以探索延迟路径或混合方案：不透明部分用延迟，透明部分用前向。

== 本代码库中的实现要点

* 一个小型计算通道构建逐瓦片光源列表。
* 逐帧 SSBO 保存瓦片头/光源索引；主 PBR 通道读取它们，只遍历相关的光源。
* 描述符更新发生在帧的安全点，因此我们不会触碰正在使用的描述符集。

== 为你的项目做选择

如果满足以下情况，使用前向渲染：

* 光源数量少，透明度和 MSAA 是优先事项，并且你想要最简单的管线。

如果满足以下情况，使用 Forward+：

* 你想要许多局部光源，同时仍想保留前向渲染的优势。

如果满足以下情况，使用延迟着色：

* 你需要扩展到大量动态光源并进行复杂光照，并且准备好单独解决透明度/MSAA 问题。

没有唯一的答案；挑选满足你需求的最简单方案。你随时可以在以后扩展管线。

== 后续工作想法

如果你想把光照系统扩展到超出「可读示例」的程度：

* 添加聚类 Forward+（使用深度切片的 3D 聚类）而不是 2D 瓦片。
* 添加阴影（从单个方向光阴影贴图开始，然后添加点光/聚光阴影）。
* 为仅不透明部分添加一个小型延迟路径（透明部分保持前向）。
* 为选择性效果（反射光线、阴影光线或 AO 探针）添加光线查询辅助函数，而无需构建完整的 RT 管线。
