= 我们引擎中的平面反射

你可能在真实场景里注意过闪亮的地板和窗户。在游戏中，我们常常把这种观感「做假」。在本引擎中，我们选择了一种实用且可靠的技术：平面反射。本页说明它是什么、我们为什么用它、它如何实现，以及什么时候你可能需要别的方案。

== 什么是平面反射？

平面反射会围绕单个平面（比如一块平坦的地板或一扇窗户）把场景渲染成镜像。可以把它想象成一台「镜像相机」，从反射面的另一侧看向场景。我们把这份镜像视图渲染进一张纹理，然后在绘制玻璃（或任何可反射的平面表面）时采样这张纹理。

平面反射非常适合：

* 平面镜、平静的水面、抛光地板、玻璃窗格。
* 需要稳定、高质量反射，且不能有严重噪点或时域不稳定的场景。

它们并不适合：

* 需要在各处呈现光泽、随视角变化的模糊的曲面／粗糙表面。
* 任意反射方向（例如具有复杂微观几何的金属）。

== 为什么示例选用平面反射

我们想要的反射方法应当：

* 易于理解（多一个通道、多一张纹理）。
* 确定且稳定（没有「闪烁」或时域累积带来的麻烦）。
* 在正向渲染器中对单个主要反射体（玻璃、地板）足够实用。

平面反射三者兼具。它还能在各类 GPU 上良好伸缩，且不要求光线追踪硬件。

== 本引擎中的实现方式

我们在主通道里增加一个小通道和一次小混合：

1. 镜像通道（离屏）
** 通过把相机沿某个平面做镜像，计算镜像视图矩阵（例如地平面取 Y=0）。
** 在禁用（或调整）面剔除的情况下，把不透明场景渲染到反射的颜色 + 深度目标中。
** 对反射图像做同步，供下一个通道采样。

2. 主通道（常规相机）
** 照常绘制不透明物体和透明物体。
** 绘制玻璃时，采样反射纹理，并用 Fresnel + 粗糙度 + 用户可控的「反射强度」将其与玻璃着色混合。

就这样。没有特别的渲染图魔法，没有光线查询，也没有时域累积。

== 镜像数学（简短版）

你在世界空间中定义一个平面：`ax + by + cz + d = 0`。

由该平面构造反射矩阵 `R`。把 `R` 作用到常规相机视图上，就得到镜像视图。实践中你还需要在镜像通道里翻转剔除方向，或把 `cullMode = none`，因为反射会改变绕序。

我们还会把平面传给着色器，用于可选的裁剪：

* 用它和世界位置做一个简单的点积，就能在镜像通道中丢弃位于平面「背后」的片元。

== 渲染步骤详解

镜像通道：

* 创建反射颜色图像（格式与主通道的需求匹配；我们选一种合成／玻璃通道能轻松采样的颜色格式）和一张反射深度图像。
* 渲染之前：用 Synchronization 2（`vkCmdPipelineBarrier2`）把反射颜色图像从 `SHADER_READ_ONLY_OPTIMAL` 转换到 `COLOR_ATTACHMENT_OPTIMAL`。深度图同理，转换到 `DEPTH_ATTACHMENT_OPTIMAL`。
* 开始动态渲染，为不透明物体绑定 PBR 管线，并禁用剔除（或翻转正面）。
* 渲染不透明网格。如有需要，可以针对该平面加上裁剪测试。
* 结束渲染。把反射颜色图像转换到 `SHADER_READ_ONLY_OPTIMAL`，供主通道采样。

主通道：

* 照常渲染不透明物体（我们使用离屏缓冲区，稍后再做色调映射合成）。
* 透明通道：绘制玻璃时，采样反射纹理并进行混合：
** 使用 Fresnel（掠射角更强），并随粗糙度衰减。
** 乘以一个你可以在 UI 中调整的小小「反射强度」。

== 同步与屏障（重点）

我们用 Vulkan Synchronization 2 保持简单：

* 不要在活跃的动态渲染通道内部改变图像布局。先结束它。
* 使用 `vkCmdPipelineBarrier2` 时注意：正确的源／目标阶段掩码、访问掩码，以及旧／新布局。
* 反射颜色：镜像通道之前 `SHADER_READ_ONLY_OPTIMAL → COLOR_ATTACHMENT_OPTIMAL`；之后转回 `SHADER_READ_ONLY_OPTIMAL`。
* 交换链图像：为合成／透明通道转换到 `COLOR_ATTACHMENT_OPTIMAL`；只有在结束最后一个渲染通道之后，才转换到 `PRESENT_SRC_KHR`。

== 描述符：反射绑定在哪里？

* 我们在 PBR 描述符集中把绑定 10 留给反射采样器。
* 在逐帧的「安全点」（上一帧的工作已完成时），我们为当前帧刷新绑定 10，使其指向上一帧的反射图像。
* 玻璃着色器会检查 UBO 标志（`reflectionEnabled`），只有在存在有效反射图像时才采样。

== 玻璃混合：一个易懂的模型

玻璃主要是透射，但我们想要鲜明而可信的反射。我们使用：

* Fresnel 项（Schlick）：掠射角处反射更强。
* 粗糙度因子：粗糙度越大 → 反射越弱、越模糊（这里保持简单，只压低强度）。
* 反射强度滑块：在 UI 中暴露，你可以几秒钟内调好可见度。

这并非完整的物理光谱模型，但没关系。它可读性好，效果也足够令人信服。

== 替代方案与选择时机

屏幕空间反射（SSR）::
* 不需要额外通道；使用当前帧已有的颜色／深度。
* 非常适合水洼和局部效果，但可能漏掉屏幕外物体，并且存在时域不稳定。
* 如果你想要到处都有快速反射，并能接受偶发瑕疵，就选 SSR。

环境贴图／立方体贴图／反射探针::
* 非常快；预先计算。
* 对近处物体不精确；最适合远处的光泽反射。
* 一般性环境反射，或者表面不是完美镜面时，选探针。

光线追踪（硬件）／混合方案::
* 非常精确；支持复杂反射。
* 需要硬件和高级降噪；代码与性能开销更大。
* 如果你的目标是高端 GPU，并且想要处处「看起来就是对的」反射，就选 RT。

平面反射（本示例）::
* 只多一个通道，确定且稳定。
* 非常适合一个或几个大型平面反射体（地板、窗户、平静的水面）。
* 当你希望为特定表面提供高质量镜面效果、又不想引入光线追踪时，选这个。

== 性能建议

* 以更低分辨率渲染镜像通道（我们提供了分辨率缩放滑块）。
* 积极剔除（我们的 CPU 视锥剔除对相机和镜像相机都有效）。
* 反射表面不可见时关闭镜像通道。
* 如果希望观感更柔和，可以考虑对粗糙表面的反射采样做模糊。

== 故障排查

「反射看起来太弱」::
* 调高反射强度滑块，和／或降低粗糙度。

== 后续工作想法

如果你想进一步推进平面反射：

* 为反射纹理增加考虑粗糙度的模糊（mip 链或可分离模糊）。
* 增加多个反射平面（对多层场景有用）。
* 增加屏幕空间回退（SSR），在有效处与平面反射混合。
* 为非平面表面增加选择性的光线查询反射（混合方案）。
