= 描述符索引与稳定的描述符更新

Vulkan 描述符很强大，但它也是最容易不小心违反「飞行帧」生命周期规则的地方之一。

在本引擎里我们用一条简单的规则：

*只在已知的安全点更新描述符。*

这条规则让流式加载保持稳定、让验证层保持安静，而且（最重要的是）让代码保持可读。

== 安全点

每个飞行帧都有一个栅栏。新帧开始时，我们等待该栅栏。一旦它给出信号，GPU 就已经完成了所有引用这一帧描述符集的工作。那就是更新本帧描述符集的安全时刻。

为什么重要：更新一个仍在使用的描述符集，会导致无效写入，或所谓的「绑定后更新」（update-after-bind）违规——除非你有意启用那些行为并围绕它们设计管线。安全点模式则保持可移植、清晰。

== 我们更新哪些内容

* 已完成流式加载的材质纹理。
* 用于平面反射的反射纹理绑定（binding 10）。
* Forward+ 的逐帧缓冲区（瓦片头部/索引、光源 SSBO），在尺寸变化时更新。

在光线查询模式下，我们还会刷新那张大纹理表（固定大小的采样器数组），好让新流式加载的纹理无需重建管线就能可见。

我们只在本帧的安全点刷新本帧的集合，其余帧留给它们各自的轮次。这样能避免跨帧的「翻来覆去」——纹理在相邻帧上看起来不一样。

== 描述符索引：何时使用

描述符索引开启了可变长数组和绑定后更新等特性。它很强大，但会把复杂度转移到同步与生命周期规则上。在本示例里我们强调清晰：

* 我们让描述符布局保持简单、稳定。
* 我们在安全点更新，而不是在命令缓冲区可能仍处于待处理状态时更新。

当我们确实使用描述符索引特性时，都是出于一个具体原因：大尺寸、非一致索引的描述符数组（例如光线查询的纹理表）。在这种情形下，正确性取决于：

* 启用 GPU 所需的描述符索引特性位
* 用正确的绑定标志标记绑定（在受支持时）
* 在异步流式加载过程中绝不缓存过期的 Vulkan 图像/采样器句柄

如果你的项目需要真正动态的描述符数组或频繁的帧中更新，描述符索引可以是合适的工具——只是要仔细记录新的不变量。

== 实用建议

* 集中管理描述符更新；不要把写入散落在帧的各处。
* 占位时使用默认纹理，然后一次替换——不要在真实纹理与默认纹理之间来回跳。
* 面向教学的示例优先使用组合图像采样器；只有在你需要那份灵活性时才拆分图像与采样器。

* 帧安全点 + 逐帧描述符刷新：
** `renderer_rendering.cpp`

** `renderer_pipelines.cpp`

** `renderer_ray_query.cpp`

== 后续工作的想法

如果你想探索更高级的描述符模式：

* 把纹理表改为可变描述符数量（当设备支持对你的目标而言足够好时）。
* 使用分离的图像/采样器描述符，在多个纹理之间共享采样器。
* 加一个「描述符压力测试」模式（仅开发期），快速流式加载纹理以验证生命周期规则。
