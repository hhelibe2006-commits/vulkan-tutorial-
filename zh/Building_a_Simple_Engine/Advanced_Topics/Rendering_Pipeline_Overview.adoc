= 渲染管线概览（本示例）

本引擎使用 Vulkan 动态渲染，通道序列不多且易读。这个顺序是刻意安排的：它让色调映射保持显式，让透明处理保持可控，也便于接入平面反射或 Ray Query 计算路径之类的可选特性。

== 通道顺序

1. 可选的反射通道（离屏）：
   * 把相机沿某个平面做镜像（例如地板或窗户）。
   * 把不透明几何渲染到反射渲染目标（颜色 + 深度）。
   * 把反射图像转换到 `SHADER_READ_ONLY_OPTIMAL`，供下一帧使用。

2. 不透明物体渲染到离屏颜色：
   * 把所有不透明物体渲染到离屏颜色图像（`opaqueSceneColor`）。
   * 深度照常读／写（如果你跑过深度预通道，则是只读）。

3. 合成到交换链：
   * 结束不透明渲染。
   * 把 `opaqueSceneColor` 转换到 `SHADER_READ_ONLY_OPTIMAL`。
   * 开始一个以交换链图像为目标的新的渲染实例，绘制一个全屏通道，采样离屏颜色（包含色调映射）。

4. 在其上叠加透明物体：
   * 继续以交换链图像作为颜色附件，并绑定场景深度。
   * 从后往前渲染透明物体（玻璃／液体）。
   * 启用时，玻璃采样上一帧的反射纹理。

5. UI：
   * 在最上层渲染 UI。
   * 结束渲染后把交换链图像转换到 `PRESENT_SRC_KHR`。

== 代码里该看哪里

* 主渲染循环与通道顺序：
** `renderer_rendering.cpp`
* 管线设置（动态渲染附件、布局、格式）：
** `renderer_pipelines.cpp`
* 合成通道着色器（色调映射 + 呈现）：
** `shaders/composite.slang`
* 多个管线共享的 PBR 着色工具：
** `shaders/pbr.slang`
** `shaders/pbr_utils.slang`
** `shaders/lighting_utils.slang`

== 为什么是这个结构

* 单个离屏缓冲区让色调映射显式化，并避免 gamma 不正确的拷贝路径。
* 透明排序保持简单，因为在该通道中交换链就是当前颜色附件。
* 反射通道是可选的，且自成一体。

== 后续工作想法

如果你想进一步推进这条管线：

* 为复杂场景增加深度预通道（有助于 early-z，并让 Forward+ 分簇更准确）。
* 在不透明离屏通道与合成之间加入一条轻量泛光链。
* 如果需要大量重叠玻璃，增加专用的透明解析路径（加权混合 OIT）。
* 通过从光栅着色器调用光线查询来演示混合渲染（反射探针、阴影测试，或只针对玻璃的反射）。
