= 高级 glTF：高性能角色管线

== 超越静态模型

「构建一个简单引擎」系列为 Vulkan 渲染打下了扎实的基础。它介绍了通过 `tinygltf` 加载 glTF 的核心机制、PBR 材质着色器，以及每个 `Model` 内部的简单层级场景图。然而，当引擎从渲染静态微缩场景演进到复杂、可交互的世界时，我们就会撞上那套初始架构的局限。

在生产级引擎里，角色不只是一个网格，而是多个高性能系统的交汇点。当角色的脚踏上不平的地形时，逆向运动学（IK）系统必须调整腿部的关节旋转。当同一个角色被抛射物击中时，动画系统必须无缝地把控制权交给物理引擎，进行布娃娃模拟。这种相互作用要求的架构，远比一个基础递归遍历更健壮、更优化。

在本教程系列中，我们将让引擎演进，以处理这些高级角色管线。我们不是简单增加动画或物理之类的「功能」，而是在重新设计核心系统，以应对现代 3D 资产的规模、性能和复杂度。

== 技术路线图

=== 1. 简介
本系列围绕一个现代角色的生命周期组织，从解析 glTF 文件一直到模拟它与世界的物理交互。我们从这篇简介开始，确立前置条件并搭好开发环境。

=== 2. 场景图与变换层级
我们先统一场景表示。之前的引擎采用混合做法——一个扁平实体列表，每个实体包含层级化的模型——而我们将转向**统一的全局场景图**。我们还会用**脏标记**系统与更面向数据的布局（DOD）取代冗余的逐帧矩阵乘法。这样能确保只在绝对必要时才更新世界空间变换，这在场景复杂度增长时是关键的优化。我们还会探索通过解析 glTF 文件中的 **"extras" 元数据**来自动设置碰撞体，让物理代理与视觉网格完美对齐。

=== 3. 高级骨骼与计算蒙皮
骨骼动画是角色运动的心跳。我们将实现高性能的**计算蒙皮**，把顶点形变的重活从顶点着色器搬到专门的计算内核。这种做法让我们「蒙皮一次，处处使用」——把结果存进共享缓冲区，光栅化器、光线追踪加速结构乃至物理查询都能访问。

=== 4. 物理集成：碰撞体与布娃娃
物理与动画常被当作两个独立实体，但在高级管线里它们深度交织。我们将探索**双向同步**：动画可以驱动物理（运动学），物理也可以接管并驱动骨架（布娃娃）。

=== 5. 程序化动画与 IK
角色对环境作出反应时才显得活着。我们将实现**逆向运动学（IK）**，使用 CCD（循环坐标下降）或 FABRIK 之类的算法，确保脚贴合地形、头部追踪兴趣点。这一「程序化层」叠加在传统动画剪辑之上，提供让角色显得踏实的最后打磨。

=== 6. 形变目标与面部动画
要有表现力丰富的角色，光有骨骼还不够。我们将实现对**形变目标**（形态键）的支持，以表达复杂的面部表情和局部的网格形变。我们会利用**描述符索引**等现代 Vulkan 特性来处理这些位移缓冲区，避免每次绘制都切换描述符的开销。

=== 7. 工具链与生产管线
代码只是战斗的一半。我们会讨论「从 Blender 到 Vulkan」的工作流，确立命名约定与导出设置，让资产进入引擎后「直接就能用」。我们还会把 **Khronos glTF-Validator** 集成进管线，在资产损坏引发神秘的引擎 bug 之前抓住它。

=== 8. 调试与视觉审计
即便管线完美，问题也会出现。我们将构建专门的调试工具，把角色系统隐藏的状态可视化。包括用于骨架和碰撞形状的延迟线条绘制器、用于识别「夹紧」几何体的蒙皮权重热力图，以及用 RenderDoc 审计计算蒙皮输出的技巧。

== 高级工具箱

贯穿本系列，我们会升级开发工具箱，以反映现代标准：

*   **Slang 着色器**：我们所有新的着色器工作——从计算蒙皮到 PBR 增强——都将用 **Slang** 编写。Slang 的模块化与自然对齐特性，使其在复杂渲染管线上比原生 GLSL 高效得多。
*   **Vulkan 1.3**：我们将利用**动态渲染**与**描述符索引**等特性，简化管线管理并提升性能。
*   **Jolt Physics**：我们选择 link:https://jrouwe.github.io/JoltPhysics/[Jolt Physics]（link:https://github.com/jrouwe/JoltPhysics[GitHub 上的源码]）作为模拟引擎。它性能优先的设计与简洁的 C++ API，使其成为实时角色动力学与布娃娃的理想选择。

== 搭建开发环境

在深入代码之前，你需要准备开发环境，装上几个新工具和库。

=== 1. Slang 着色器编译器
本系列中所有计算与图形着色器都将使用 **Slang**。

* **下载**：从 link:https://github.com/shader-slang/slang/releases[Slang GitHub Releases] 获取最新的二进制发行版。
* **配置**：确保 `slangc` 可执行文件在系统 PATH 中。
* **Vulkan 集成**：Slang 会把 `.slang` 文件直接编译为 SPIR-V（`.spv`），随后用你现有的 Vulkan 着色器加载代码载入即可。

=== 2. Jolt Physics
Jolt 是本系列推荐使用的物理引擎。
* **集成**：建议用 CMake 的 `FetchContent` 把 Jolt 直接集成进项目：
[source,cmake]
----
include::FetchContent.cmake
FetchContent_Declare(
    Jolt
    GIT_REPOSITORY https://github.com/jrouwe/JoltPhysics.git
    GIT_TAG master
)
FetchContent_MakeAvailable(Jolt)
----
* **初始化**：Jolt 需要少量样板代码（内存管理、作业系统和层接口），我们会在物理集成一章中讲解。

=== 3. Khronos glTF-Validator
为确保我们自定义的 glTF 资产有效，我们将使用官方验证器。

* **安装**：按 link:https://github.com/KhronosGroup/glTF-Validator[glTF-Validator 仓库]中的说明操作。它既可以作为独立的 CLI 工具使用，也可以通过 NPM 获取。

== 准备起始项目

本系列假定你已经有一个来自「构建一个简单引擎」系列的可用引擎。要迁移到高级 glTF 架构，你应当准备一个「起始项目」，它需要：

1.  **支持 Vulkan 1.3**：确保创建实例和逻辑设备时请求 1.3 版 API。
2.  **启用动态渲染**：确保启用了 `VK_KHR_dynamic_rendering`；如果你完成过简易引擎系列，这应该已经处于启用状态——该系列在其高级主题一章中引入了动态渲染。
3.  **集成 GLM**：我们将大量使用 GLM 进行数学运算，特别是骨骼动画所需的四元数支持。

如果你是从零开始，建议先把简易引擎的核心重构为支持全局场景图，再进入下一章。
