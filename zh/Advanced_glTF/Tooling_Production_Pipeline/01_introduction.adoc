= 工具链与生产管线

== 引擎缺陷的隐藏源头

有一类问题，每个图形程序员最终都会遇到，而且它让人格外沮丧，因为调试工具会把你引向错误的方向：一个看起来像代码缺陷的资产缺陷。角色的肢体朝后指。法线贴图完全不对。动画本该驱动上臂，却驱动了前臂。布娃娃一激活就立刻瘫倒。在花了好几个小时单步调试蒙皮着色器、检查四元数约定、核对矩阵乘法顺序之后，你发现原来是 Blender 的导出设置从一开始就是错的——导出时法线被翻转了，或者关节命名约定与加载器的预期不匹配。

本章要系统地防止这一类问题。我们将建立一条清晰的生产管线：一串把 Blender 场景从美术师的工作站变成经过验证、可直接供引擎使用的 glTF 资产的步骤，并在每个阶段设置检查点，让错误尽早被发现，而且是在便于诊断的上下文中被发现。

这条管线分为三个阶段。第一个是**创作**：Blender 一侧那些决定资产如何导出的选择。骨骼命名约定、顶点组分配、为物理扩展数据定义自定义属性，以及导出设置，都属于这一阶段。把它们做对，意味着生成的 glTF 文件在构造上就是正确的，引擎加载器不需要任何特殊处理。第二个阶段是**验证**：把导出的文件交给 Khronos glTF-Validator 跑一遍，在文件到达你的加载器之前就检查格式违规、缺失数据和规范不符。第三个阶段是**建立基准真相**：用专业级的 glTF 查看器确认资产的外观与行为都正确，然后才能断定剩下的问题出在引擎代码里。

这不是什么光鲜的工作。但正是这类工作，把专业的生产管线与无休止的调试循环区分开来。
