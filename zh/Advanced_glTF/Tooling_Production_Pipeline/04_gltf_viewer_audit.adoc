= glTF 查看器审计：确立基准

== 基准的意义

资产通过验证后，你知道它符合规范，但还不知道它看起来是否正确。glTF-Validator 只告诉你文件结构良好；它不会告诉你法线朝向对不对、骨架是否正确驱动网格、动画剪辑是否按动画师的本意播放。这正是参考查看器的用武之地。

**基准**（ground truth）是一份已知正确的资产渲染结果——由某个成熟、经过充分测试的 glTF 规范实现生成——你可以拿它来对比自己引擎的输出。两者一致时，之后出现的任何差异几乎肯定出在引擎代码里。两者不一致时，你就有了证据：差异源自资产本身，或源自引擎对规范的理解，而不是某种神秘的图形 API 行为。

在调试引擎代码之前先确立基准，这一习惯投入产出比极高。没有基准，每个视觉瑕疵都含义不明：它可能是着色器 bug，可能是 Vulkan API 误用，可能是矩阵算错，也可能是资产问题。有了基准参考，你就能立刻给瑕疵分类。若参考查看器里也出现同样的问题，那就是资产问题——回去修 blend 文件。若参考查看器显示正常而引擎不正常，那就是引擎问题——去调试代码。光是这一步分类，就能省下几个小时。

== 推荐的查看器

市面上有几款成熟、高质量的 glTF 查看器可以免费使用。就我们的目的而言，推荐两个：

**Khronos glTF Sample Viewer**（https://github.khronos.org/glTF-Sample-Viewer-Release）。这是 Khronos Group 自己的参考实现——正是维护 glTF 规范的那个组织。它基于 WebGL 构建，在任何现代浏览器里都能运行，因此无需安装即可使用。它实现了完整的 glTF PBR 材质模型、全部动画插值模式（线性、阶跃、三次样条）、蒙皮以及形变目标。由于它是参考实现，在涉及规范符合性的问题上，它是权威性最高的查看器。如果你的资产在这里显示不对，问题必定在资产本身。

**Babylon.js Sandbox**（https://sandbox.babylonjs.com）。这是一个成熟的商业级实现，对所有 glTF 特性都有良好支持，其 UI 维护得也不错，可以方便地隔离并检查单个动画、骨骼和形变目标。它的节点检查器让你查看场景图层级、检查每帧动画中的骨骼变换，并验证形变目标权重是否被正确驱动。专门调试骨骼动画问题时，它往往比 Khronos 查看器更好用。

两个查看器都支持拖放 `.glb` 文件，这让审计流程很快：从 Blender 导出，拖到查看器里，几秒钟内你就有了参考渲染。

== 在查看器里看什么

系统的审计应当按以下顺序检查：

**休息姿势。** 打开文件，立刻暂停所有动画。角色应当处于在 Blender 中作为绑定姿势确立的 T 姿势或 A 姿势。如果角色在休息姿势下就已形变——肢体弯曲、网格被拉向错误的骨骼——那么源头上的蒙皮权重或逆绑定矩阵就是错的。

**材质。** 确认所有材质渲染出的颜色、粗糙度、金属度和法线贴图都正确。特别留意法线贴图是否在正确的位置产生凸起或凹陷效果——法线贴图的绿色通道被翻转是常见的导出错误，表现为细微表面细节上的明暗反转。

**动画播放。** 在查看器中逐个播放动画剪辑，确认符合美术的意图。留意驱动了错误网格区域的骨骼、播放速度不对的动画（时间戳缩放问题），以及不是平滑插值而是突跳或跳变的剪辑。如果某个剪辑使用三次样条插值，确认切线产生的曲线平滑——常见错误是导出的切线缩放出错，导致剪辑中段出现振荡瑕疵。

**形变目标。** 在查看器的材质或动画检查器里，手动把每个形变目标的权重从 0 拉到 1，确认面部按预期形变。如果某个形变目标看起来毫无效果，可能是位移访问器被导出成全零，或者该目标被指派到了错误的网格图元。如果某个形变目标产生极端形变，可能是位移向量处在错误的坐标空间（缩放或轴向约定问题）。

**骨架层级。** 在支持骨骼检查的查看器里（例如 Babylon.js Sandbox），展开场景图，确认父子关系与 Blender 中的绑定层级一致。确认叶子骨骼（如果误导出了一些）没有被当作有意义的关节对待。

== 从查看器到引擎：不一致时怎么办

当引擎渲染与查看器参考不一致时，调试过程就变得有条理了：

如果**材质**不一致：拿你的 PBR 着色器对照 glTF 规范的 BRDF 公式。最常见的差异是粗糙度到感知粗糙度的转换（glTF 使用感知粗糙度，某些 PBR 实现使用线性粗糙度）以及金属度工作流（glTF 始终使用金属度/粗糙度，从不用高光/光泽度）。

如果**骨架**不对：把引擎在休息姿势下算出的关节世界矩阵与查看器显示的做对比。把引擎算出的矩阵导出为调试叠加层，逐个关节比对。最常见的原因是矩阵乘法顺序写错（`parent * local` 与 `local * parent`）以及逆绑定矩阵的应用方式错误（`joint_matrix = global_joint_transform * inverse_bind_matrix`，其中 global_joint_transform 由从根到关节遍历场景图算出）。

如果**形变目标**不对：拿展开后的数据与原始 glTF JSON 值做对比，以此验证 expand_sparse_accessor 的实现。稀疏索引散布步骤里只要有一个 off-by-one 错误，就会让每个位移整体偏移一个顶点，产生特征性的「游移」瑕疵，面部在错误的区域形变。

如果**动画**不对：把 glTF 文件中采样器输入的时间戳与引擎用于插值的时间戳做对比。如果文件里存的是秒而引擎当作毫秒解释（或相反），每个动画都会以 1/1000 速度或 1000 倍速度播放。还要确认你的三次样条插值公式与 glTF 规范完全一致——规范使用 Hermite 基，且切线向量预先按时间间隔缩放，这与某些教科书上的写法不同。
