= 场景图与变换层级

== 统一世界

在「构建一个简单引擎」系列中，我们实现了一种混合式场景架构。我们在世界中维护一个扁平的 `ObjectInstance` 实体集合，每个实体包含一个 `Model`，而 `Model` 拥有自己的内部 glTF 节点层级。对于学习而言这是一个完美的折中：它让我们能够加载复杂的 glTF 资产，同时让顶层引擎逻辑保持简单。

然而，当我们进入高级角色动画与物理时，这种分离就成了一种障碍。角色并不只是一个自包含的模型；它是多个相互作用系统的集合。角色的手可能是一个需要抓握另一把剑实体的节点。角色的脚可能是必须与地形物理碰撞体交互的节点。为了无缝支持这些跨实体交互，我们需要转向**统一场景图**。

在本章中，我们将消解「世界」与「模型」之间的边界。我们会把引擎迁移到单一、全局的递归节点系统上，其中每个对象——无论它是一个 200 根骨骼的角色、一栋静态建筑，还是一个光源——都只是通用层级中的一个 `Node`。

== 性能障碍：冗余计算

「简单引擎」使用直截了当的递归遍历来计算世界空间变换矩阵：

[source,cpp]
----
void renderNode(const std::vector<Node*>& nodes, const glm::mat4& parentMatrix) {
    for (const auto node : nodes) {
        glm::mat4 nodeMatrix = parentMatrix * node->getLocalMatrix();
        // ... render and recurse ...
    }
}
----

这种写法虽然优雅，却有一个重大的性能缺陷：它每帧都为每个节点重新计算世界矩阵，无论该节点实际上是否移动过。在拥有数千个节点的场景中——这在现代角色密集的环境里很常见——这会造成 CPU 周期与内存带宽的巨大浪费。

为解决这个问题，我们将实现**脏标记模式**（Dirty Flag Pattern）。每个节点都会跟踪自己的局部变换或父节点的世界变换是否发生过变化。我们只在节点「脏」的时候才执行代价高昂的矩阵乘法。这一优化决定了一个引擎是在几个角色面前就卡顿，还是能应付一整群人。

== 连接动画与物理

场景图是角色管线在架构上的「神经系统」。正是在这里，骨骼动画的数学理论与引擎世界的物理现实相遇。

角色的骨架，本质上就是一个专用的场景图。先构建一个健壮、经过优化的层级，我们就能得到一个既能处理简单父子挂接、又能以同一套底层逻辑处理复杂骨骼结构的系统。此外，这个层级还为我们的物理引擎提供了挂接点。我们会把碰撞代理（胶囊体、盒体）直接挂到层级中的节点上。当动画系统移动某个骨骼节点时，物理引擎的碰撞体会自动跟随。这种双向同步正是让角色的手臂在挥动过程中能够对碰撞做出反应的关键。

== 我们将构建什么

在本章中，我们将围绕四个关键领域，为高级角色管线铺设基础性的「管道」：

*   **引擎扩展**：我们会把实体管理重构为全局递归的 `Node` 系统。我们将实现脏标记优化，并探索一种更面向数据的布局以改善缓存局部性。
*   **元数据与物理扩展**：我们会探索如何利用 glTF 的「extras」来自动化物理设置。我们将利用在 3D 工具中定义的自定义属性，在引擎中自动生成碰撞体与物理属性。
*   **物理同步理论**：我们会建立视觉节点与物理刚体之间的数学联系，为系列后续的运动学到动力学的交接（布娃娃）做好准备。
*   **变换管线**：我们会完善数学部分，以处理逆变换与全局到局部的转换，这些是逆向运动学（IK）的前提条件。

让我们先扩展引擎核心，构建一个足以应对现代角色动画严苛要求的场景图。
