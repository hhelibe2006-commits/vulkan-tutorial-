= 蒙皮的数学

== 为什么数学很重要

很容易把蒙皮当成一个黑箱：你给 GPU 一些骨骼和一个网格，它就自己算出顶点该去哪里。很多开发者这样用了好几年。但一旦出问题——而在骨骼动画里，问题迟早总会出——懂底层数学的人几分钟就能定位，不懂的人则只能盯着一个扭曲变形的网格发呆，搞不明白自己的角色为什么看起来像被扔进了搅拌机。

本节不是走马观花式的概述。我们要从第一性原理出发把蒙皮方程一步步搭出来，读完你应该能看懂下一节的计算着色器代码，并清楚每一次矩阵乘法为什么在那里。

== 绑定姿势及其存在的原因

每个蒙皮角色的生命都始于所谓的**绑定姿势**（**Bind Pose**，有时也叫 **T-Pose** 或**静止姿势**）。这是美术把网格绑到骨骼系统上时使用的那个特定骨架配置，也是绘制蒙皮权重时骨骼与网格完美对齐的「中性」状态。

绑定姿势之所以至关重要，是因为 glTF 文件里的所有动画数据都是*相对于绑定姿势的增量*。当一个关节的动画通道说「绕 Z 轴旋转 30 度」时，它的意思是「比绑定姿势的旋转多 30 度」。这意味着绑定姿势是把动画数据与网格几何联系起来的共同参考系。

在 glTF 中，绑定姿势信息以每个关节的**逆绑定矩阵**（Inverse Bind Matrix）形式存储。这个矩阵正如其名：它是网格绑定到骨架那一刻该关节变换矩阵的数学逆矩阵。如果关节在绑定姿势下的世界矩阵是 `B`，那么文件里保存的逆绑定矩阵就是 `B⁻¹`。

我们马上就会看到为什么需要这个逆矩阵。

== 三步蒙皮方程

计算一个动画顶点应该出现在哪里分三步。把每一步单独弄明白，组合起来的方程就会显得理所当然，而不是神秘莫测。

=== 第 1 步：把顶点变换到骨骼局部空间

网格中的每个顶点都存储在**模型空间**中——它的位置相对于模型原点。但要应用关节的旋转，我们需要顶点处在**骨骼局部空间**中，也就是以关节自身为原点的空间。

这正是逆绑定矩阵的用途。当我们用某个关节的逆绑定矩阵去乘一个顶点位置时，我们是在表达该顶点*相对于该关节在绑定姿势下的位置*。本质上我们是在问：「如果把绑定姿势下的关节放到它自己坐标系的原点，这个顶点会在哪里？」

举例来说，如果某个角色的手腕关节在绑定姿势下位于 `(0.5, 1.2, 0.0)`，那么手腕的逆绑定矩阵就编码了这个偏移。当我们用这个矩阵去乘手部附近的一个顶点时，结果是一个靠近原点的位置——靠近手腕——而不是世界空间里的某处。

=== 第 2 步：应用当前的关节变换

现在顶点已经相对于绑定姿势下的关节表达出来了，我们可以应用关节的*当前*变换。这就是该关节的动画世界矩阵，也就是我们在上一章用脏标记系统算出来的那个。

当我们用当前关节世界矩阵去乘骨骼局部空间中的顶点位置时，我们是在说：「把这个原本相对于绑定姿势关节摆放的顶点，移动到动画关节现在所在的位置。」如果手腕当前相对其绑定姿势旋转了 45 度，顶点会正确地跟随这个旋转，因为我们事先把它表达成了相对手腕原点的位置。

单个关节的组合运算就是：

`Animated Position = Joint World Matrix * Inverse Bind Matrix * Rest Position`

从右往左读（矩阵乘法就是这么工作的）：我们取静止位置，把它变换到关节的局部空间，再从关节的局部空间变换到最终的动画世界空间。

=== 第 3 步：混合多个关节的影响

真实的角色网格并不是由单根骨骼驱动的。每个顶点同时受多个关节影响，这叫作**线性混合蒙皮**（Linear Blend Skinning，LBS），有时也叫**平滑蒙皮**。没有它，角色网格在关节处就会像纸板一样折叠、起皱，而不是像真实骨架上的皮肤那样平滑拉伸。

在 glTF 中，每个顶点最多存储四个**关节索引**和对应的四个**权重**。关节索引指明哪些骨骼影响这个顶点，权重则规定每根骨骼贡献多少。权重之和必须为 1.0，以确保顶点不会被意外缩放或平移。

单个顶点的完整蒙皮方程，是各关节变换的加权和：

----
Skinned_Position = (w0 * J0 * IB0 + w1 * J1 * IB1 + w2 * J2 * IB2 + w3 * J3 * IB3) * Rest_Position
----

其中 `Jn` 是关节 `n` 的当前世界矩阵，`IBn` 是它的逆绑定矩阵，`wn` 是该顶点对应于这个关节的权重。

这个加权和有时被称为顶点的**蒙皮矩阵**（Skin Matrix）。关节附近的不同顶点会有不同的权重分布——正好落在肘部的顶点可能 50% 属于上臂、50% 属于前臂，而在上臂中段的顶点可能 90% 属于上臂、10% 属于前臂。美术在建模软件里用权重绘制工具来控制这些权重。

== 关节矩阵：预先计算关键运算

在上面的方程里，我们要为每个顶点做一次 `Jn * IBn` 乘法。但请注意，对受同一关节影响的顶点来说，这个乘积完全相同。无论算的是第 100 个还是第 100000 个顶点，只要它们都受关节 `5` 影响，就都用同一个 `J5 * IB5` 矩阵。

这意味着我们可以在上传到 GPU 之前，先在 CPU 上预计算这些乘积，而且也应该这么做。与其让每个着色器调用去取两个矩阵再相乘，我们创建一个预乘好的**关节矩阵**数组——每个关节一个——只把它上传到 GPU。

[source,cpp]
----
// Called once per frame, after the animation update and scene graph update
void compute_joint_matrices(
    const Skin& skin,
    const std::vector<Node>& nodes,
    std::vector<glm::mat4>& joint_matrices_out)
{
    joint_matrices_out.resize(skin.joints.size());

    for (size_t i = 0; i < skin.joints.size(); ++i) {
        // Get the current world matrix of this joint's node
        // (already computed by the scene graph's dirty flag system)
        const Node& joint_node = nodes[skin.joints[i]];
        const glm::mat4& current_world = joint_node.world_matrix;

        // Multiply: Current Joint Transform * Inverse Bind Matrix
        // This pre-computes the per-joint portion of the skinning equation.
        // The shader only needs to multiply this by the vertex's rest position.
        joint_matrices_out[i] = current_world * skin.inverse_bind_matrices[i];
    }
}
----

这里的 `Skin` 结构与我们解析 glTF 文件得到的结构一致：一组关节节点索引，以及它们对应的逆绑定矩阵。输出的 `joint_matrices_out` 将作为**着色器存储缓冲区对象**（Shader Storage Buffer Object，SSBO）上传到 GPU——这是一块 GPU 可访问的大缓冲区，计算着色器可以自由索引。

== 处理法线

上面的蒙皮方程能正确变换顶点位置，但一个完整的蒙皮实现还必须变换**顶点法线**。法线是垂直于网格表面的向量，驱动着所有光照计算。如果你让网格变形却不相应地变形法线，你的角色看起来就会像仍处在 T-pose 下被照亮——这是个非常刺眼的视觉瑕疵。

法线不能用完整的关节矩阵变换（它包含平移）。法线必须用**法线矩阵**变换，也就是关节矩阵中 3x3 旋转与缩放部分的逆矩阵的转置。多数情况下——这也是角色动画的标准做法——我们可以假定关节矩阵不含非等比缩放。在这种情形下，法线矩阵直接简化为关节矩阵的 3x3 部分。

[source,cpp]
----
// For joint matrices without non-uniform scale, the normal transform is simpler:
glm::mat3 normal_matrix = glm::mat3(joint_matrix);

// If non-uniform scale is present (e.g., squash-and-stretch animation):
// glm::mat3 normal_matrix = glm::transpose(glm::inverse(glm::mat3(joint_matrix)));
----

这个取舍值得说清楚：跳过完整的法线矩阵计算是一种性能优化，实践中几乎总是看不出来，因为角色的骨骼关节很少使用非等比缩放。如果你的引擎将来需要支持挤压拉伸骨骼动画，你就得回头重新审视这个假设。

== 切线与副切线

对于使用法线贴图的角色——这在 AAA 制作中几乎普遍存在——我们还需要对**切线向量**做蒙皮。切线与副切线定义了每个顶点的坐标系，它把法线贴图的纹理空间映射到变形后网格的世界空间。如果网格变形了而切线坐标系没跟上，法线贴图光照就会出错。

切线使用与法线相同的方式变换——取关节矩阵的 3x3 旋转部分，不含平移。副切线通常不直接存储，而是在片元着色器里用法线与切线的叉积重建，手性符号则存在切线的 W 分量里。

有了这套数学基础，编写计算着色器所需的一切就齐备了。我们知道需要哪些输入（静止位置、法线、切线、关节索引、权重，以及预计算好的关节矩阵），知道要做什么计算，也知道该产生什么输出（写进一个新缓冲区的动画位置、法线与切线，其他人人都能从中读取）。
