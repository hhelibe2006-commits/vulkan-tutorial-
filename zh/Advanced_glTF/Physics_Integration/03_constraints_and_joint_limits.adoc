= 约束与关节限制

== 为什么没有约束的布娃娃不堪入目

如果你把上一节创建的物理刚体全部立刻切到动态模式，然后让物理求解器跑起来，你会得到一个布娃娃——但是个很糟的布娃娃。每个身体部位都会各自乱甩。手臂不会连着肩膀。膝盖会向侧面、向后、向前弯，甚至能转一整圈。脊柱会垮成一堆互不相连的身体部件。这个角色看起来不像一个倒下的人，倒像一袋碰巧刚才还占着同一空间的松散物件。

问题在于物理刚体默认对彼此一无所知。它们是一个个独立的被模拟对象。把它们连接起来的东西——让膝盖*成为膝盖*、让肩膀*成为肩膀*的东西——是**约束**。物理约束是求解器必须遵守的规则：它可以说「这两个刚体必须保持固定距离」，或者「这个刚体可以相对那个刚体旋转，但只能在这个角度范围内」，或者「这个刚体连着那个刚体，可以朝任意方向自由转动」。

没有约束，你只有一堆彼此分离的砖块。有了约束，你才有了一副骨架。

== 人形角色所需的两种约束

对人形布娃娃来说，两种约束类型就能覆盖整个身体：**球窝（Ball-and-Socket）**约束和**铰链（Hinge）**约束。

球窝约束（有时也叫球形约束）允许朝任意方向旋转，但阻止两个刚体分离。想一想人的肩膀或髋关节是怎么工作的：你可以把手臂或腿在一个很宽的锥形范围内转动，但关节本身不发生平移——球始终待在窝里。这是肩、髋、颈和踝的正确约束。用物理引擎的术语说，它去掉了全部三个平移自由度，但保留三个旋转自由度，并受角度限制约束。

铰链约束只允许绕单一轴旋转。想一想膝盖：它在一个平面内弯曲，不会侧向旋转，也不会轴向旋转（至少不明显）。铰链约束强制这种单轴旋转，是膝、肘的正确选择，有时也用于手腕，取决于你的布娃娃需要多细。它去掉了全部三个平移自由度和三个旋转自由度中的两个，只留下一个。

这一区别之所以重要，是因为它直接决定布娃娃在视觉上怎么读。膝盖向侧面弯，会立刻让人觉得别扭。肩膀在一个锥形范围内转动，即便锥角的具体数值不符合生理精度，看起来也是对的。把约束类型与解剖功能匹配起来，是让布娃娃看起来可信的最重要的一件事。

== 角度限制：人类的运动范围

只选对约束类型还不够。没有角度限制的球窝关节允许手臂转 360 度——这意味着角色的手臂可以笔直地指向肩膀后方，或者像直升机旋翼一样旋转。真实的肩膀虽然是球窝关节，但受软组织限制，运动范围是有限的；超出这个范围就会出现「手臂不可能地旋转」的样子，让布娃娃滑稽可笑。

角度限制告诉物理求解器每个轴上的有效旋转范围。对铰链约束来说很直接：绕单根铰链轴的最小角和最大角。对球窝约束来说就复杂一些——我们通常要指定一个**摆动限制**（描述骨骼能偏离其中立轴多远的锥形半角）和一个**扭转限制**（骨骼能绕自身主轴旋转多远）。

把这些限制存进 glTF extras 的方式与碰撞体定义相同。肩部骨骼的 extras 可能长这样：

[source,json]
----
{
  "physics": {
    "collider": "capsule",
    "radius": 0.06,
    "half_height": 0.14,
    "mass": 2.5,
    "constraint": {
      "type": "ball_socket",
      "swing_limit_deg": 80,
      "twist_limit_deg": 45,
      "parent_bone": "spine_upper"
    },
    "collision_group": "arm",
    "collision_mask": "world,props"
  }
}
----

膝关节骨骼的 extras 则是：

[source,json]
----
{
  "physics": {
    "collider": "capsule",
    "radius": 0.055,
    "half_height": 0.20,
    "mass": 3.0,
    "constraint": {
      "type": "hinge",
      "hinge_axis": [0, 0, 1],
      "limit_min_deg": -140,
      "limit_max_deg": 0,
      "parent_bone": "thigh"
    },
    "collision_group": "leg",
    "collision_mask": "world,props"
  }
}
----

`parent_bone` 字段告诉我们这条约束连接到哪个刚体。约束将建立在父骨骼的物理刚体与本骨骼的物理刚体之间。`hinge_axis` 指定骨骼局部空间中的旋转轴。

== 解析约束定义

我们扩展 extras 解析代码，把约束定义也捕获下来：

[source,cpp]
----
struct ConstraintDef {
    enum class Type { NONE, BALL_SOCKET, HINGE };

    Type        type              = Type::NONE;
    float       swing_limit_deg   = 180.0f;   // Ball-socket: cone half-angle
    float       twist_limit_deg   = 180.0f;   // Ball-socket: twist range
    float       hinge_min_deg     = -180.0f;  // Hinge: minimum angle
    float       hinge_max_deg     =  180.0f;  // Hinge: maximum angle
    glm::vec3   hinge_axis        = {0,0,1};  // Hinge: rotation axis in local space
    std::string parent_bone;                  // Name of the parent node
};

ConstraintDef parse_constraint_def(const tinygltf::Value& phys_extras)
{
    ConstraintDef def;
    if (!phys_extras.Has("constraint")) return def;

    const auto& con = phys_extras.Get("constraint");

    const std::string type_str = con.Get("type").Get<std::string>();
    if      (type_str == "ball_socket") def.type = ConstraintDef::Type::BALL_SOCKET;
    else if (type_str == "hinge")       def.type = ConstraintDef::Type::HINGE;
    else                                return def;

    if (con.Has("swing_limit_deg")) def.swing_limit_deg = static_cast<float>(con.Get("swing_limit_deg").GetNumberAsDouble());
    if (con.Has("twist_limit_deg")) def.twist_limit_deg = static_cast<float>(con.Get("twist_limit_deg").GetNumberAsDouble());
    if (con.Has("limit_min_deg"))   def.hinge_min_deg   = static_cast<float>(con.Get("limit_min_deg").GetNumberAsDouble());
    if (con.Has("limit_max_deg"))   def.hinge_max_deg   = static_cast<float>(con.Get("limit_max_deg").GetNumberAsDouble());

    if (con.Has("hinge_axis")) {
        const auto& ax = con.Get("hinge_axis");
        def.hinge_axis = {
            static_cast<float>(ax.Get(0).GetNumberAsDouble()),
            static_cast<float>(ax.Get(1).GetNumberAsDouble()),
            static_cast<float>(ax.Get(2).GetNumberAsDouble())
        };
    }

    if (con.Has("parent_bone")) def.parent_bone = con.Get("parent_bone").Get<std::string>();

    return def;
}
----

== 创建约束

定义解析好之后，我们创建真正的物理约束。这一步发生在所有骨骼刚体创建完成之后，因为一条约束必须引用两个刚体——而在约束能向物理引擎注册之前，这两个刚体都必须已经存在。

[source,cpp]
----
void create_ragdoll_constraints(
    const std::vector<Node>& nodes,
    const std::map<std::string, uint32_t>& name_to_node,
    std::vector<BoneBody>& bodies,
    std::map<uint32_t, JPH::BodyID>& node_to_body,
    PhysicsWorld& physics_world)
{
    for (auto& bone_body : bodies) {
        const Node& node        = nodes[bone_body.node_index];
        const ConstraintDef& con = node.constraint_def;

        if (con.type == ConstraintDef::Type::NONE) continue;
        if (con.parent_bone.empty()) continue;

        // Look up the parent body by name
        auto parent_node_it = name_to_node.find(con.parent_bone);
        if (parent_node_it == name_to_node.end()) continue;

        auto parent_body_it = node_to_body.find(parent_node_it->second);
        if (parent_body_it == node_to_body.end()) continue;

        JPH::BodyID parent_body = parent_body_it->second;
        JPH::BodyID child_body  = bone_body.physics_body;

        if (con.type == ConstraintDef::Type::BALL_SOCKET) {
            physics_world.create_ball_socket_constraint(
                parent_body,
                child_body,
                glm::radians(con.swing_limit_deg),
                glm::radians(con.twist_limit_deg));

        } else if (con.type == ConstraintDef::Type::HINGE) {
            physics_world.create_hinge_constraint(
                parent_body,
                child_body,
                con.hinge_axis,
                glm::radians(con.hinge_min_deg),
                glm::radians(con.hinge_max_deg));
        }
    }
}
----

这里有一个重要的顺序考虑。约束应当在所有刚体都加入物理世界之后再创建，因为有些引擎（例如 Jolt Physics）要求所有刚体先进入模拟的宽相位，然后引用它们的约束才能安全注册。

== 人形角色的参考限制

为了给你一个起点，下面是一套适用于通用人形布娃娃的合理角度限制。这些数值是运动医学文献中的近似生物力学值，并略微放宽了一些，让布娃娃看起来可信，同时不必精调：

肩（球窝）从中立位置大约可以摆动 90 到 100 度，每个方向大约可以扭转 45 度。肘（铰链）从 0 度屈曲到约 145 度，在其他任何轴上都没有有意义的角自由度。手腕有一些侧向偏转（约 ±20 度）和一些屈曲/伸展（屈曲约 70 度，伸展约 60 度）——在布娃娃用途中常简化为单个铰链。

髋（球窝）向前摆动约 120 度、向后 15 度、侧向 45 度，轴向扭转约 45 度。膝（铰链）从 0 度屈曲到约 135 度。踝的屈曲与伸展合计约 50 度，常简化为一个铰链。

脊柱是最复杂的情况。现实中它是一系列小关节，每个都有几个自由度。做布娃娃时，通常把脊柱建模为两到三个球窝约束（下脊柱到中脊柱、中脊柱到上脊柱），每个的摆动限制约为 15 到 20 度——足以让脊柱弯曲、垮塌，但不足以出现怪异的对折。

这些数值只是起点，不是规范。你需要针对自己的美术风格和手感去调整。风格化的动作游戏可能想要夸张的范围。写实的模拟可能需要根据生物力学测量得出更紧的限制。正确的答案就是玩起来感觉对的那个。
