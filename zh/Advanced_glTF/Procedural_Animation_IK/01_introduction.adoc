= 程序化动画与逆向运动学

== 关键帧动画的局限

到目前为止我们构建的一切——场景图、计算蒙皮管线、物理布娃娃系统——都在为播放和混合美术在 Blender 中创作的动画服务。关键帧动画是一件强大的工具，对角色的大部分动作而言，它正是正确的做法。美术可以花上几个小时打磨一段行走循环、一次战斗挥击或一段待机呼吸动画，这份投入看得出回报。

但关键帧动画有一个根本局限：它是为特定环境创作的。行走循环假定地面是平的；伸手动画假定要去够的物体恰好在动画师摆放的位置；死亡动画假定角色倒在空旷平坦的地面上。现实世界——或者说真实的游戏世界——并非如此。

一个角色跨越布满岩石的山坡时，每只脚都需要精确落在它遇到的那个表面上，而不是悬在地面上方半米，或切进斜坡里。一个角色去够动态放置的拾取物时，手需要抵达真实的物体位置，而这个位置每帧都在变。一名士兵扑向掩体时，头部需要持续追踪敌人，即使身体这时正执行预先做好的下蹲动画。一个全速跑过急弯的角色应当向转弯内侧倾斜，而不是像在轨道上滑行那样僵直地立着。

这些问题无法靠制作更多关键帧动画来解决。地形配置、物体位置和动态场景都有无穷多种。解决方案是**程序化动画**：实时地、用数学计算求出关节变换——这些变换不由美术创作，而由引擎根据当前世界状态计算得出。

== 程序化动画是什么、不是什么

有必要说清程序化动画在这里的确切含义，因为业界对这个词的使用比较随意。本章中，我们指的是在运行时用算法修改骨架的关节变换，以响应场景的当前状态。我们谈的不是程序化内容生成、粒子系统，也不是任何生成几何体的东西。我们谈的是计算关节旋转。

程序化动画通常是叠加在关键帧动画*之上*的一层，而不是取而代之。基础姿势来自动画师的动画片段；程序化层调整特定关节以响应环境。这是一个叠加式的过程：关键帧系统提供生物学上合理的基础运动，程序化层则做出美术无法预料的、小幅而有针对性的修正。

位置修正的核心技术是**逆向运动学**，简称 IK。标准的关键帧动画按*正向运动学*工作：你设定关节旋转，末端执行器（手、脚）就落到数学上它该在的地方。IK 反过来：你指定末端执行器*必须*在的位置，算法反算出把它放到那里所需的关节旋转。这并非平凡的求逆——对一条多关节链，通常有无穷多组合法解，算法必须挑出看起来最自然的那一组。

我们会深入讲解两种 IK 算法：**循环坐标下降（CCD）**与 **FABRIK**（前向与后向到达 IK）。两者都是实用、实时的算法，在游戏引擎中被广泛使用。我们还会讲解两个最常见的应用：不平地形上的脚部放置，以及用于头部追踪的注视控制器。最后，我们会实现物理驱动的程序化倾斜，它从物理模拟的速度数据中推导出角色身体的倾斜。

== 本章与本系列其余部分的关系

本章假定你已经有一套能正常工作的场景图（第 2 章），世界矩阵能正确传播，并且你理解动画混合系统（第 3 章）。我们实现的 IK 算法会从场景图读取关节世界矩阵，并把修正后的关节局部变换写回去，触发脏标记传播系统更新所有后代节点。

第 4 章的布娃娃系统在这里也相关，尤其是在脚部放置那一节。当角色站在不平地形上时，脚部 IK 系统不能与物理系统对抗——它们必须协作。我们会讨论控制层级，以及如何确保 IK 修正与物理反馈互相加强而不是互相矛盾。
