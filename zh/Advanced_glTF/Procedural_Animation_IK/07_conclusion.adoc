= 程序化动画：小结与下一步

== 我们构建了什么

在本章中，我们从一个忠实回放美术创作动画的角色，走到了一个能实时适应环境的角色。这两者之间的距离——虽然可以用代码行数来衡量——但从玩家感知的角度看要重要得多。一个能正确踏上石块、转头注视有趣之物、并自然地倾斜着过弯的角色，会让玩家感到它*存在于*游戏世界中，而纯粹关键帧驱动的角色做不到这一点。

我们来回顾一下实现了什么。我们从两个基础的 IK 算法开始：CCD 与 FABRIK。CCD 逐个关节地工作，旋转每个关节使末端执行器逐步靠近目标，对于短链和紧凑的关节限制收敛很快。FABRIK 以位置而非旋转来思考，更均匀地重新分配链的形态，对于较长的链和整条手臂的伸展往往看起来更自然。两者都与场景图的脏标记系统集成：它们读取世界矩阵、计算修正、再写回局部旋转。

接着我们把 CCD 应用到了脚部放置——对人形角色来说这是影响最普遍的 IK 应用。脚部放置要求我们在基础 IK 之外解决三个问题：身体高度调整（骨盆必须下移以容纳不平地形）、脚部旋转（脚必须与地形法线对齐，而不只是达到正确的高度）、以及时间平滑（原始的 IK 目标会跳变；平滑后的目标才有踏实感）。我们还介绍了着地权重系统，它根据脚处于着地阶段还是摆动阶段来决定是否施加 IK 修正，确保 IK 增强而不是覆盖基础动画。

注视控制器引入了一种纯旋转的程序化技术。通过计算头部当前前向方向与指向目标的方向之间的夹角，并把这个夹角分配到从脊柱到头部的关节链上，我们实现了自然的头颈追踪。平滑目标系统确保追踪以恰当的惯性感来响应——警觉的角色快，放松的角色慢。

最后，物理驱动的倾斜系统把角色的运动物理与其身体姿态连接起来。通过从角色的加速度计算有效重力向量，我们推导出一个施加到脊柱各关节上的倾斜角。结果是：角色的身体传达了速度、重量与行进方向，而无需任何一张美术创作的倾斜动画。

== 需要记住的取舍

本章构建的每一个系统都涉及取舍，值得把它们明确说出来。

CCD 比 FABRIK 更容易正确实现，但对长链或极端伸展可能产生有偏的姿态。FABRIK 在视觉上更均衡，但需要额外一步把求解出的位置转换回关节旋转，这在坐标空间方面引入了复杂度。对于人形角色中典型的腿部链，CCD 通常是对的默认选择；对于脊柱和整条手臂的伸展，优先用 FABRIK。

带射线投射和骨盆调整的脚部放置，看起来比不做脚部放置好得多，但它在环境变化与角色适应之间引入了延迟（即平滑时间常数）。激进平滑会缩短延迟，但会增加可见跳变的几率。保守平滑感觉更自然，但意味着角色从台沿踏下后脚会短暂地悬空。在你的目标地形上做性能分析并相应调参。

基于直接旋转的注视控制器在中等角度范围内效果良好——从静止姿态算起大约可达 60 或 70 度。超出这个范围后，把旋转分配到多个关节会有帮助，但你会撞上「看起来怎样才算自然」的边界。对于需要向后看的角色，你通常需要制作一段「转身去看」的动画来让身体真正转过去，而不是试图把注视角度硬拉到 180 度。

物理驱动的倾斜纯粹是启发式的。物理上正确的倾斜角（由 `atan2(acceleration, gravity)` 推导）对同时在做其他夸张动作的游戏角色来说，往往在视觉上过于极端。`lean_strength` 这个调参参数之所以存在，正是因为物理准确性与视觉可信性不是一回事。相信你的眼睛，胜过相信公式。

== 接下来是什么

在第 6 章中，我们把注意力转向**形变目标与面部动画**。到目前为止我们所做的一切都与骨骼动画有关——也就是使身体产生形变的层级关节系统。形变目标是另一种根本不同的表示方式：它不旋转关节，而是存储逐顶点的位移向量，用于在面部表情、口型同步姿态以及其他连续形状变化之间进行混合。

形变目标带来了一系列不同的挑战。顶点数量很大——一个高质量的面部网格可能有数万个顶点——而在面部动画密集的过场动画中，活跃形变目标的数量也可能相当可观。我们将使用 Vulkan 1.4 的描述符索引来处理形变目标位移缓冲区，无需逐绘制的描述符更新，并把形变结果与第 3 章构建的蒙皮计算管线集成起来。

== 验证：要看什么

要验证你的 IK 实现：
1.  **收敛性**：在 CCD 或 FABRIK 中，监视迭代过程中误差距离的变化。它应当单调递减。如果它振荡或增大，你的关节旋转逻辑（特别是父空间到局部空间的转换）很可能是错的。
2.  **稳定性**：用不可达的目标来测试你的 IK 求解器。链应当朝目标充分伸展，而不发生抖动或剧烈打转。
3.  **骨盆调整**：确保角色站在陡坡上时髋部正确下沉。如果没有，腿看起来就会过度伸展或显得「僵硬」。
