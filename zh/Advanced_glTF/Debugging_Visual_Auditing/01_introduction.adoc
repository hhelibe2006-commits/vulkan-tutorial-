= 调试与视觉审计

== 当资产是对的，引擎是错的

上一章讲了如何在 glTF 资产进入引擎之前确保它正确。本章从资产通过验证、参考查看器显示正确结果的那一刻接起——但你的引擎渲染出来仍然有问题。

到了这个阶段，问题出在引擎代码里。问题是哪一部分代码，而这正是视觉调试工具不可或缺的地方。我们在这个系列里搭建的角色管线包含几个各自都很复杂的阶段：场景图变换层级、计算蒙皮通道、物理模拟、程序化动画层。视觉伪影可能来自其中任何一个。如果没有工具让每个阶段的状态可见，你就只能靠瞎猜。

本章的技术就是让看不见的状态变得可见。物理模拟对角色身体的每根骨骼都有完整的几何表示——但你看不到，因为物理引擎默认什么都不画。蒙皮着色器会算出一个逐顶点的输出缓冲区，其中包含最终的动画位置——但除非你知道该找什么格式，否则在 GPU 调试器里也无从检查。驱动顶点形变的骨骼影响权重以每顶点四个浮点值存储——但光看渲染出的网格，你无法判断它们是否正确。

我们会为每一个盲点实现工具。调试绘制器渲染线框几何体，把骨架、碰撞形状和物理约束的可视化叠加在角色身上。蒙皮热力图用由骨骼影响权重导出的顶点颜色渲染网格，让错误或极端的权重绘制立刻可见。RenderDoc 捕获与分析让你冻结一帧，直接检查蒙皮后的输出缓冲区，在 GPU 层面验证顶点位置和法线。
