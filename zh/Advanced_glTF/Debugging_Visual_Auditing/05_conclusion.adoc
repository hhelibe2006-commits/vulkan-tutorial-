= 调试：小结与本系列结语

== 本章我们构建了什么

调试不是某一件工具或某一种技巧——它是一套方法论：按顺序提出的一系列问题，系统地缩小可能的失败原因范围。

我们从调试绘制器开始，它让看不见的物理世界变得可见。延迟线段缓冲区的做法——每帧累积线段、一次性上传、用单次调用绘制——让调试渲染足够快，可以在开发期间一直开着而不会明显影响帧率。骨骼绘制器精确显示场景图把每个关节放在世界空间的哪个位置，使变换层级错误立刻可见。碰撞形状绘制器（运动学刚体绿色、动态刚体红色）把物理表示与渲染网格并排显示，于是你能一眼看出物理刚体是否在正确跟随动画。约束绘制器显示布娃娃的连接结构，所以当布娃娃炸开时，你能看出到底是约束没拉住（刚体彼此远离），还是一开始就设置错了（锚点不对）。

蒙皮热力图把诊断的镜头移到了顶点蒙皮数据本身。主骨骼热力图按影响最大的关节为每个顶点着色，把游离的权重指派和错误的骨骼领地暴露为异常色块。权重分布热力图按权重分布的复杂度着色，标记出权重绘制杂乱或过度复杂的区域。

RenderDoc 分析提供了 GPU 层面的真实基准：能在帧级别查看蒙皮计算输出缓冲区的确切内容，把顶点位置与期望值对照，检查法线向量是否正确，并针对某个可疑顶点单步执行着色器调用。用 `vkSetDebugUtilsObjectNameEXT` 和 `vkCmdBeginDebugUtilsLabelEXT` 给 GPU 命令和缓冲区加标签的这套习惯，让 RenderDoc 的资源浏览器变得可导航，而不是让人望而生畏。

== 系列回顾

在这八章里，我们在 Vulkan 之上搭建了一条完整、可用于生产的角色管线。让我们追踪数据从文件到帧的完整路径：

**glTF 文件**承载骨架层级、顶点蒙皮数据、动画、物理扩展元数据以及形变目标。**第 2 章**展示了如何把该层级加载进递归场景图，并用脏标记传播系统高效更新世界矩阵。**第 3 章**利用蒙皮数据构建了一条 Vulkan 计算管线，在 GPU 上对网格做形变，把结果写入一个共享缓冲区，供光栅化器、光线追踪系统和物理查询使用。

**第 4 章**建立了物理模拟层：由骨骼层级派生出代理碰撞体、编码人体活动范围的约束、ANIMATED/BLENDED/RAGDOLL 三态交接，以及通过位掩码实现的碰撞过滤。**第 5 章**在其上加入了程序化动画：用于脚部放置与伸手够物的 CCD 与 FABRIK IK、用于头部追踪的注视控制器，以及作为脊柱旋转施加的物理驱动倾斜。

**第 6 章**扩展了计算蒙皮管线以支持形变目标，利用 Vulkan 1.4 的描述符索引处理无界数组的位移缓冲区，无需每次绘制都更换描述符。**第 7 章**退后一步，建立了生产工作流：命名约定、导出设置、自动校验和参考查看器审计。**第 8 章**用引擎侧的调试工具闭合了整个闭环。

你构建的这些系统不是演示——它们是一套生产框架。每一个都设计为可与其他系统组合：IK 操作的场景图正是物理系统驱动的那个场景图；形变目标集成的计算着色器正是布娃娃读取的那个着色器；调试绘制器使用的物理世界数据正是布娃娃系统写入的那些数据。这种可组合性，就是每个阶段那些谨慎架构决策的回报。

你在这个基础上构建的下一个角色，都会受益于这里学到的每一条经验。框架会成长，资产管线会演化。但基础架构——场景图、计算蒙皮、物理集成、程序化分层——将始终是承载其他一切的骨架。

== 验证：该看什么

要验证你的调试工具：

1.  **清空行为**：确保 `DebugDrawer` 在每次 `flush()` 调用之后都正确清空其线段缓冲区。如果上一帧的线段残留下来，说明缓冲区没有被清空。
2.  **坐标空间**：确认你的调试线条出现在世界空间中。一个常见错误是把局部空间坐标传给绘制器，这会导致调试几何体错误地跟随角色。
3.  **RenderDoc 检查**：使用 RenderDoc 的 **Buffer Viewer** 检查你的计算蒙皮输出缓冲区。如果缓冲区里的值与你的预期一致，但角色渲染不正确，那么问题很可能出在顶点输入描述或图形管线状态里。
