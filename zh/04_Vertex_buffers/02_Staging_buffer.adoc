= 暂存缓冲区

== 简介

我们现在的顶点缓冲区可以正常工作，但允许我们从 CPU 访问它的那种内存类型，对显卡本身来说可能并不是读取它最优的内存类型。
最优的内存具有 `vk::MemoryPropertyFlagBits::eDeviceLocal` 标志，在独立显卡上通常无法被 CPU 访问。
本章我们要创建两个顶点缓冲区。
一个位于 CPU 可访问内存中的 _暂存缓冲区_，用来接收从顶点数组上传的数据；另一个是位于设备本地内存中的最终顶点缓冲区。
然后我们用缓冲区拷贝命令把数据从暂存缓冲区移动到实际的顶点缓冲区。

== 传输队列

缓冲区拷贝命令需要支持传输操作的队列族，用 `vk::QueueFlagBits::eTransfer` 表示。
好消息是，任何具备 `vk::QueueFlagBits::eGraphics` 或 `vk::QueueFlagBits::eCompute` 能力的队列族都已经隐式支持 `vk::QueueFlagBits::eTransfer` 操作。
在这些情况下，实现不需要在 `queueFlags` 中显式列出它。

如果你喜欢挑战，仍然可以尝试为传输操作专门使用另一个队列族。
这需要你对程序做以下修改：

* 在 `uint32_t queueIndex` 之外引入 `uint32_t transferQueueIndex`（现在也许该把前者重命名为 `graphicsQueueIndex`），并显式寻找带有 `vk::QueueFlagBits::eTransfer` 位、但不带 `vk::QueueFlagBits::eGraphics` 的队列族。
* 修改 `createLogicalDevice`，请求 `vk::raii::Queue` 类型的 `transferQueue` 句柄（也许还要把 `queue` 重命名为 `graphicsQueue`）
* 为在传输队列族上提交的命令缓冲区创建第二个命令池
* 把资源的 `sharingMode` 改为 `vk::SharingMode::eConcurrent`，并同时指定图形和传输两个队列族
* 把 `vk::raii::CommandBuffer::copyBuffer` 这类传输命令（本章会用到）提交到传输队列，而不是图形队列

这有点麻烦，但它会让你深入了解资源如何在队列族之间共享。

== 抽象缓冲区创建

本章要创建多个缓冲区，所以最好把缓冲区创建移到一个辅助函数里。
新建 `createBuffer` 函数，把 `createVertexBuffer` 中的代码（映射部分除外）移进去。

[,c++]
----
std::pair<vk::raii::Buffer, vk::raii::DeviceMemory> createBuffer(vk::DeviceSize size, vk::BufferUsageFlags usage, vk::MemoryPropertyFlags properties)
{
  vk::BufferCreateInfo   bufferInfo{.size = size, .usage = usage, .sharingMode = vk::SharingMode::eExclusive};
  vk::raii::Buffer       buffer          = vk::raii::Buffer(device, bufferInfo);
  vk::MemoryRequirements memRequirements = buffer.getMemoryRequirements();
  vk::MemoryAllocateInfo allocInfo{.allocationSize = memRequirements.size, .memoryTypeIndex = findMemoryType(memRequirements.memoryTypeBits, properties)};
  vk::raii::DeviceMemory bufferMemory = vk::raii::DeviceMemory(device, allocInfo);
  buffer.bindMemory(*bufferMemory, 0);
  return {std::move(buffer), std::move(bufferMemory)};
}
----

记得为缓冲区大小、内存属性和用途添加参数，这样我们就能用这个函数创建许多不同类型的缓冲区。
该函数把生成的缓冲区和绑定到它的设备内存一起作为 `std::pair` 返回。
由于 `vk::raii` 句柄无法拷贝，你必须把它们从函数中移动出来。

现在你可以从 `createVertexBuffer` 中删掉缓冲区创建和内存分配的代码，改为直接调用 `createBuffer`：

[,c++]
----
void createVertexBuffer()
{
  vk::DeviceSize bufferSize = sizeof(vertices[0]) * vertices.size();

  auto [stagingBuffer, stagingBufferMemory] =
      createBuffer(bufferSize, vk::BufferUsageFlagBits::eTransferSrc, vk::MemoryPropertyFlagBits::eHostVisible | vk::MemoryPropertyFlagBits::eHostCoherent);

  void *dataStaging = stagingBufferMemory.mapMemory(0, bufferSize);
  memcpy(dataStaging, vertices.data(), bufferSize);
  stagingBufferMemory.unmapMemory();
}
----

运行程序，确认顶点缓冲区仍然正常工作。

== 使用暂存缓冲区

现在我们要改写 `createVertexBuffer`，只把主机可见的缓冲区用作临时缓冲区，而把设备本地缓冲区用作实际的顶点缓冲区。

[,c++]
----
void createVertexBuffer()
{
  vk::DeviceSize bufferSize = sizeof(vertices[0]) * vertices.size();

  auto [stagingBuffer, stagingBufferMemory] =
      createBuffer(bufferSize, vk::BufferUsageFlagBits::eTransferSrc, vk::MemoryPropertyFlagBits::eHostVisible | vk::MemoryPropertyFlagBits::eHostCoherent);

  void *dataStaging = stagingBufferMemory.mapMemory(0, bufferSize);
  memcpy(dataStaging, vertices.data(), bufferSize);
  stagingBufferMemory.unmapMemory();

  std::tie(vertexBuffer, vertexBufferMemory) =
      createBuffer(bufferSize, vk::BufferUsageFlagBits::eVertexBuffer | vk::BufferUsageFlagBits::eTransferDst, vk::MemoryPropertyFlagBits::eDeviceLocal);

  copyBuffer(stagingBuffer, vertexBuffer, bufferSize);
}
----

我们现在用一个新的 `stagingBuffer` 及其 `stagingBufferMemory` 来映射和拷贝顶点数据。
本章会用到两个新的缓冲区用途标志：

* `vk::BufferUsageFlagBits::eTransferSrc`：缓冲区可以在内存传输操作中作为源。
* `vk::BufferUsageFlagBits::eTransferDst`：缓冲区可以在内存传输操作中作为目标。

`vertexBuffer` 现在从设备本地的内存类型中分配，这通常意味着我们无法使用 `vk::raii::DeviceMemory::mapMemory`。
不过，我们可以把数据从 `stagingBuffer` 拷贝到 `vertexBuffer`。
我们必须通过为 `stagingBuffer` 指定传输源标志、为 `vertexBuffer` 指定传输目标标志（外加顶点缓冲区用途标志）来表达这个意图。

现在我们来写一个把内容从一个缓冲区拷贝到另一个缓冲区的函数，名为 `copyBuffer`。

[,c++]
----
void copyBuffer(vk::raii::Buffer & srcBuffer, vk::raii::Buffer & dstBuffer, vk::DeviceSize size)
{
}
----

内存传输操作和绘制命令一样，都是通过命令缓冲区执行的。
因此我们必须先分配一个临时命令缓冲区。
你也许希望为这类短命的缓冲区单独创建一个命令池，因为实现可能会据此应用内存分配优化。
这种情况下，你应在创建命令池时使用 `vk::CommandPoolCreateFlagBits::eTransient` 标志。

[,c++]
----
void copyBuffer(vk::raii::Buffer & srcBuffer, vk::raii::Buffer & dstBuffer, vk::DeviceSize size)
{
  vk::CommandBufferAllocateInfo allocInfo{ .commandPool = commandPool, .level = vk::CommandBufferLevel::ePrimary, .commandBufferCount = 1 };
  vk::raii::CommandBuffer commandCopyBuffer = std::move(device.allocateCommandBuffers(allocInfo).front());
}
----

然后立即开始录制命令缓冲区：

[,c++]
----
commandCopyBuffer.begin({.flags = vk::CommandBufferUsageFlagBits::eOneTimeSubmit});
----

我们只会使用这个命令缓冲区一次，并且在拷贝操作执行完成之前不会从这个函数返回。
用 `vk::CommandBufferUsageFlagBits::eOneTimeSubmit` 把我们的意图告诉驱动是个好习惯。

[,c++]
----
commandCopyBuffer.copyBuffer(*srcBuffer, *dstBuffer, vk::BufferCopy(0, 0, size));
----

缓冲区的内容通过 `vk::raii::CommandBuffer::copyBuffer` 命令传输。
它以源缓冲区和目标缓冲区为参数，还接受一个要拷贝的区域数组。
区域由 `vk::BufferCopy` 结构体定义，包含源缓冲区偏移、目标缓冲区偏移和大小。
与 `vk::raii::DeviceMemory::mapMemory` 不同，这里无法指定 `vk::WholeSize`。

[,c++]
----
commandCopyBuffer.end();
----

这个命令缓冲区只包含拷贝命令，所以紧接着就可以停止录制。
现在执行命令缓冲区以完成传输：

[,c++]
----
queue.submit(vk::SubmitInfo{.commandBufferCount = 1, .pCommandBuffers = &*commandCopyBuffer}, nullptr);
queue.waitIdle();
----

与绘制命令不同，这次没有需要等待的事件。
我们只想立即在缓冲区上执行传输。
等待这次传输完成同样有两种可行方式。
我们可以使用栅栏并通过 `vk::raii::Device::waitForFences` 等待，或者干脆用 `vk::raii::Queue::waitIdle` 等待传输队列变为空闲。
栅栏允许你同时安排多次传输并等待它们全部完成，而不是一次只执行一个。
这可能会给驱动更多优化的机会。

现在可以在 `createVertexBuffer` 函数中调用 `copyBuffer`，把顶点数据移动到设备本地缓冲区：

[,c++]
----
copyBuffer(stagingBuffer, vertexBuffer, bufferSize);
----

把数据从暂存缓冲区拷贝到设备缓冲区之后，RAII 缓冲区对象会自行清理并释放内存。

运行程序，确认你再次看到了熟悉的三角形。
目前可能还看不出改进，但它的顶点数据现在是从高性能内存中加载的。
等我们开始渲染更复杂的几何体时，这一点就会变得重要。

== 结语

需要注意的是，在真实应用中，你不应该为每个单独的缓冲区都调用 `vk::raii::Device::allocateMemory`。
同时存在的内存分配数量上限受物理设备限制 `maxMemoryAllocationCount` 约束，即使像 NVIDIA GTX 1080 这样的高端硬件，这个值也可能低到 `4096`。
同时为大量对象分配内存的正确做法是编写自定义分配器，利用我们在许多函数中见过的 `offset` 参数，把单次分配合给许多不同的对象。

你可以自己实现这样的分配器，也可以使用 GPUOpen 计划提供的 https://github.com/GPUOpen-LibrariesAndSDKs/VulkanMemoryAllocator[VulkanMemoryAllocator] 库。
不过在本教程中，为每个资源使用单独的分配是可以的，因为目前我们还远不会触及这些限制。
