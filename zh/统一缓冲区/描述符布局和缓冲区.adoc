= 描述符布局和缓冲区
:toc:
:toclevels: 3
:toc-title: 目录

== 介绍
现在我们可以为每个顶点传递任意属性给顶点着色器，但是全局变量呢？从本章开始我们将学习 3D 图形，这需要一个模型-视图-投影矩阵。我们可以将其作为顶点数据包含，但这会浪费内存，并且每次变换发生变化时都需要更新顶点缓冲区。而变换很容易在每一帧都发生变化。

在 Vulkan 中，解决这个问题的正确方法是使用资源描述符。描述符允许着色器自由访问缓冲区和图像等资源。我们将设置一个包含变换矩阵的缓冲区，并让顶点着色器通过描述符访问它们。描述符的使用包含三个部分：

- 在管道创建期间指定描述符集布局
- 从描述符池中分配描述符集
- 绑定渲染期间设置的描述符

描述符集布局指定了管线将要访问的资源类型，就像渲染通道指定了将要访问的附件类型一样。描述符集指定了将绑定到描述符的实际缓冲区或图像资源，就像帧缓冲区指定了要绑定到渲染通道附件的实际图像视图一样。然后，描述符集会像顶点缓冲区和帧缓冲区一样，绑定到绘制命令。

描述符有很多种类型，但本章我们将使用统一缓冲区对象 (UBO)。我们将在后续章节中介绍其他类型的描述符，但基本流程相同。假设我们有一个 C 结构体，其中包含我们希望顶点着色器使用的数据，如下所示：

[source,c++]
----
struct UniformBufferObject
{
    glm::mat4 model;
    glm::mat4 view;
    glm::mat4 proj;
};
----

== 顶点着色器
然后我们可以将数据复制到 `vk::raii::Buffer` 中，并通过顶点着色器中的统一缓冲区对象描述符访问它，如下所示：

[source,slang]
----
struct VSInput {
    float2 inPosition;
    float3 inColor;
};

struct UniformBuffer {
    float4x4 model;
    float4x4 view;
    float4x4 proj;
};
ConstantBuffer<UniformBuffer> ubo;

struct VSOutput
{
    float4 pos : SV_Position;
    float3 color;
};

[shader("vertex")]
VSOutput vertMain(VSInput input) {
    VSOutput output;
    output.pos = mul(ubo.proj, mul(ubo.view, mul(ubo.model, float4(input.inPosition, 0.0, 1.0))));
    output.color = input.inColor;
    return output;
}
----

我们将逐帧更新模型矩阵、视图矩阵和投影矩阵，使上一章中的矩形在三维空间中旋转。我假设您熟悉 MVP 变换。如果您不熟悉，请参阅第一章中提到的 https://www.opengl-tutorial.org/beginners-tutorials/tutorial-3-matrices/[资源]。

修改顶点着色器，使其包含如上所述的统一缓冲区对象。SV_Position修改代码行，使其使用变换来计算裁剪坐标系中的最终位置。与二维三角形不同，裁剪坐标系的最后一个分量可能不是 `1`，这会导致在转换为屏幕上的最终归一化设备坐标时出现除法运算。这在透视投影中用作透视除法，对于使近处物体看起来比远处物体更大至关重要。

== 片段着色器
片段着色器与前几章保持一致：

[source,slang]
----
[shader("fragment")]
float4 fragMain(VSOutput vertIn) : SV_TARGET {
    return float4(vertIn.color, 1.0);
}
----

== 描述符集布局
下一步是在 C++ 端定义 UBO，并在顶点着色器中将此描述符告知 Vulkan。

[source,c++]
----
struct UniformBufferObject
{
    glm::mat4 model;
    glm::mat4 view;
    glm::mat4 proj;
};
----

我们可以使用 GLM 中的数据类型精确匹配着色器中的定义。矩阵中的数据与着色器期望的方式是二进制兼容的，因此我们稍后可以直接 `memcpy` 将 `UniformBufferObject` 转换为 `vk::raii::Buffer`。

我们需要提供着色器中用于管线创建的每个描述符绑定的详细信息，就像我们之前需要提供每个顶点属性及其location索引的详细信息一样。我们将创建一个名为 `createDescriptorSetLayout` 的新函数来定义所有这些信息。它应该在管线创建之前调用，因为我们在创建管线时需要用到这些信息。

[source,c++]
----
void initVulkan()
{
    ...
    createDescriptorSetLayout();
    createGraphicsPipeline();
    ...
}

...

void createDescriptorSetLayout()
{
}
----

每个绑定都需要通过 `vk::DescriptorSetLayoutBinding` 结构体来描述。

[source,c++]
----
void createDescriptorSetLayout() {
		vk::DescriptorSetLayoutBinding uboLayoutBinding{
		    .binding = 0, .descriptorType = vk::DescriptorType::eUniformBuffer, .descriptorCount = 1, .stageFlags = vk::ShaderStageFlagBits::eVertex};
}
----

前两个字段指定着色器中使用的描述符类型，即统一缓冲区对象。着色器变量 `binding` 可以表示统一缓冲区对象数组，并 `descriptorCount` 指定数组中值的数量。例如，这可以用于为骨骼动画中的每个骨骼指定变换。我们的 MVP 变换位于单个统一缓冲区对象中，因此我们使用一个统一缓冲区对象 `descriptorCount` 的值为 `1`。

我们还需要指定描述符将在哪些着色器阶段被引用。该 `stageFlags` 字段可以是多个值 `vk::ShaderStageFlagBits` 的组合，也可以是单个值 `vk::ShaderStageFlagBits::eAllGraphics`。在本例中，我们仅在顶点着色器中引用该描述符。

该 `pImmutableSamplers` 字段仅与图像采样相关的描述符有关，我们稍后会详细介绍。您可以保留其默认值。

所有描述符绑定都合并到一个 `vk::raii::DescriptorSetLayout` 对象中。在上面定义一个新的类成员 `pipelineLayout`：

[source,c++]
----
vk::raii::DescriptorSetLayout descriptorSetLayout = nullptr;
vk::raii::PipelineLayout      pipelineLayout      = nullptr;
----

然后我们可以使用 `vk::raii::DescriptorSetLayout` 构造函数来创建它。此函数接受一个简单的 `vk::DescriptorSetLayoutCreateInfo` 绑定数组：

[source,c++]
----
vk::DescriptorSetLayoutBinding uboLayoutBinding{
    .binding = 0, .descriptorType = vk::DescriptorType::eUniformBuffer, .descriptorCount = 1, .stageFlags = vk::ShaderStageFlagBits::eVertex};
vk::DescriptorSetLayoutCreateInfo layoutInfo{.bindingCount = 1, .pBindings = &uboLayoutBinding};
descriptorSetLayout = vk::raii::DescriptorSetLayout(device, layoutInfo);
----

我们需要在创建渲染管线时指定描述符集布局，以告知 Vulkan 着色器将使用哪些描述符。描述符集布局在渲染管线布局对象中指定。修改以下代码 `vk::PipelineLayoutCreateInfo` 以引用该布局对象：

[source,c++]
----
vk::PipelineLayoutCreateInfo pipelineLayoutInfo{ .setLayoutCount = 1, .pSetLayouts = &*descriptorSetLayout, .pushConstantRangeCount = 0 };
----

你可能想知道为什么这里可以指定多个描述符集布局，因为单个描述符集布局已经包含了所有绑定。我们将在下一章详细讨论这个问题，届时我们将探讨描述符池和描述符集。

== 均匀缓冲层
下一章我们将指定用于着色器的统一缓冲区 (UBO) 数据所在的缓冲区，但首先我们需要创建这个缓冲区。由于每一帧都会将新数据复制到统一缓冲区，因此使用暂存缓冲区实际上没有任何意义。在这种情况下，暂存缓冲区只会增加额外的开销，并可能降低性能而不是提升性能。

我们应该使用多个缓冲区，因为可能同时有多个帧在传输，我们不希望在前一帧仍在读取缓冲区数据时，为了准备下一帧而更新缓冲区！因此，我们需要拥有与传输帧数相同的统一缓冲区，并且写入操作应写入GPU当前未读取的统一缓冲区。

为此，添加新的类成员 `uniformBuffers`，以及 `uniformBuffersMemory`：

[source,c++]
----
vk::raii::Buffer       indexBuffer        = nullptr;
vk::raii::DeviceMemory indexBufferMemory  = nullptr;

std::vector<vk::raii::Buffer>       uniformBuffers;
std::vector<vk::raii::DeviceMemory> uniformBuffersMemory;
std::vector<void *>                 uniformBuffersMapped;
----

同样地，创建一个新函数，`createUniformBuffers` 该函数在之后被调用 `createIndexBuffer` 并分配缓冲区：

[source,c++]
----
void initVulkan()
{
    ...
    createVertexBuffer();
    createIndexBuffer();
    createUniformBuffers();
    ...
}

...

void createUniformBuffers()
{
    for (size_t i = 0; i < MAX_FRAMES_IN_FLIGHT; i++)
    {
        vk::DeviceSize bufferSize = sizeof(UniformBufferObject);
        auto [buffer, bufferMem]  = createBuffer(
            bufferSize, vk::BufferUsageFlagBits::eUniformBuffer, vk::MemoryPropertyFlagBits::eHostVisible | vk::MemoryPropertyFlagBits::eHostCoherent);
        uniformBuffers.emplace_back(std::move(buffer));
        uniformBuffersMemory.emplace_back(std::move(bufferMem));
        uniformBuffersMapped.emplace_back( uniformBuffersMemory.back().mapMemory(0, bufferSize));
    }
}
----

我们在创建缓冲区后立即对其进行 `vk::raii::DeviceMemory::mapMemory` 映射，以获取一个指针，以便稍后将数据写入该指针。在应用程序的整个生命周期内，缓冲区始终映射到此指针。这种技术称为“持久映射”，适用于所有 Vulkan 实现。由于映射并非免费，因此无需在每次更新缓冲区时都重新映射，从而提高性能。

== 更新统一数据

创建一个新函数 `updateUniformBuffer`，并在提交下一帧之前从 `drawFrame` 函数中添加对该函数的调用：

[source,c++]
----
void drawFrame()
{
    ...

    updateUniformBuffer(frameIndex);

    ...

		const vk::SubmitInfo   submitInfo{.waitSemaphoreCount   = 1,
		                                  .pWaitSemaphores      = &*presentCompleteSemaphores[frameIndex],
		                                  .pWaitDstStageMask    = &waitDestinationStageMask,
		                                  .commandBufferCount   = 1,
		                                  .pCommandBuffers      = &*commandBuffers[frameIndex],
		                                  .signalSemaphoreCount = 1,
		                                  .pSignalSemaphores    = &*renderFinishedSemaphores[imageIndex]};

    ...
}

...

void updateUniformBuffer(uint32_t currentImage)
{
}
----

该函数会在每一帧生成一个新的变换，使几何体旋转。我们需要添加两个新的头文件来实现此功能：

[source,c++]
----
#include <glm/glm.hpp>
#include <glm/gtc/matrix_transform.hpp>

#include <chrono>
----

该 `glm/gtc/matrix_transform.hpp` 标头公开了可用于生成模型变换（例如 `glm::rotate`）、视图变换（例如 `glm::lookAt`）和投影变换（例如 `glm::perspective`）的函数。

标准 `chrono` 库头文件公开了一些用于精确计时的函数。我们将利用这些函数来确保几何体无论帧速率如何，都能以每秒 90 度的速度旋转。

[source,c++]
----
void updateUniformBuffer(uint32_t currentImage)
{
    static auto startTime = std::chrono::high_resolution_clock::now();

    auto currentTime = std::chrono::high_resolution_clock::now();
    float time       = std::chrono::duration<float, std::chrono::seconds::period>(currentTime - startTime).count();
}
----

该 `updateUniformBuffer` 函数首先会执行一些逻辑，以浮点精度计算自渲染开始以来经过的时间（以秒为单位）。

现在我们将定义统一缓冲区对象中的模型、视图和投影变换。模型旋转将是绕 Z 轴的简单旋转，使用以下 `time` 变量：

[source,c++]
----
UniformBufferObject ubo{};
ubo.model = rotate(glm::mat4(1.0f), time * glm::radians(90.0f), glm::vec3(0.0f, 0.0f, 1.0f));
----

该 `glm::rotate` 函数接受一个已存在的变换、旋转角度和旋转轴作为参数。`glm::mat4(1.0f)` 构造函数返回一个单位矩阵。使用旋转角度 `time * glm::radians(90.0f)` 可以实现每秒旋转 90 度的目的。

[source,c++]
----
ubo.view = lookAt(glm::vec3(2.0f, 2.0f, 2.0f), glm::vec3(0.0f, 0.0f, 0.0f), glm::vec3(0.0f, 0.0f, 1.0f));
----

对于视图变换，我决定以45度角从上方观察几何体。该 `glm::lookAt` 函数以眼睛位置、中心位置和向上轴作为参数。

[source,c++]
----
ubo.proj =
    glm::perspective(glm::radians(45.0f), static_cast<float>(swapChainExtent.width) / static_cast<float>(swapChainExtent.height), 0.1f, 10.0f);
----

我选择使用透视投影，垂直视场角为 45 度。其他参数包括宽高比、近视平面和远视平面。重要的是，要使用当前的交换链范围来计算宽高比，以便在调整窗口大小后考虑窗口的新宽度和高度。

GLM 最初是为 OpenGL 设计的，OpenGL 中裁剪坐标的 Y 坐标与 Vulkan 中的坐标相反。如果不进行相应的补偿，图像将会上下颠倒渲染。

一种常见的补偿方法是反转投影矩阵中 Y 轴缩放因子的符号（`ubo.proj[1][1] *= -1;`）。这种方法虽然有效，但也会反转投影矩阵的手性，这就需要在 `frontFace` 启用背面剔除的地方进行相应的翻转，并且可能会影响下游任何假定使用标准右手投影的程序。因此，我们将在视口阶段应用相同的校正，这样就不会影响投影矩阵。返回到您在命令缓冲区 `vk::Viewport` 中设置的，并为其赋予负高度：

[source,c++]
----
commandBuffer.setViewport(0, vk::Viewport(0.0f, static_cast<float>(swapChainExtent.height), static_cast<float>(swapChainExtent.width), -static_cast<float>(swapChainExtent.height), 0.0f, 1.0f));
----

将高度设置 `y` 为全值或 `height` 负值会在视口变换期间翻转 Y 轴（此变换在裁剪之后应用）——最终图像的最终效果与翻转投影矩阵相同，但投影矩阵本身及其手性保持不变。这是 Vulkan 的核心功能（源自 Vulkan 的 `VK_KHR_maintenance1`），因此无需启用任何额外的功能或扩展。

现在所有变换都已定义完毕，我们可以将统一缓冲区对象中的数据复制到当前统一缓冲区。这与顶点缓冲区的操作完全相同，只是无需临时缓冲区。如前所述，我们只需映射一次统一缓冲区，因此可以直接写入而无需再次映射：

[source,c++]
----
memcpy(uniformBuffersMapped[currentImage], &ubo, sizeof(ubo));
----

以这种方式使用 UBO 并不是向着色器传递频繁变化的值的最有效方法。向着色器传递少量数据缓冲区的更高效方法是推送常量。我们可能会在以后的章节中讨论这些内容。

xref:描述符池和集.adoc[下一章]我们将研究描述符集，它实际上会将 `vk::raii::Buffer` 绑定到统一缓冲区描述符，以便着色器可以访问此变换数据。
