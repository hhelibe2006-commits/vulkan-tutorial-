= 构建推理引擎入门

你已经学习了 ML 推理管线，探索了 ONNX Runtime 这类第三方库，也实现了基础的 Vulkan 计算运算。接下来的问题是：既然 ONNX Runtime 这样的库已经存在而且工作得很好，你为什么要自己造一个推理引擎？

诚实的答案？对大多数生产应用来说，你大概不该造。ONNX Runtime 凝聚了多年的优化工作，支持数百个算子，并在无数次部署中经受了检验。能用就用它。

但弄懂如何构建推理引擎，会让你学到更深入的东西。它揭开了底层运作的神秘面纱。当你遇到性能瓶颈、数值精度问题或部署限制时，你会明白它们为什么发生、该如何应对。在何时该用哪个库、哪些优化才重要、自己正在做什么取舍上，你也会做出更好的判断。

本节将教你从零构建一个简单但可用的推理引擎。它还没到生产可用的程度，但足够真实，能在你的 GPU 上运行真正的神经网络。

== 旅程

我们会分阶段构建它，每个阶段都揭示一层理解：

**阶段 1：硬编码前向传播**。我们从最简单、最可能行得通的方案开始——单个神经网络，逐层硬编码。你从一个简单的二进制文件加载权重，并按顺序执行每一层的计算着色器。没有灵活性，没有抽象，只有直接执行。这是我们的基线。它能工作，更重要的是，它完全可以理解。

**阶段 2：识别模式**。一旦你看到硬编码版本跑通了，你就会注意到重复。每一层做的事都类似：分配缓冲区、上传数据、绑定描述符、派发计算着色器。差异只在细节里——用哪个着色器、尺寸是多少、参数有哪些。我们找出哪些是共通的、哪些是变化的。

**阶段 3：抽象**。模式识别出来之后，我们就构建抽象。用一个张量类来表示数据，用一个运算接口表示层，用一种图结构来记录连接关系。这样我们就能表示任意网络，而不只是硬编码的那一个。

**阶段 4：模型格式**。现在我们需要一条把网络定义和权重送进引擎的路。我们可以自己发明一种格式，但业界已经解决了这个问题。ONNX 和 TensorFlow Lite 是全领域通用的标准格式。我们学习解析它们，提取出图结构和训练好的权重。

**阶段 5：集成**。最后，我们把所有部件串起来。加载模型文件、构建内部表示、分配 GPU 资源、执行推理。最终得到的是一个能运行真实网络的可用推理引擎。

== 我们要构建什么

到本节结束时，你将拥有这样的代码：

- 加载训练好的 MNIST 模型（手写数字识别）
- 从 ONNX 或 TensorFlow Lite 格式中解析模型结构和权重
- 在 Vulkan 计算上执行完整的前向传播
- 产出正确的预测（可对照 PyTorch/TensorFlow 验证）

这个实现不会是生产可用的。它只支持有限的几种层类型（全连接、卷积、ReLU、最大池化），也不会有全部优化。但它是真实的、完整的，并且有教学价值。

== 教学代码与生产代码

在本节中，我们做选择时优先考虑清晰，而不是性能。在生产代码里，你会用到这些技术：

- 算子融合（把多个运算合并进一个着色器，见 xref:ML_Inference/Advanced_Topics/05_model_optimization.adoc[模型优化技术：超越代码]）
- 高级内存池化（在互不重叠的生命周期之间复用缓冲区，见 xref:ML_Inference/Advanced_Topics/04_memory_management.adoc[高级内存管理：突破内存墙]）
- FP16 或 INT8 量化（用精度换速度，见 xref:ML_Inference/Advanced_Topics/02_quantization_strategies.adoc[量化策略：精通比特预算]）
- 多线程图执行（并行运行互相独立的运算）

我们会在后面的章节里触及这些内容，但我们的推理引擎保持简单。目标是理解，而不是最大吞吐量。
