= Mojo / MAX：来自 Modular 的编译器驱动推理

== 概述

Modular 的 Mojo（编程语言）与 MAX（推理引擎）致力于给开发者带来类 Python 的体验，同时具备编译器级的性能。其工作流强调导入常见模型格式、执行图级与内核级优化，并部署紧凑、可直接上生产的产物。这套栈演进很快；请把本章当作实用指引，而非固定规范。我们的目标是讲清心智模型与集成形态，让你能跑通第一次构建并评估它是否合适。

== 需要的工具

计划先在 Python 里验证。准备好你的训练框架以便导出，如果统一用 ONNX 就备好 ONNX 工具链，以及适用于你平台的 MAX/Mojo SDK。具体的安装器与 CLI 变化频繁——请遵循 Modular 当前文档，为你的操作系统取得正确版本。同时备好 CPU 黄金参考（例如 ONNX Runtime），这样每当你更换编译器或精度时，都能量化正确性。

== 与 IREE/TVM 的定位对比

如果你今天就需要一个高度可控、支持 Vulkan AOT 的开源编译器，xref:ML_Inference/Third_Party_Libraries/12_iree.adoc[IREE] 与 xref:ML_Inference/Third_Party_Libraries/13_apache_tvm.adoc[TVM] 在 Vulkan 上最为成熟。MAX/Mojo 优先考虑开发者体验与一体化感受。当它们满足你的平台需求时，你会得到非常顺手且性能强劲的工作流。

对后端要求要明确。MAX 通常侧重 CPU 与厂商 GPU 后端（例如 CUDA/Metal）。Vulkan 的可用性取决于平台，在某些环境中可能以间接方式（经 SPIR‑V/WebGPU 路径）提供。如果 Vulkan 是跨目标的硬性要求，请在你的设备上核实当前支持情况；否则在本教程以 Vulkan 为先的路径中，优先选 IREE/TVM。

== 命令之前，先讲思路

MAX 把你的模型编译一次，交给你一个打包好的产物，外加一个小运行时供你在应用里调用。把前处理/后处理留在 Vulkan 中，这样就能与本教程其他路径共享代码。把 MAX 当作一个库边界：张量进，张量出。

== 实用工作流（高层）

你会依次转换/导入、编译/打包，然后运行/部署。多数团队统一以 ONNX 作为交接格式，走 PyTorch→ONNX 或 TensorFlow→SavedModel/ONNX。为你的目标编译，并把产物随运行时一起发布。在应用里像调用库一样调用打包好的模型。把 Vulkan 前处理/后处理留在外面，这样无论换哪个编译器，其余代码都保持不变。

用一个固定形状的模型和一个可复现的输入张量来锚定整个过程。运行一次 CPU 黄金参考并保存期望输出。每次更改编译器选项或后端时，都用简单的误差指标（MAE/RMSE）与同一参考对比。这样就把集成变成受控实验，而不是靠猜。

由于 CLI 与 API 细节会随时间变化，具体调用方式请查阅当前文档。关键的架构思想与本教程其余部分一致：每个模型/配置编译一次，发布一个小运行时，并让 Vulkan 前处理/后处理保持独立，以求清晰与性能。

== 目标后端与 Vulkan

后端覆盖范围随版本发布而变化。在桌面上，可以预期有强大的 CPU 与厂商 GPU 后端（CUDA/Metal）。Vulkan 支持可能视平台与版本以间接方式（SPIR‑V 或 WebGPU 路径）提供——请在你的目标硬件上核实。在移动端/嵌入式上，请再次确认受支持的后端，并留意体积占用。

如果 Vulkan 可用性是硬性要求且你必须马上发布，优先选 IREE/TVM。如果 MAX 支持的后端已覆盖你的硬件，那么对重视一体化工具链的团队来说，它可能是最舒适的选择。

== 集成模式

无论选哪个编译器，与 Vulkan 应用的集成模式都相同：

1）在 Vulkan 中前处理：缩放/归一化到张量缓冲区，避免 CPU 开销。
2）通过引擎运行时调用编译好的模型。
3）在 Vulkan/CPU 中后处理并呈现。

这样能把拷贝降到最低，并让你用异步计算重叠工作。

== 验证正确性（不要跳过）

在编译路径旁边保留一条参考路径（例如 CPU 上的 ONNX Runtime）。喂入完全相同的输入，计算误差指标，并在结果背离时逐层二分定位差异。把它固化成一个小脚本，每次构建都能跑；当某次驱动更新或精度变更本会悄悄引入回归时，第一次跑它就能回本。

== Android 与嵌入式说明

为你的 ABI 交叉编译运行时，把打包好的模型随资产一起发布，并在设备上测量。如果你需要为散热做占空比控制，就采用嵌入式各章所用的同一套框架：间歇运行推理，并在视觉连续性重要时用 Vulkan 在结果之间做插值。

== 故障排查

如果模型导入失败，就在导出时简化图、核对形状，并尝试另一种交换格式（ONNX 与 SavedModel）。如果运行时输出看起来不对，就与（CPU 上的）黄金参考对比，先修正第一处偏离的层，再追求性能。

== NNEF 互操作

把 NNEF→ONNX 转换作为第一步。进入 ONNX 后，按 MAX/Mojo 的标准编译器导入路径处理。
