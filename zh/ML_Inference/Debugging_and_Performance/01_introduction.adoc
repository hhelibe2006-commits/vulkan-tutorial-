= 调试与性能：验证与速度的艺术
:pp: ++
:stem: latexmath

你已经构建好了 ML 推理应用。你编排过描述符集，编写过计算着色器，也处理过 Vulkan 资源管理这套复杂的舞蹈。它能编译，能运行而不崩溃，甚至还能吐出一个装满数字的张量。但接下来是那个价值百万美元的问题：**它真的在正常工作吗？**

在传统图形学里，如果存在 bug，通常一眼就能看出来。屏幕闪着品红色，阴影脱离了地面，或者角色变成一堆参差不齐的三角形。而在机器学习里，bug 常常是**无声的**。一个配置错误的归一化常量，或者一道稍微写错的内存屏障，都不会让应用崩溃；它只会产出一个「大体正确」但在数学上错误的结果。

设想你正在构建一套自动驾驶系统。如果你的推理引擎只有 1% 的数值漂移，它也许不会完全认不出道路，但可能会把「停止」标志错认成「限速」标志。这就是我们面对的风险。

本节不只关注找出崩溃——它关注的是找出**真相**。我们要从「看起来能跑」走向「我已经对照基准真值验证了每一个小数位」。一旦正确性就位，我们随后会把注意力转向工程的第二根支柱：**性能**。因为在真实世界里，一个以 2 FPS 运行的完美模型，和一个以 60 FPS 运行的坏模型一样没用。

== 「无声失败」问题

面向 ML 的 Vulkan 计算是一场高空走钢丝。你拥有显式控制 GPU 的全部力量，同时也承担全部责任。与 TensorFlow 或 PyTorch 这类高级框架不同——它们替你处理同步与内存布局的「管道活儿」——Vulkan 期望你成为每一个字节的主人。

在深度神经网络中，误差是**累积**的。如果你的第一个卷积层有一点微小的精度误差，这个误差会被随后 50 层不断放大和变换。等它到达 Softmax 输出时，那 0.001 的微小偏差就可能决定置信度得分是 99% 还是 51%。

=== 无声 bug 的解剖

Vulkan ML 中最常见的一些「无声杀手」包括：

*   **同步缺口**：你的 ReLU 着色器在 GPU 尚未完成写入刷新之前，就从卷积输出缓冲区读取数据。在一块快速的桌面 GPU 上，这可能 99% 的时候都能正常工作，但在一块缓存行为不同的移动 SoC 上，它就会产出垃圾数据。
*   **数值漂移**：对高动态范围数据使用 `float16` 却没有做恰当的缩放。如果你的激活值超出半精度格式的表示范围，就会得到「NaN」（非数）结果，它会传播到整个网络，最终让你的整个输出归零。
*   **布局不匹配**：你的着色器期望的是平面（NCHW）张量，而你的预处理环节仍在输出交错（HWC）数据。网络「看到」的是一团乱序的东西，却仍尽力去分类，于是给出随机的、低置信度的预测。
*   **量化噪声**：在没有恰当校准的情况下把 32 位权重转成 8 位整数。如果浮点范围与整数范围之间缺乏严谨的映射，网络就会「幻觉」出并不存在的模式。

== 专家思维：验证、分析、优化

为了解决这些问题，我们采用一套三阶段的工程纪律，它与专业引擎（如 TensorRT 或 ONNX Runtime）的构建方式如出一辙。

=== 1. 验证正确性（「基准真值」阶段）
我们把 Vulkan 的结果与一份**黄金参考**做对比——通常是运行在 CPU 上的 PyTorch 或 ONNX Runtime。我们不只检查最终输出，而是检查**每一层**。这种对 bug 的「二分查找」让我们能精确定位到底是哪一个计算着色器偏离了数学真相。

=== 2. 分析瓶颈（「侦探」阶段）
一旦确认代码正确，我们就问：「它为什么慢？」我们借助 **RenderDoc**、**NVIDIA Nsight** 和 **Radeon GPU Profiler** 等工具查看底层实况。我们测量内核的**算术强度**，判断我们究竟受限于数学运算的速度（计算受限），还是受限于内存总线的速度（内存受限）。

=== 3. 优化关键路径（「一级方程式」阶段）
知道瓶颈之后，我们做外科手术式的优化。如果内存受限，就用**共享内存分块**。如果延迟受限，就用**内核融合**来消除显存往返。我们的目标是触及硬件的 **Roofline 极限**——即某一架构在物理上所能达到的最高性能。

== 低效的代价

在嵌入式或移动环境中，性能不只是「顺不顺滑」的问题——它还关乎**续航**与**散热**。

[latexmath]
++++
\text{Energy} = \text{Power} \times \text{Time}
++++

一个以 100% GPU 利用率运行 50 ms 的未优化 Vulkan 着色器，耗电速度是一个融合优化后、10 ms 就跑完并让 GPU 进入休眠状态的着色器的 5 倍。本节会教你如何成为一名注重能效的开发者。

== 你将掌握什么

读完本章，你不只是「懂 Vulkan」的人——你会成为一名性能工程师。你将学会：

*   **数值验证**：如何用 latexmath:[MAE]（平均绝对误差）与 latexmath:[MSE]（均方误差）从数学上证明你的实现是准确的。
*   **Vulkan 调试**：掌握 RenderDoc，用它「冻结时间」，检查 GPU 缓冲区里的原始比特。
*   **GPU 架构**：理解 **Warp**、**波前** 与**内存层级**构成的隐秘世界。
*   **优化配方**：可直接复制粘贴的实用模式，涵盖共享内存分块与 NC/4HW4 向量化布局。
*   **异步计算**：如何利用多个 Vulkan 队列，把你的 ML 推理「藏进」图形渲染通道里面。

调试与优化不是「额外」步骤；它们就是开发过程的核心。代码能编译不代表你完成了；只有当结果真实、性能最优时，你才算完成。
