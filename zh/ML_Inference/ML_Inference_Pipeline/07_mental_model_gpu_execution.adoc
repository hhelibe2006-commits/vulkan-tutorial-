= 心智模型：GPU 执行

我们已经走过了一大片领域——从什么是机器学习，到神经网络如何工作，再到打包训练好的模型的那些格式。现在该用一个心智模型把这一切串起来了：它把这些概念统统连到 Vulkan 的实际 GPU 执行上。

把这一章看作退后一步看全局。我们会沿着完整路径走一遍：从磁盘上一个训练好的模型，到在你的 GPU 上跑起来的推理，并沿途指出关键挑战和设计决策。

== 从模型到 GPU 的旅程

让我们跟着一个训练好的模型，看它在你的应用里走完整个生命周期。理解这段旅程，能帮你看清每一块拼在哪里，以及它为什么重要。

*第 1 步：训练（不关我们的事）*

在某个地方，某个人训练了一个神经网络。可能是你，也可能是某位发表了预训练模型的研究者。他们用 PyTorch 或 TensorFlow，喂进去数百万个样本，经过几小时乃至几天的计算，得到一个训练好的模型。权重和偏置已经学好了，模型在测试数据上表现不错，现在它可以部署了。

我们的故事就从这里开始——有一个训练好的模型，需要它在生产环境中高效运行。

*第 2 步：导出为推理格式*

训练框架的原生格式并不适合部署。它带着训练专用的机制，可能绑定在某个特定的框架版本上，也没有针对体积或加载速度做优化。所以模型会被导出成推理格式——TFLite 或 ONNX。

这个导出过程会剥掉训练专用的组件，优化计算图（删除不必要的运算、尽可能融合层），并把所有东西打包成紧凑的标准格式。你得到的只是一个文件——可能几 MB，也可能几百 MB——里面包含网络架构、全部学到的权重，以及关于如何使用它的元数据。

*第 3 步：加载与解析（你的第一个挑战）*

现在你的应用需要加载这个模型文件。这是第一个真正的挑战：解析特定于格式的结构，把需要的信息提取出来。

你读的是一个带特定模式的二进制文件。对 ONNX 来说，这意味着解析 Protocol Buffers；对 TFLite 来说，是 FlatBuffers。两者各有各的怪癖，但都包含同样的关键信息：有哪些层、它们如何连接、每一层执行什么运算，以及每个运算的权重。

解析的同时，你在构建一种内部表示——一个抓住模型架构的图结构。图中每个节点代表一个运算（卷积、矩阵乘法、激活函数等），边则代表运算之间的数据流。

*第 4 步：编译到 Vulkan（翻译）*

手里有了模型图，你需要把它翻译成 Vulkan 计算运算。你的神经网络知识和 Vulkan 知识正是在这里汇合。

模型里每一种运算都需要一个对应的计算着色器。卷积层需要卷积着色器。矩阵乘法需要矩阵乘法着色器。激活函数需要激活着色器。你本质上是在建一个实现神经网络运算的计算着色器库。

但光有着色器还不够。你还需要：

*分配 GPU 内存*，供所有张量使用——输入、输出、中间激活和权重。这是一个重要的设计决策。你要一次性预分配全部内存（静态分配），还是按需分配（动态分配）？对于不再需要的中间结果，你会复用它们的内存吗？

*上传权重*到 GPU 内存。这些是定义模型的那数百万个学到的参数。推理期间它们保持不变，所以只需上传一次，然后让它们常驻 GPU 内存。

*创建 Vulkan 管线*，为每个着色器配上合适的描述符集来访问缓冲区。这是标准的 Vulkan 工作，但规模可能比你习惯的更大——一个复杂模型可能有几十种不同的运算类型。

*规划执行顺序*。模型图告诉你依赖关系——哪些运算必须在其他运算开始前完成。你需要把它转成一串带恰当同步的计算派发。

*第 5 步：执行推理（收获时刻）*

现在可以跑推理了。每个推理请求都会经历下面这些步骤：

*传输输入数据*到 GPU 内存。可能是图像、音频缓冲区，或其他输入数据。传输本身很直接，但对延迟敏感的应用来说，把这份开销压到最小很重要。

*按计划好的顺序派发计算着色器*。每个着色器读取输入张量、执行运算、写出输出张量。数据一层一层流过网络，直到最后的输出。

*在运算之间同步*。这对正确性至关重要。你必须确保每个运算都已完成、其写入在依赖它的运算开始前可见。Vulkan 为此提供了几种工具：管线屏障、内存屏障和信号量。

*把结果回读*到 CPU 内存。最终的输出张量里是你的预测结果——类别概率、检测到的对象、生成的文本，模型产出什么就是什么。

整个过程——从输入到输出——必须跑得快。对于实时应用，你可能只有几毫秒来完成一次推理。

== 关键挑战

我们深入看看每个阶段会遇到的挑战，因为理解这些挑战能帮你做出更好的设计决策。

=== 挑战 1：内存管理

神经网络处理的是大型多维数组（张量）。单张图像可能是 224×224×3 个浮点数（约 600KB）。中间激活可能大得多。一个典型模型可能需要数百 MB 的 GPU 内存。

最朴素的做法——给每个张量都分配一个新缓冲区——很浪费。很多中间张量只在很短时间内需要。一个运算完成后、它的输出被下一个运算消费掉，那块内存就可以复用。

聪明的做法是分析模型图，找出哪些张量可以共享内存。如果张量 A 只在运算 1-3 中需要，张量 B 只在运算 5-7 中需要，它们就可以用同一块内存。这叫作*内存复用*或*内存池化*，能大幅减少内存占用。

代价是复杂度。带内存复用的静态分配需要预先分析整张图并规划内存使用。动态分配更简单，但更慢、更占内存。对大多数应用来说，静态分配带来的性能收益值得那份实现复杂度。

=== 挑战 2：同步

GPU 是高度并行的，但神经网络推理本质上是串行的——每一层都依赖前一层的输出。第 4 层没完成，就没法开始第 5 层。这就在并行性和依赖之间造成了张力。

Vulkan 让你显式控制同步，这既强大又危险。同步太少，会出现竞态——运算在数据写入之前就读它，导致结果错误。同步太多，又会把执行串行化，损失并行性和性能。

关键在于精确理解你的依赖关系。用管线屏障强制必要的顺序，同时让独立的运算重叠执行。例如，如果你的模型有并行分支（现代架构中很常见），只要在它们合并时做同步，这些分支就可以并发执行。

=== 挑战 3：性能优化

让推理跑通是一回事，让它跑得快是另一回事。优化机会有很多：

*运算融合*：把多个运算合并进单个着色器可以减少开销。例如，卷积后面紧跟激活，可以融合成一个同时做这两件事的着色器，省掉一个中间缓冲区和一次派发。

*内存布局*：数据在内存里的排布方式影响缓存效率。某些布局对特定运算更友好。找到正确的布局——或者在布局之间转换——会显著影响性能。

*批处理*：把多个输入放在一起处理，能更好地利用 GPU，从而提高吞吐量。不要一次只对一张图像做推理，而是 4 张、8 张或 16 张一起处理。这会增加延迟，但能大幅提升吞吐量。

*硬件专属特性*：现代 GPU 对某些运算有专用硬件。例如 NVIDIA GPU 上的 Tensor core、AMD 上的 WMMA，或 Intel 上的 XMX，都能加速矩阵乘法。了解你的目标硬件并利用它的能力（通常通过 WebGPU 或 Vulkan 这类跨厂商 API），可以带来可观的加速。

挑战在于弄清哪些优化对你的具体模型和硬件才重要。性能分析必不可少——先测出时间实际花在哪里，再去优化那些热点。

== 以层和运算来思考

在实现推理时，想清楚神经网络概念与 GPU 计算运算之间的映射会很有帮助。我们用例子把它讲具体些。

*全连接（Dense）层*：它本质上是一次矩阵乘法，后接一个激活函数。输入是向量（或一批向量），权重是矩阵，你计算的是 `output = activation(weights × input + bias)`。在 GPU 上，这变成一个矩阵乘法着色器加一个激活着色器。矩阵乘法是耗时的部分——根据维度不同是 O(n²) 或 O(n³)——所以优化它很重要。

*卷积层*：这是一个滑动窗口运算。你拿一个小滤波器（也许是 3×3 或 5×5）在输入上滑动，在每个位置计算加权和。再加上多个滤波器和多个输入通道，计算量就很大了。在 GPU 上，你可以在输出位置和通道上并行化。每个工作组可以计算一个输出块（tile），组内线程处理不同的通道或位置。

*池化层*：这更简单——在小区域上取最大值或平均值来做降采样。它高度并行：每个输出位置都是独立的。你的着色器可以并行处理很多输出位置，几乎不需要同步。

*归一化层*：它需要沿某个维度计算统计量（均值、方差），然后再归一化。这更棘手，因为计算统计量需要归约运算，而归约需要小心的同步。不过一旦拿到统计量，应用归一化就很直接了。

理解这些映射能帮你设计高效的着色器，并对性能做出推理。卷积很多的模型会受限于计算。小运算很多的模型会受限于开销。明白这一点，你的优化策略就有了方向。

== 把它们整合起来

我们走一个完整的例子，把它落到实处。想象你在对一个图像分类模型做推理——比如 ResNet-50 这样的模型。

你从一张图像开始：224×224×3 个像素。把它传到 GPU 内存——约 600KB。第一层是卷积：7×7 的滤波器，64 个输出通道。你派发卷积着色器，它读取输入图像和权重张量，计算卷积，写出输出。这个输出是 112×112×64（因为步长而降了采样）。

接下来是批量归一化和 ReLU 激活。你为这些运算派发着色器，读入卷积的输出，写出归一化并激活后的结果。

然后你进入一连串残差块——ResNet 的核心。每个块都有多次卷积、归一化和激活，还有把较早的激活加到较晚的激活上的跳跃连接。你为每个运算派发着色器，小心同步，确保跳跃连接读到的是正确的数据。

经过很多层之后，你到达全局平均池化——把每个通道缩减成一个值。然后是一个最终的全连接层，产出类别概率。你派发最后这几个着色器，输出是一个 1000 维的概率向量（对应 ImageNet 的类别）。

最后，你把这个输出回读到 CPU 内存。找出概率最大的那个，那就是你的预测：「金毛寻回犬」还是「咖啡杯」，取决于模型认为图像里有什么。

整个过程——几十次着色器派发、数百 MB 数据流过 GPU——在几毫秒内完成。这就是 GPU 加速对神经网络推理的威力。

== 小结

本章给出了用 Vulkan 做 ML 推理的完整心智模型，沿着从训练好的模型到 GPU 执行的路径走了一遍。这条管线包括：导出为推理格式、加载并解析模型文件、编译成 Vulkan 计算着色器，以及在 GPU 上执行推理。

关键挑战是内存管理（高效地分配和复用缓冲区）、同步（在不把执行过度串行化的前提下强制依赖关系），以及性能优化（融合、布局、批处理、硬件特性）。理解神经网络层与 GPU 计算运算之间的映射，能帮你设计高效的实现。

在「ML 推理管线」这一系列章节中，我们已经打下了一个全面的基础：什么是机器学习、神经网络如何工作、训练与推理的区别、迁移学习策略、模型格式，以及完整的执行管线。这些概念上的理解，为下一章的实践实现做好了准备，那里我们会深入面向 ML 负载的 Vulkan 计算着色器。

== 回顾与展望

我们来回顾一下整个系列章节中学到的东西：

我们从理解*机器学习*开始：它让计算机从数据中学习，而不是遵循显式的规则。这个根本转变——从编写规则到学习模式——让那些无法显式编程的任务成为可能。

我们探讨了*神经网络*——受生物神经元启发的数学函数。我们看到了为什么*单靠线性函数不够*——它们会坍缩成更简单的形式——以及为什么*非线性激活函数*对神经网络逼近复杂函数至关重要。

我们区分了*训练*与*推理*，明白推理关注的是高效地使用训练好的模型，而不是学习过程本身。我们探讨了*推理管线*：预处理、神经网络执行和后处理。

我们学习了*迁移学习*，它让我们能利用预训练模型，而不必从头训练。我们探讨了*模型格式*（TFLite 和 ONNX），它们连接起训练框架和部署环境。

最后，我们沿着*完整管线*从训练好的模型走到了 GPU 执行，指出了内存管理、同步和性能优化方面的关键挑战。
