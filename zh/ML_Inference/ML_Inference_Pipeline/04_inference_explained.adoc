= 推理详解

== 引言

在上一章中，我们探索了神经网络是如何学习的——通过梯度下降、反向传播和迭代优化调整数百万个权重的复杂过程。我们从第一性原理出发构建理解，看清网络在训练中如何从数据里发现模式。

现在，我们要彻底转移焦点。本教程系列讲的不是训练神经网络——而是*使用*它们。具体来说，讲的是拿已经训练好的模型，用 Vulkan 计算着色器在 GPU 上高效运行。这个过程称为*推理*，它与训练有着根本性的不同，而这些差异对实现方式影响深远。

理解这一区别并非只是学术问题——它塑造我们将要做的每一个设计决策。我们写的代码、分配的内存、实现的同步，全都源于对「推理是什么、不是什么」的理解。

== 两个阶段，两个世界

机器学习有两个截然不同的阶段，它们发生在不同时间、不同地点，目标与约束也不同。下面我们逐一厘清。

=== 训练：学习阶段

把训练看作研发阶段。在某个地方——也许是大学实验室，也许是科技公司，也许就是你自己的工作台——有人正在教一个神经网络执行某项任务。

他们从一个一无所知的网络开始。权重是随机的。如果你喂给它一张猫的图片，它会输出胡言乱语——也许会自信地宣称这是一台烤面包机。此时网络什么也没学到。

接着训练过程开始。网络看到数百万个样本：标着「猫」的猫图片、标着「狗」的狗图片、标着「车」的汽车图片。对每个样本，网络做出一个预测。当它预测错误时（一开始几乎总是错），训练算法会衡量错得有多离谱，并稍微调整权重，让下次做得更好。

这个过程重复数百万次。网络逐渐学会模式：「有尖耳朵和胡须的图像往往是猫」「有轮子和车窗的图像往往是车」。那些权重——上一章讨论过的数百万个数字——从随机值慢慢变成编码这些知识的有意义模式。

这个过程*代价高昂*。在高端 GPU 上，用 ImageNet 训练一个现代图像识别模型可能要花几天甚至几周。训练一个大语言模型的计算成本可能高达数百万美元。它需要海量数据集、对学习率和其他超参数的细致调优，以及在优化算法上的深厚专业知识。

好消息是？你通常不需要亲自做这件事。研究者和公司训练好模型并公开发布。你可以下载一个预训练模型，它已经知道如何识别物体、翻译语言或生成图像。训练这项苦活已经有人做完了。

=== 推理：部署阶段

推理是训练完成之后发生的事。你有一个训练好的模型——一个包含数百万个已学习权重的文件。现在你想*使用*它，对新数据做出预测。

这是完全不同的场景。权重是固定的——它们不再变化。没有学习，没有优化，也没有反向传播。你只是把数据送过网络，得到预测。

约束也不同了。训练是离线的，通常在性能强劲的服务器硬件上进行，想花多久就花多久。推理发生在生产环境中，通常在性能较弱的设备上，而且必须*快*。当用户打开你的应用、把摄像头对准某个物体时，他们期待立刻识别出来。当游戏需要做一个 AI 决策时，它不能等上几秒才拿到预测——它需要在毫秒级得到答案。

这正是 Vulkan 的用武之地。把推理实现在 Vulkan 层，我们就能细粒度地控制 GPU 执行。我们可以针对推理特有的约束做优化：固定权重、只做前向传播、实时性能要求。我们不是在构建训练系统——我们在构建部署系统，这是一个截然不同的工程挑战。

=== 为什么这一区分对实现很重要

理解训练与推理的分野，对我们如何构建 Vulkan 推理引擎有实际影响。

训练时，你需要保存每一层的中间激活值，因为反向传播要用它们计算梯度。这意味着整个前向传播过程都要留在内存里。对推理而言，我们只需要当前层的激活值——一旦算出第 5 层的输出并传给第 6 层，第 5 层的激活值就可以丢弃，那块内存可以复用。这大幅降低了内存需求。

训练时，你会把大量样本成批处理（32、64、128 甚至更多），因为这样能得到更稳定的梯度估计和更好的 GPU 利用率。对推理而言，如果需要低延迟，你可以一次只处理一个样本；如果追求吞吐量，也可以分批——这取决于你的应用需求，由你来选。

训练时，你需要自动微分、梯度计算和优化器状态。对推理而言，这些全都不存在。我们实现的系统要简单得多：加载权重、跑前向传播、拿到输出。这种简单是一种解放——我们可以把全部精力放在让前向传播尽可能快上。

== 推理管线：让数据流过整个系统

我们来追踪一下运行推理时实际发生了什么。理解这条流程，能帮你看清 Vulkan 处在什么位置，以及我们需要实现什么。

=== 阶段 1：输入数据到达

你的应用手上有一些希望模型处理的数据。可能是摄像头拍到的图像、麦克风采集的音频缓冲区、用户输入的文本，或者设备的传感器读数。这些数据以应用自然产生的格式存在——图像可能是缓冲区里的 RGB 像素，音频可能是 PCM 采样，文本可能是字符串。

这些原始数据还不能直接喂给神经网络。模型对输入格式有特定预期，我们需要满足这些预期。

=== 阶段 2：预处理转换数据

预处理是连接应用数据格式与模型期望输入格式的桥梁。这个阶段可能包含多种变换，做对至关重要——如果你的预处理与模型的期望不符，无论模型多好，预测结果都是垃圾。

==== 图像预处理：从像素到张量

我们从图像开始，因为它在图形应用中很常见，而且这些变换很直观。

*缩放*：模型是在特定输入尺寸上训练的。一个在 224×224 图像上训练的模型，学到的是那个尺度下的模式。如果你喂给它一张 1920×1080 的图像，模式就处在完全不同的尺度上——本来应该是一张脸的东西可能占据整个输入，本来应该是一个完整物体的东西可能只剩一个小角落。你需要先缩放。

但缩放并不简单。要裁剪吗？如果要，从哪儿裁——中心裁剪还是随机裁剪？要拉伸吗？如果宽高比不匹配，你是拉伸（让图像变形）还是加黑边（letterbox）？答案取决于模型是怎么训练的。如果它是在中心裁剪的图像上训练的，推理时就应该中心裁剪；如果是在拉伸的图像上训练的，就应该拉伸。这里不匹配会降低精度。

*归一化*：图像通常把像素存为 0 到 255 的 8 位整数。神经网络处理的是浮点数，而且对输入值的取值范围很敏感。大多数模型期望输入被归一化到特定区间。

常见的归一化方案包括：

- 缩放到 [0, 1]：`pixel_float = pixel_int / 255.0`
- 缩放到 [-1, 1]：`pixel_float = (pixel_int / 127.5) - 1.0`
- 标准化：`pixel_float = (pixel_int - mean) / std`，其中 mean 和 std 由训练数据集计算得出

最后一种尤为重要。许多模型（尤其是用 ImageNet 训练的模型）期望输入按 ImageNet 统计量做标准化：mean = [0.485, 0.456, 0.406]，std = [0.229, 0.224, 0.225]（每个 RGB 通道各一组）。如果你没有施加完全相同的归一化，模型看到的输入就偏离了它训练时的分布，精度会受损。

*色彩空间转换*：这是一个不易察觉的坑。OpenCV 以 BGR 顺序（蓝、绿、红）加载图像，而大多数 ML 框架期望 RGB（红、绿、蓝）。如果你用其中一种约定训练模型，却用另一种约定做推理，模型就会在本该看到蓝色的地方看到红色，反之亦然。对某些模型来说，这会彻底破坏预测结果。

同样，有些模型期望灰度输入（单通道），有些期望 RGB（三通道）。把 RGB 转成灰度并不是简单地对通道取平均——正确的转换使用考虑了人眼感知的加权和：`gray = 0.299*R + 0.587*G + 0.114*B`。

*通道顺序*：即便同为 RGB，内存布局也有差异。有些框架用「通道在后」（height × width × channels），像素按 RGBRGBRGB… 存放；另一些用「通道在前」（channels × height × width），所有红色值在前，然后是绿色，再是蓝色。你的模型期望其中一种，你需要与之匹配。

==== 文本预处理：从字符串到词元

文本预处理更复杂，因为它涉及语言结构，而不只是数值变换。

*分词*：把文本切成片段是第一步。最简单的是词级分词：「Hello world」变成 ["Hello", "world"]。但这样有问题——标点怎么办？模型从未见过的词怎么办？

现代模型使用子词分词。字节对编码（BPE）或 WordPiece 之类的算法会把词拆成更小的单元。「unhappiness」可能变成 ["un", "happiness"]，这样即使模型在训练时从未见过「unhappiness」，只要它分别见过「un」和「happiness」，也能理解这个词。

每个词元（token）会被转换成一个来自词表的数值 ID。「Hello」可能是 ID 5234，「world」可能是 ID 8912。模型处理的是这些 ID，而不是原始文本。

*序列长度处理*：模型有最大序列长度——可能是 512 个词元，也可能是 1024 个。如果你的输入更短，就用特殊的填充词元补齐；如果更长，就截断。截断的位置很重要：从开头截、从末尾截，还是智能地保留最重要的部分？

*特殊词元*：大多数模型期望用特殊词元标记结构。开头的 [CLS] 词元可能表示「这是一个序列的起点」，[SEP] 词元可能用来分隔不同片段，[PAD] 词元填充未使用的位置。这些词元在词表中有特定 ID，你需要把它们插入到模型期望的位置。

==== 音频预处理：从波形到特征

音频预处理通常要把原始波形变换成神经网络更容易处理的表示。

*重采样*：音频可能以 48kHz 录制，但你的模型期望 16kHz。重采样会改变采样率，其中涉及抗混叠滤波和插值生成新样本。

*单声道转换*：如果你的音频是立体声而模型期望单声道，你需要合并通道。简单取平均即可：`mono = (left + right) / 2`，但更精细的做法可能会保留更多信息。

*频谱图*：许多音频模型不处理原始波形，而是处理频谱图——用频域表示音频。频谱图展示每个时间点上存在哪些频率。计算频谱图要对音频信号的叠接窗口施加短时傅里叶变换（STFT）。

梅尔频谱图更进一步，把频率轴转换到梅尔刻度，这更符合人类对音高的感知。语音识别系统之类的模型通常期望这种输入。

==== 预处理发生在哪里：CPU 与 GPU

传统上，预处理在 CPU 上完成。与运行神经网络相比，它相对轻量，而 CPU 也很擅长处理这些多样的操作（缩放、色彩转换、分词）。

但对性能敏感的应用来说，GPU 预处理可能带来明显差别。如果你要以每秒 60 帧处理视频，每帧在 CPU 预处理上花 5ms，累积起来就很可观。把这部分移到 GPU——把缩放和归一化实现为计算着色器——能显著降低延迟。

代价是复杂度。CPU 预处理可以使用现成的库（图像用 OpenCV，音频用 librosa，分词器来自 ML 框架）。GPU 预处理则意味着要自己写计算着色器并管理数据传输。对大多数应用来说，CPU 预处理就够了。对延迟敏感的应用（实时视频处理、交互式 AR/VR），GPU 预处理值得考虑。

==== 与训练保持一致至关重要

关键洞见是：推理时的预处理必须与训练时的预处理*完全*一致。如果模型训练时用的是双线性插值缩放，推理时你也应该用双线性插值。如果训练时用的是 ImageNet 归一化，推理时你必须用 ImageNet 归一化。

这里的不匹配是推理精度不佳的常见原因。模型在训练框架里表现很好，一部署就失效，因为预处理有细微差异。一定要查阅模型文档或训练代码，弄清楚用的到底是什么预处理。

=== 阶段 3：神经网络执行

这是推理的核心——运行真正的神经网络。预处理后的输入数据逐层流过网络，直到抵达输出。训练期间学到的所有东西，都在这里派上用场。

我们用一个例子把它具体化。假设你在运行一个图像分类模型——比如 ResNet 或 MobileNet。输入是 224×224×3 的张量（高 × 宽 × 颜色通道），也就是 150,528 个代表图像的浮点数。

==== 第一层：特征提取开始

第一层可能是一个卷积，有 64 个 7×7 的滤波器，步长为 2。这在实践中意味着什么？

卷积是一种滑动窗口操作。想象拿一个 7×7 的放大镜在图像上滑动，一次挪一步。在每个位置，你看到的是 7×7 的像素块（跨全部 3 个颜色通道，所以实际上是 7×7×3 = 147 个值）。你把 147 个值各自乘上对应的已学习权重，全部求和，再加上偏置项，就得到一个输出值。

现在你有 64 个不同的滤波器，每个都有自己的一套 147 个权重。于是在每个位置，你算出 64 个不同的输出值——每个滤波器一个。每个滤波器都学会了检测不同的模式：也许一个检测水平边缘，另一个检测垂直边缘，再一个检测红色区域，等等。

步长为 2 意味着窗口每次移动 2 个像素而不是 1 个，输出在每个维度上就只有一半大。于是 224×224×3 的输入变成 112×112×64 的输出。你在空间上做了降采样（224×224 到 112×112），却增加了通道数（3 到 64）。你是在用空间分辨率换特征丰富度。

仅这一个卷积层就涉及大约 224 × 224 × 64 × 7 × 7 × 3 = 1.47 亿次乘加运算。计算量很大，但 GPU 恰好擅长这类工作——同一个操作在不同数据上重复数百万次。

==== 激活函数：引入非线性

卷积之后，输出会流过激活函数——比如 ReLU。回想上一章讲过的为什么这很重要：没有非线性，堆叠层并不会增强网络的表达能力。正是激活函数让网络能学习复杂的模式。

ReLU 简洁得漂亮：`output = max(0, input)`。对卷积输出的 112×112×64 = 802,816 个值，每个值如果是正数就保留，是负数就替换为零。这在计算上很便宜——只是一个比较和一次选择——但它是网络正常工作的必要条件。

从 GPU 的角度看，这是典型的易并行操作。每个输出值都独立于其他所有值。你可以同时处理成千上万个值，线程之间不需要任何同步。

==== 更深的层：构建层级特征

随着数据流向网络深处，模式在延续，但特征变得更抽象。第二个卷积层看到的不是原始图像，而是第一层的输出——它已经表示了边缘和基本模式。这一层学会把这些边缘组合成更复杂的形状：角、曲线、简单纹理。

第三层再把这些形状组合成更复杂的模式：物体的部件、有辨识度的纹理、反复出现的纹样。等到深入 10 层或 20 层时，网络检测的已是高层概念：「这看起来像毛发」「这看起来像车轮」「这看起来像一张脸」。

这种层级式特征学习是深层神经网络如此强大的关键洞见之一。浅层学到通用、可复用的特征（边缘对任何图像都适用），中间层学到领域相关的模式（毛发、金属还是玻璃），深层学到任务特定的概念（猫、狗还是车）。

==== 批归一化：让数值保持在合理范围

许多现代网络包含批归一化层。这些层解决一个微妙的问题：数据流过许多层后，数值的分布可能发生偏移和扩散。一开始处在合理范围（比如 0 到 1）的值，到第 20 层时可能均值变成 100、标准差变成 50。这让训练变得不稳定，也会损害推理性能。

批归一化通过在每一层对数值做归一化来解决这个问题。它计算激活值的均值和标准差，然后平移、缩放，使其均值为 0、标准差为 1（或者接近，具体由可学习参数提供一定灵活性）。

推理时有一个简化：均值和标准差是训练期间算好的固定值。你不需要在运行时统计，只需施加一个固定变换：`output = (input - mean) / sqrt(variance + epsilon) * scale + shift`。这仍然是逐元素操作，但需要为每一层加载那些固定统计量（mean、variance、scale、shift）。

==== 池化：为效率而降采样

池化层在保留重要信息的同时缩小空间维度。最常见的最大池化把输入分成小块（通常是 2×2），只输出每块中的最大值。

为什么这么做？它减少了流经网络的数据量，让后续层更快。它还提供了一定程度的平移不变性——如果某个特征在图像中稍微移动，只要仍在池化区域内，最大池化依然能捕捉到它。

从实现角度看，最大池化很直接：对每个输出位置，读入 4 个输入值（2×2 池化），求最大值，写出。所有输出位置之间都是并行的。

==== 全连接层：做出最终决策

在网络接近末尾的地方，经过多次卷积提取出丰富特征之后，通常会看到全连接（稠密）层。这些层把全部特征组合起来，做出最终预测。

全连接层不过是一次矩阵乘法。如果你有 2048 个输入特征和 1000 个输出类别，就是用 1000×2048 的权重矩阵乘以 2048 维的输入向量。这是 2,048,000 次乘加运算，全部都可以并行。

最后一层通常为每个类别输出原始分数（logits）。它们还不是概率——只是一些数字，表示网络认为某个类别存在的程度有多强。数字越大，置信度越高。

==== 完整的前向传播

综合起来，对 ResNet-50 这类网络做一次完整的前向传播包括：

- 1 个初始卷积层
- 16 个残差块，每块包含 3 个卷积、3 个批归一化和 3 个 ReLU 激活，外加跳跃连接
- 1 个全局平均池化层
- 1 个全连接层

总共约 50 层（所以叫「ResNet-50」），涉及数十亿次乘加运算。在现代 GPU 上，整个过程只需几毫秒就能完成。

每一层都从 GPU 内存读取输入张量，执行计算，再把输出张量写回 GPU 内存。一层的输出成为下一层的输入。数据像水在管道中流动一样穿过网络，在每个阶段发生变换，最后作为预测结果涌现出来。

这正是 Vulkan 大放异彩的地方。每一层变成一个计算着色器。张量以缓冲区的形式存放在 GPU 内存中。我们派发计算操作来处理它们，用同步保证正确的执行顺序，并把数据从一层传到下一层。GPU 的大规模并行能力让我们能同时处理成千上万个值，使推理快到足以满足实时应用。

=== 阶段 4：后处理解读输出

神经网络产出的是原始输出，但在对你的应用有用之前，这些输出往往需要解读。从网络里出来的原始数字就只是数字。后处理把它们变成可行动的信息。

==== 分类：从 logits 到标签

对分类模型来说，输出通常是一个分数向量，称为 *logits*——每个可能的类别对应一个数字。如果你要把图像分到 1000 个类别（比如 ImageNet），就会得到 1000 个数字。

这些 logits 还不是概率。它们是原始分数，可以是任何值——正、负、大、小。「猫」的 logit 是 5.2、「狗」的是 2.1，只说明网络对「猫」更有信心，但这些数字不能当作百分比来解读。

*Softmax 转换*：要把 logits 转成概率，你需要施加 softmax 函数：

[source]
----
probability[i] = exp(logit[i]) / sum(exp(logit[j]) for all j)
----

这保证所有概率都在 0 与 1 之间，且总和为 1。现在你可以说「模型有 87% 的把握认为这是一只猫」。

*找最高预测*：最简单的后处理就是找出最大概率并返回对应类别标签。这只是对输出向量做一次线性扫描——O(n)，n 是类别数。

*Top-K 预测*：你常常想要前 5 个预测，而不只是第 1 个。当模型不确定时这很有用——也许它有 40% 的把握认为是「金毛寻回犬」，35% 认为是「拉布拉多」，15% 认为是「黄色拉布拉多」。这三种都说得通，全部展示能给用户更多信息。

找 Top-K 需要部分排序或基于堆的方法。对 K=5、n=1000 个类别而言，这仍然非常快。

*置信度阈值*：有时你只想返回超过某个置信度阈值的预测。如果最高预测只有 30% 的置信度，也许你该返回「不确定」而不是硬猜。这取决于具体应用——医疗诊断可能要求 95% 的置信度，而照片应用也许 50% 就接受了。

==== 目标检测：从边界框到对象

目标检测更复杂。网络输出多个检测结果，每个包含：

- 一个边界框（x, y, width, height）
- 一个类别标签（或每个类别的概率）
- 一个置信度分数（网络有多确定这里有一个对象）

典型的检测器可能输出 10,000 个以上候选框，其中大多数是误检或重复。

*置信度过滤*：首先滤掉低置信度的检测。如果某个框的置信度低于 0.5（或你选定的任何阈值），就丢弃它。这样一下子就把 10,000 个候选减少到大概 100 到 200 个。

*非极大值抑制（NMS）*：多个框常常检测到同一个对象。你可能会有 5 个框都在检测同一辆车，位置和大小略有不同。NMS 负责去掉这些重复。

算法是这样的：
1. 按置信度对所有框排序（最高在前）
2. 取出置信度最高的框，加入输出
3. 删除与这个框重叠显著的框（通常 IoU > 0.5）
4. 对剩余框重复上述过程

「重叠」用交并比（IoU）衡量：重叠面积除以并集面积。如果两个框重叠了 80%，它们很可能在检测同一个对象，那就只保留置信度更高的那个。

NMS 最坏情况下是 O(n²)，但先做置信度过滤后，n 已经足够小，在 CPU 上跑得很快。检测数量很多时也有 GPU 实现。

*按类别 NMS*：有些检测器按类别分别施加 NMS。检测「车」的框不会抑制检测「人」的框，即使两者重叠。这样就能在同一位置检测出多个对象（比如坐在车里的人）。

*坐标转换*：检测器输出的框常常是归一化坐标（0 到 1），或相对于锚框的坐标。你需要把它们转换成图像空间中的绝对像素坐标，这要根据图像尺寸做缩放和偏移。

==== 分割：从掩码到区域

分割模型为每个像素输出一个标签。对一张 224×224、含 21 个类别（比如 Pascal VOC）的图像，输出是 224×224×21 的张量——每个像素 21 个概率值。

*用 argmax 得到标签*：对每个像素找出概率最高的类别。这把 224×224×21 的张量变成 224×224 的标签图，每个像素只有一个类别 ID。

*掩码平滑*：原始输出可能有噪声——个别像素会被误分类。施加少量平滑（比如中值滤波或形态学操作）能清理掩码。

*轮廓提取*：如果你需要物体边界而不是像素标签，就从掩码中提取轮廓。这样会得到勾勒每个物体的多边形或曲线，有时比像素网格更有用。

*实例分割*：有些模型会区分同一类别的不同实例（两辆不同的车，而不只是「车的像素」）。后处理要把像素聚类成实例，常用连通分量或更复杂的算法。

==== 生成模型：从噪声到内容

生成模型（如 GAN 或扩散模型）输出图像、音频或文本。这里的后处理就是让输出变得可用。

*反归一化*：如果模型输出 [-1, 1] 区间的值，你需要转换回 [0, 255] 才能得到图像：`pixel_int = (pixel_float + 1) * 127.5`。

*裁剪*：确保数值在有效范围内。像素值应该是 0-255，音频采样应该在 [-1, 1]，等等。裁剪可避免超出范围的值带来瑕疵。

*格式转换*：从模型的输出格式转换成你应用需要的格式。也许模型输出的是平面式 RGB（先所有红色，再所有绿色，再所有蓝色），而你需要交错式 RGB（RGBRGBRGB…）。

==== 后处理发生在哪里：CPU 与 GPU

和预处理一样，后处理传统上也在 CPU 上完成。求最大值、施加 NMS、提取轮廓这类操作很适合 CPU 执行，也有成熟的库实现。

但在高吞吐场景下，GPU 后处理能帮上忙。如果你对 32 张图像的批次做推理，每张产生 200 个检测结果，那就是 6400 个框要处理。在 GPU 上做 NMS 可能比把这么多数据传输到 CPU、处理完再传回结果更快。

取舍与预处理相同：CPU 更简单，能复用现有库；GPU 在大规模处理时更快，但需要自己实现。

=== 阶段 5：输出返回你的应用

最后，处理好的结果回到你的应用。这可能是一个简单的标签（「金毛寻回犬」）、一组带位置的检测对象、一句生成的文本，或者模型产出的任何其他输出。

你的应用按需使用这些输出：展示给用户、驱动游戏逻辑决策、触发动作，或送进另一个系统。推理管线到此完成。

== 把神经网络看作计算操作

现在我们换个视角，从 GPU 编程的角度思考神经网络。这个心智模型对用 Vulkan 实现推理至关重要。

=== 张量：数据结构

神经网络里的一切都作用于*张量*——多维数字数组。灰度图像是二维张量（高 × 宽），彩色图像是三维张量（高 × 宽 × 通道），一批图像是四维张量（批 × 高 × 宽 × 通道）。

从 Vulkan 的角度看，张量不过是 GPU 内存里的缓冲区。一个 224×224×3 的图像张量就是一个装着 224 × 224 × 3 = 150,528 个浮点数的缓冲区。张量的「形状」（224, 224, 3）是元数据，告诉我们要如何把这个线性缓冲区解释成多维结构。

理解张量形状以及它们如何逐层变换至关重要。如果一个卷积层接受 224×224×3 的输入、产生 112×112×64 的输出，你需要分配足够容纳 112 × 112 × 64 = 802,816 个浮点数的缓冲区。你必须知道这些形状，才能正确分配内存。

=== 层：操作

神经网络中的每一层都是对张量的一次特定数学运算。我们来看看最常见的类型，以及它们对 GPU 实现意味着什么。

*稠密（全连接）层*执行矩阵乘法。如果你的输入是长度为 N 的向量，该层有 M 个输出，那么你是用 M×N 的权重矩阵乘以 N 维输入向量，再加上 M 维偏置向量。这是经典的矩阵-向量乘法，GPU 处理起来非常高效。挑战在于大层（比如 4096 个输入、4096 个输出）要乘一个 4096×4096 的矩阵，也就是 1600 万次乘加运算。有效并行化是性能的关键。

*卷积层*用一个小的滤波器（通常是 3×3 或 5×5）在输入上滑动，在每个位置计算加权和。配上多个输入通道和多个输出滤波器，计算量就很大。对一张 112×112 的图像做 3×3 卷积、64 个输入通道、128 个输出滤波器，大约要做 112 × 112 × 64 × 128 × 9 = 11 亿次乘加运算。好消息是？这些运算高度并行——每个输出位置都可以独立计算。

*激活函数*施加逐元素非线性。ReLU 很简单：`output = max(0, input)`。Sigmoid 需要算指数：`output = 1 / (1 + exp(-input))`。这些是易并行的——每个元素相互独立——但有些激活函数（如 sigmoid）计算代价较高。

*池化层*通过在小区域上取最大值或平均值来降采样。2×2 窗口的最大池化取每个 2×2 块的最大值，把 112×112 的图像缩到 56×56。这既简单又并行，但索引必须小心，确保读到正确的输入位置。

*归一化层*（如批归一化）沿某个维度统计均值和方差，再用这些统计量归一化数值。这要棘手一些，因为计算统计量需要规约操作——你需要在许多元素上求和，这就涉及同步。但一旦拿到统计量，施加归一化就很直接。

=== 执行模型

从 Vulkan 的角度看，运行推理就是一连串带相应同步的计算着色器派发。我们来拆解一下这在实践中意味着什么。

==== 基本流程

你先把输入张量上传到 GPU 内存。这是一次主机到设备的传输——把数据从 CPU 内存复制到 GPU 内存。对一张 224×224×3 的图像（150,528 个 float，约 600KB）来说，在现代系统上这次传输很快，但它仍然是你想尽量减小的一项开销。

然后你派发第一层的计算着色器。这个着色器读取输入张量和该层的权重（权重早已驻留在 GPU 上，在启动时加载一次），执行计算，写入中间张量。这个中间张量留在 GPU 内存里——不会传回 CPU。

你插入一个内存屏障，确保写入完成并对后续操作可见。这对正确性至关重要——没有它，下一层可能在上一层写完之前就开始读取，导致竞态条件和错误结果。

接着派发第二层的着色器，它读取那个中间张量，写入另一个张量。如此逐层进行，直到抵达最终输出。每一层是一次计算着色器派发，每个中间结果都是 GPU 内存中的缓冲区，屏障保证正确的顺序。

最后，你把输出张量读回 CPU 内存。这是一次设备到主机的传输。对一个 1000 类的分类模型来说，只有 1000 个 float（约 4KB）——比输入小得多。

==== 内存管理：规模带来的挑战

问题在这里：神经网络很吃内存。我们跟着 ResNet-50 走一遍，看看为什么。

第 1 层（卷积）：输入 224×224×3，输出 112×112×64。那是 150,528 个输入 float 和 802,816 个输出 float。再加上权重：64 个 7×7×3 的滤波器 = 9,408 个权重。合计：这一层约 3.8MB。

第 2 层（卷积）：输入 112×112×64，输出 112×112×64。输入输出各 802,816 个 float，再加权重。又约 3.2MB。

等你深入到第 10 层，累计的中间张量已经达到数十 MB。到第 50 层，就是数百 MB 的量级。

朴素的做法——为每个张量单独分配缓冲区——很快就会耗尽 GPU 内存。典型的移动 GPU 可能只有 2-4GB 内存，而你要和图形渲染、纹理以及其他应用共享这些内存。

==== 内存复用：解决方案

关键洞见是：大多数中间张量的生命周期很短。第 5 层执行完、第 6 层消费掉它的输出之后，第 5 层的输出张量就再也不会被用到了。那块内存可以给第 7 层的输出复用。

这叫*内存池化*或*内存复用*，是在资源受限设备上运行大模型的关键。

算法是这样的：

1. 分析模型图，确定每个张量的生命周期——哪些层产生它、哪些层消费它。
2. 找出生命周期不重叠的张量——它们可以共用同一块内存。
3. 分配一个内存缓冲区池，把张量分配到缓冲区上，使得任意两个生命周期重叠的张量不共用同一块缓冲区。

这本质上是一个图着色问题。实践中，简单的贪心算法效果就不错：按顺序处理各层，对每个输出张量，找到第一个当前未被使用的可用缓冲区。

有了内存复用，ResNet-50 的内存占用从数百 MB 降到数十 MB，降到原来的 1/5 到 1/10。这决定了它是「装不进设备」还是「跑得从容」。

==== 同步：保证正确性

GPU 是高度并行的，但神经网络推理本质上是串行的——每一层都依赖上一层的输出。我们需要同步来强制这种顺序，同时在可能的地方仍然保持并行。

*管线屏障*：Vulkan 中用于计算工作的主要同步原语。管线屏障的意思是「此点之前的所有操作必须完成，之后的操作才能开始」。你在层与层之间插入屏障，确保正确的顺序。

但屏障有代价——它们会串行化执行。如果你在每一次操作之后都插屏障，就是在强迫 GPU 在每次派发之间空等，浪费并行性。

*粒度很重要*：诀窍在于找到合适的粒度。你不需要在每次操作后都加屏障——只有当一次操作的输出变成另一次操作的输入时才需要。如果第 5 层写张量 A、第 6 层读张量 A，两者之间就需要屏障。但如果第 5 层写张量 A、第 7 层写张量 B（两者互不依赖），它们可以并行运行。

现代网络常常有并行分支——ResNet 有跳跃连接，Inception 有多条并行路径。只要在它们汇合时做好同步，这些分支就可以并发执行。

*内存屏障与执行屏障*：Vulkan 区分执行依赖（操作 A 必须在操作 B 开始前完成）和内存依赖（操作 A 的写入必须对操作 B 的读取可见）。两者你都需要。带适当内存屏障的管线屏障能同时保证执行顺序和内存可见性。

==== 工作组大小：在并行度与资源之间平衡

派发计算着色器时，你要指定启动多少个工作组、每个工作组里有多少线程（调用）。这个选择对性能影响很大。

*太小*：如果工作组太小（比如 8 个线程），你就没有利用 GPU 的并行能力。现代 GPU 能同时运行数千个线程，而你只用了其中极小一部分。

*太大*：如果工作组太大（比如 1024 个线程），可能超出硬件限制或耗尽共享内存。每个工作组都需要资源（寄存器、共享内存），GPU 只能在资源允许的范围内运行相应数量的工作组。

*刚刚好*：典型的工作组大小是 64、128 或 256 个线程。这在并行度（足够多的线程让 GPU 保持忙碌）与资源占用（不至于多到耗尽资源）之间取得平衡。

最优大小取决于着色器的资源用量和具体的 GPU。性能分析必不可少——尝试不同大小并测量性能。

==== 数据布局：内存访问模式很重要

数据在内存中的排布方式会极大影响性能。GPU 有内存层次结构——全局内存（慢但大）、共享内存（快但小）和寄存器（最快但极小）。高效地访问内存至关重要。

*合并访问*：当相邻线程访问相邻内存位置时，GPU 表现最好。如果线程 0 读地址 0，线程 1 读地址 4，线程 2 读地址 8，等等，GPU 就能把这些合并成一次内存事务。如果线程访问随机地址，每次访问都变成单独的事务，性能被拖垮。

*张量布局*：张量元素的存储顺序会影响访问模式。「通道在后」（NHWC：批、高、宽、通道）与「通道在前」（NCHW：批、通道、高、宽）之间，视操作不同，可能有 2 到 3 倍的性能差异。

对卷积来说，通道在前往往更好，因为你在每个空间位置要读取所有通道。对逐元素操作，通道在后可能更好。没有普适答案——取决于你的操作和硬件。

*共享内存*：对复用数据的操作（比如卷积中多个输出位置读取相同的输入值），把数据加载到共享内存能大幅减少全局内存流量。线程协作把一块数据加载进共享内存，同步之后，所有线程都从快速的共享内存读取，而不是从缓慢的全局内存读取。

|研发环境，硬件强劲，没有实时性约束
|生产环境，硬件五花八门，延迟要求严格
|===

对我们的 Vulkan 实现来说，关键结论是简单：我们只实现前向传播。没有梯度，没有反向传播，没有优化器状态。这让任务好管理得多，但仍然需要细致的工程才能达到良好性能。

== 我们要构建什么

基于对推理的这些理解，我们来明确这个教程系列究竟要构建什么。

我们要创建一个基于 Vulkan 的推理引擎，它能加载预训练模型，并在 GPU 上高效运行。这个引擎将：

*加载模型*：从标准格式（ONNX 或 TFLite）加载模型，提取网络结构和已学习权重。

*分配 GPU 内存*：为张量分配 GPU 内存——输入、输出、中间激活值和权重——并用智能的内存复用把占用降到最低。

*实现神经网络操作*：用 Vulkan 计算着色器实现卷积、矩阵乘法、激活、池化、归一化以及其他常见层类型。

*执行推理*：按正确顺序派发计算着色器并施加适当的同步，确保数据在网络中正确流动。

*优化性能*：选择高效算法、尽量减少内存带宽占用，并利用 GPU 特有的特性。

我们不是在构建训练系统。我们不实现反向传播或优化器，不处理数据增强或学习率调度。那些都发生在别处，发生在训练阶段。我们只专注于拿一个训练好的模型，尽可能快地运行它。

这种聚焦让任务变得可控。推理比训练简单，但依然需要细致的工程。性能要求很高——实时应用需要毫秒级的预测——而 Vulkan 给了我们满足这些要求的底层控制能力。

== 小结

推理是使用训练好的神经网络对新数据做预测的过程。训练要通过反向传播和优化调整权重，而推理使用固定权重，只执行网络的前向传播。

推理管线由五个阶段组成：输入数据从你的应用到达，预处理把它转换成模型期望的格式，神经网络逐层执行，后处理解读原始输出，最终结果返回你的应用。每个阶段都可以针对性能优化，而 Vulkan 尤其适合神经网络执行阶段。

从 Vulkan 的角度看，神经网络就是一系列作用于张量（存放在 GPU 缓冲区中的多维数组）的计算操作。每一层都是一个计算着色器，它读取输入张量、执行数学运算、写出输出张量。关键挑战——内存管理、同步和性能优化——正是 Vulkan 被设计来处理的事。

理解训练与推理的区别塑造了我们的实现：我们只需要前向传播，可以复用内存存放中间结果，可以专门针对部署而非训练的约束做优化。这种聚焦让构建 Vulkan 推理引擎变得可控，同时仍需要细致的工程才能达到实时性能。

现在我们对推理是什么、它与训练有何不同有了理解，接下来可以探索迁移学习策略，让我们能把已有模型适配到新任务上，而不必从头训练。
