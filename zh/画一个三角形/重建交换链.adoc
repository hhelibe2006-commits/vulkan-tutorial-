:toc:
:toclevels: 3

== 介绍
我们目前的应用程序可以成功绘制三角形，但有些情况它还无法正确处理。窗口表面可能会发生变化，导致交换链不再兼容。造成这种情况的原因之一是窗口大小发生变化。我们需要捕获这些事件并重新创建交换链。

== 重建交换链
创建一个 `recreateSwapChain` 函数，该函数调用 `createSwapChain` 所有依赖于交换链或窗口大小的对象创建函数。
[source,c++]
----
void recreateSwapChain() {
    device.waitIdle();

    createSwapChain();
    createImageViews();
}
----
我们首先调用 `vk::raii::Device::waitIdle`。

为了确保在重新创建这些对象之前清理掉旧版本，我们应该将部分清理代码移到一个单独的函数中，以便从 `recreateSwapChain` 函数中调用它。我们称它为 `cleanupSwapChain`：
[source,c++]
----
void cleanupSwapChain() {

}

void recreateSwapChain() {
    device.waitIdle();

    cleanupSwapChain();

    createSwapChain();
    createImageViews();
}
----
我们将把所有在交换链刷新过程中重新创建的对象的清理代码从 `cleanup` 移到 `cleanupSwapChain`：
[source,c++]
----
void cleanupSwapChain() {
    swapChainImageViews.clear();
    swapChain = nullptr;
}

void cleanup() {
    cleanupSwapChain();

    glfwDestroyWindow(window);
    glfwTerminate();
}
----
请注意，在 `chooseSwapExtent` 我们已经查询了新的窗口分辨率，以确保交换链图像具有（新的）正确大小，因此无需修改 `chooseSwapExtent` （记住，在创建交换链时，我们已经必须使用 `glfwGetFramebufferSize` 来获取表面的像素分辨率）。

重建交换链就这么简单！但是，这种方法的缺点是，我们需要在创建新的交换链之前停止所有渲染操作。即使旧交换链 `oldSwapchain` 中的图像绘制命令仍在执行，也可以创建新的交换链。你需要将之前的交换链传递给结构体 `vk::SwapchainCreateInfoKHR` 中的相应字段，并在使用完毕后立即销毁旧的交换链。

== 次优或过时地交换链
现在我们只需要确定何时需要重建交换链，并调用我们的 `recreateSwapChain` 函数。幸运的是，Vulkan 通常会在渲染过程中直接告知我们交换链不再适用。`vk::raii::SwapchainKHR::acquireNextImage` 函数 `vk::raii::Queue::presentKHR` 可以返回以下特殊值来指示这一点。

* `vk::Result::eErrorOutOfDateKHR`：交换链与表面不兼容，无法再用于渲染。这种情况通常发生在窗口大小调整之后。请注意，“vk::Result::eErrorOutOfDateKHR”实际上是一个错误代码，默认情况下会触发异常。通过定义“VULKAN_HPP_HANDLE_ERROR_OUT_OF_DATE_AS_SUCCESS”，该错误代码将被视为成功代码，因此可以由“vk::raii::SwapchainKHR::acquireNextImage”和“vk::raii::Queue::presentKHR”返回。
* `vk::Result::eSuboptimalKHR`：交换链仍然可以用于成功地呈现到表面，但表面属性不再完全匹配。
[source,c++]
----
auto [result, imageIndex] = swapChain.acquireNextImage(UINT32_MAX, *presentCompleteSemaphores[frameIndex], nullptr);

if (result == vk::Result::eErrorOutOfDateKHR) {
    recreateSwapChain();
    return;
}
if (result != vk::Result::eSuccess
    && result != vk::Result::eSuboptimalKHR) {
    assert(result == vk::Result::eTimeout
        || result == vk::Result::eNotReady);
    throw std::runtime_error("获取交换链图像失败");
}
----
如果在尝试获取图像时发现交换链已过期，则无法再向其呈现图像。因此，我们应该立即重新创建交换链，并在下次 `drawFrame` 调用中重试。

如果交换链处于次优状态，你也可以决定这样做，但我选择在这种情况下继续执行，因为我们已经获取了一张图像。`vk::Result::eSuccess` 和 `vk::Result::eSuboptimalKHR` 都被视为“成功”返回码。

`vk::raii::Queue::presentKHR` 函数返回相同的值，含义也相同。在这种情况下，如果交换链处于次优状态，我们也会重建交换链，因为我们希望获得尽可能最佳的结果。
[source,c++]
----
const vk::PresentInfoKHR presentInfoKHR{
    .waitSemaphoreCount = 1,
    .pWaitSemaphores = &*renderFinishedSemaphores[imageIndex],
    .swapchainCount = 1,
    .pSwapchains = &*swapChain,
    .pImageIndices = &imageIndex
};
result = queue.presentKHR(presentInfoKHR);
if (result == vk::Result::eSuboptimalKHR
    || result == vk::Result::eErrorOutOfDateKHR) {
    recreateSwapChain();
}else {
    assert(result == vk::Result::eSuccess);
}
----
== 解决死锁
回想xref:渲染/多帧并行处理.adoc[上一章]的内容，函数开始时 `drawFrame` 会等待一段时间，然后立即重置当前帧的栅栏：
[source,c++]
----
auto fenceResult = device.waitForFences(*inFlightFences[frameIndex], vk::True, UINT64_MAX);
if (fenceResult != vk::Result::eSuccess) {
  throw std::runtime_error("未等到栅栏!");
}

device.resetFences(*inFlightFences[frameIndex]);
----
如果我们保持这种结构，并尝试运行现在可以从上述获取图像步骤提前返回的代码 `drawFrame`，则可能会遇到死锁。调试代码后，我们发现应用程序到达了 `vk::raii::Device::waitForFences` 后面的某个帧，但从未继续执行。这是因为当 `vk::raii::SwapchainKHR::acquireNextImage` 返回时 `vk::Result::eErrorOutOfDateKHR`，我们会重新创建交换链，然后从返回 `drawFrame` ——但当前帧的栅栏在之前就已经被重置了，那时我们还不知道是否实际会提交任何工作。由于我们立即返回 `vk::raii::Device::waitForFences`，因此没有工作提交执行，栅栏永远不会被触发，导致下次等待同一个栅栏对象时程序永远停止运行。

幸好有一个简单的解决方法 `vk::raii::Device::waitForFences` 。延迟重置围栏，直到我们确定要提交包含该围栏的工作成果之后。这样，即使我们提前返回，围栏仍然处于激活状态，下次使用同一个围栏对象时也不会发生死锁。
现在 `drawFrame` 开头应该看起来像这样：
[source,c++]
----
auto fenceResult = device.waitForFences(*inFlightFences[frameIndex], vk::True, UINT64_MAX);
if (fenceResult != vk::Result::eSuccess) {
    throw std::runtime_error("未等到栅栏！");
}

auto [result, imageIndex] = swapChain.acquireNextImage(UINT64_MAX, *presentCompleteSemaphores[frameIndex], nullptr);

if (result == vk::Result::eErrorOutOfDateKHR) {
    recreateSwapChain();
    return;
}
if (result != vk::Result::eSuccess && result != vk::Result::eSuboptimalKHR) {
    assert(result == vk::Result::eTimeout || result == vk::Result::eNotReady);
    throw std::runtime_error("获取交换链镜像失败！");
}

device.resetFences(*inFlightFences[frameIndex]);
----
== 显式处理调整大小
虽然许多驱动程序和平台会在窗口大小调整后自动触发 `vk::Result::eErrorOutOfDateKHR`，但这并不能保证一定会发生。因此，我们将添加一些额外的代码来显式处理窗口大小调整。首先，添加一个新的成员变量，用于标记窗口大小调整是否已发生：
[source,c++]
----
bool framebufferResized = false;
----
然后应该修改 `drawFrame` 函数，使其也检查此标志：
[source,c++]
----
if (result == vk::Result::eErrorOutOfDateKHR
    || result == vk::Result::eSuboptimalKHR
    || framebufferResized) {
    framebufferResized = false;
    recreateSwapChain();
}
else {
    ...
}
----
`vk::raii::Queue::presentKHR` 很重要，可以确保信号量处于一致状态，否则已发出信号的信号量可能永远无法被正确等待。在前面的章节中，我们禁用了窗口大小调整，要启用此功能，我们将提示设置 `GLFW_RESIZABLE` 为 `true`。现在，为了实际检测窗口大小调整，我们可以使用GLFW框架中的函数 `glfwSetFramebufferSizeCallback` 来设置回调：
[source,c++]
----
void initWindow() {
    glfwInit();

    glfwWindowHint(GLFW_CLIENT_API, GLFW_NO_API);
    glfwWindowHint(GLFW_RESIZABLE, GLFW_TRUE);

    window = glfwCreateWindow(HIDTH, HEIGHT, "Vulkan", nullptr, nullptr);
    glfwSetFramebufferSizeCallback(window, framebufferResizeCallback);
}

static void framebufferResizeCallback(GLFWwindow* window, int width, int height) {

}
----
我们之所以创建一个 `static` 函数作为回调函数，是因为 GLFW 不知道如何使用 `HelloTriangleApplication` 指向 `this` 的正确指针来正确调用成员函数。

但是，我们在回调函数中确实得到了一个引用 `GLFWwindow`，并且还有一个 GLFW 函数 `glfwSetWindowUserPointer` 允许你将任意指针存储在其中：
[source,c++]
----
window = glfwCreateWindow(WIDTH, HEIGHT, "Vulkan", nullptr, nullptr);
glfwSetWindowUserPointer(window, this);
glfwSetFramebufferSizeCallback(window, framebufferResizeCallback);
----
现在可以从回调函数 `glfwGetWindowUserPointer` 中获取此值，以便正确设置标志：
[source,c++]
----
static void framebufferResizeCallback(GLFWwindow* window, int width, int height) {
    auto app = reinterpret_cast<HelloTriangleApplication*>(glfwGetWindowUserPointer(window));
    app->framebufferResized = true;
}
----
现在尝试运行程序并调整窗口大小，看看帧缓冲区是否真的随窗口正确调整大小。

== 处理最小化
还有一种情况会导致交换链失效，那就是一种特殊的窗口大小调整：窗口最小化。这种情况很特殊，因为它会导致帧缓冲区大小为0。在本教程中，我们将通过扩展函数 `recreateSwapChain` 来解决这个问题，暂停直到窗口再次位于前台：
[source,c++]
----
void recreateSwapChain() {
    int width = 0, height = 0;
    glfwGetFramebufferSize(window, &width, &height);
    while ((width == 0
        || height == 0)
        && !glfwWindowShouldClose(window)) {
        glfwGetFramebufferSize(window, &width, &height);
        glfwWaitEvents();
    }
    if (glfwWindowShouldClose(window)) {
        return;
    }

    device.waitIdle();

    ...
}
----
初始调用 `glfwGetFramebufferSize` 处理的是窗口大小已正确且 `glfwWaitEvents` 无需等待的情况。该 `glfwWindowShouldClose` 检查处理的是窗口在最小化状态下关闭的情况——如果没有此检查，循环将无限循环等待帧缓冲区大小，而该大小永远不会再次变为非零值。
