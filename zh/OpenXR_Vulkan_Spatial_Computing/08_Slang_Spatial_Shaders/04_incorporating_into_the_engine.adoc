= 集成到引擎中

在 `simple_game_engine` 中采用多视图，让我们可以单趟渲染两只眼睛，显著降低 CPU 的绘制调用开销。这一实现的示例见 link:../../../attachments/openxr_engine/shaders/pbr.slang[pbr.slang] 与 link:../../../attachments/openxr_engine/renderer_pipelines.cpp[renderer_pipelines.cpp]。

== 更新着色器加载

在 `renderer_resources.cpp` 中，我们需要修改管线的创建代码以启用多视图。做法是添加一个设置了 `viewMask` 的 `vk::PipelineRenderingCreateInfo`。

[source,cpp]
----
// renderer_resources.cpp
bool Renderer::createGraphicsPipeline() {
    // ...
    vk::PipelineRenderingCreateInfo renderingInfo{
        .viewMask = xrMode ? 0x3 : 0x0, // 0x3 enables views 0 and 1
        .colorAttachmentCount = 1,
        .pColorAttachmentFormats = &swapChainImageFormat
    };

    pipelineInfo.pNext = &renderingInfo;
    // ...
}
----

== 适配 Slang 着色器

我们的 Slang 着色器（比如 `pbr.slang`）必须改写以处理 `SV_ViewID` 语义。这样着色器就能区分左眼和右眼。

首先，我们修改 `common_types.slang`，在 `UniformBufferObject` 中加入矩阵数组：

[source,slang]
----
// common_types.slang
struct UniformBufferObject {
    // NEW: Replace the single viewProjection matrix with an array
    // This supports Stereo (N=2), Quad-Views (N=4), and beyond
    float4x4 viewProjections[4];
    float4x4 model;
};
----

接着修改 `pbr.slang`：

[source,slang]
----
// pbr.slang
struct VS_Input {
    float3 position : POSITION;
    // ...
};

struct VS_Output {
    float4 position : SV_Position;
    uint viewID : SV_ViewID; // NEW: The hardware-provided view index
    // ...
};

[shader("vertex")]
VS_Output vertexMain(VS_Input input, uint viewID : SV_ViewID) {
    VS_Output output;

    // Select the correct ViewProjection matrix based on the eye index (0 to 3)
    float4x4 vp = ubo.viewProjections[viewID];
    output.position = mul(vp, mul(pushConstants.model, float4(input.position, 1.0)));
    output.viewID = viewID;

    return output;
}
----

== 为什么要做这些改动？

通过启用 `viewMask` 并使用 `SV_ViewID`，我们把立体渲染的负担从 CPU 转移到了 GPU。引擎不再循环两次、提交两套命令，而是只提交一套，由硬件的**实例数据步进**（Instance Data Step）或**几何复制**（Geometry Replication）负责扩展成两个视图。这是在 Vulkan 1.3 中实现高性能空间渲染最高效的方式。
