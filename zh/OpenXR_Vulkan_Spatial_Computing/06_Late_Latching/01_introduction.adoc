= 延迟锁存与时间线信号量

在空间计算中，「我以为我的头在这里」与「像素真正画到显示器上」之间的差距，被称为**动作到光子（M2P）**延迟。即便有了上一章探讨的预测式帧循环，仍然存在一段时间窗口：用户可以在我们启动模拟之后、GPU 完成渲染之前移动头部。如果用的是过时的头部位姿，虚拟世界就会感觉在「游移」，或拖在用户真实动作的后面。

**延迟锁存**就是为此而生。我们不再在帧开始时采集一次头部位姿然后处处使用，而是要尽可能晚地「锁存」最新的位姿——理想情况下，就在 GPU 开始执行依赖它的绘制调用之前。

要在 Vulkan 1.3 中做到这一点又不造成大规模 CPU 停顿，我们借助**时间线信号量**。传统上，同步 CPU 与 GPU 需要 `vkDeviceWaitIdle` 这类「重」操作，或者跨复杂帧难以管理的二值信号量。时间线信号量让我们可以创建一个 64 位单调递增计数器，CPU 和 GPU 都能在它上面等待或发出信号。

把统一缓冲区对象（UBO）或推送常量的更新挡在某个时间线信号量值之后，我们就能确保 GPU 只有在 CPU 写完最新的视图矩阵与投影矩阵之后才继续执行绘制调用。这把预测误差降到最低，让虚拟世界牢牢锚定在用户的现实中。

在本章中，我们来看看如何：

1. 用时间线信号量编排 CPU/GPU 握手。
2. 在提交前的「最后一微秒」更新着色器数据。
3. 把这些临门一脚的更新集成到引擎的命令缓冲区流程中。
