= 延迟锁存实现

延迟锁存的效率取决于 CPU 向 GPU 发出信号之前的最后时刻。在我们的引擎中，我们使用持久映射内存和时间线信号量来确保尽可能低的延迟。

== 生态系统视角

本章属于以下类别：**超越 OpenXR 标准**。

虽然 OpenXR 负责提供位姿，但「延迟锁存」这项具体的低延迟同步技术是用 Vulkan 的核心同步特性实现的。这是一项强大的优化，你用 Vulkan 来实现它，从而获得比标准集成更好的结果。

== 「最后一秒」的视图预测

延迟锁存的魔力发生在 CPU 给 GPU 下达「放行」指令之前的最后片刻。在我们引擎的主循环中，我们用 `predictedDisplayTime` 调用 `xrLocateSpace`，取得绝对最新的头部位姿。

[source,cpp]
----
// 1. Get the absolute latest head pose from OpenXR
XrSpaceLocation spaceLocation{
    .type = XR_TYPE_SPACE_LOCATION
};
xrLocateSpace(viewSpace, baseSpace, predictedDisplayTime, &spaceLocation);

if (spaceLocation.locationFlags & XR_SPACE_LOCATION_ORIENTATION_VALID_BIT) {
    // 2. Convert to matrix and update persistently mapped memory
    auto latestViewMatrix = convertXrPoseToMatrix(spaceLocation.pose);
    std::memcpy(mappedUboPointer, &latestViewMatrix, sizeof(latestViewMatrix));

    // 3. Flush if memory is not host-coherent using designated initializers
    vk::MappedMemoryRange flushRange{
        .memory = *uboBufferMemory,
        .offset = 0,
        .size = sizeof(latestViewMatrix)
    };
    device.flushMappedMemoryRanges(flushRange);
}

// 4. Signal the timeline semaphore to unblock the GPU
vk::SemaphoreSignalInfo signalInfo{
    .semaphore = *lateLatchingSemaphore,
    .value = nextValue
};
device.signalSemaphore(signalInfo);
----

== 持久映射：效率的硬性要求

要让延迟锁存生效，我们承受不起每帧调用 `vkMapMemory` 和 `vkUnmapMemory` 的开销。我们在初始化时把 Vulkan 缓冲区映射一次，并在应用程序的整个生命周期内保留 CPU 侧的指针。这样，我们就能在时间紧迫的更新窗口内发挥直接 `memcpy` 的原始性能。

在你更新内存的同时，运行时正在刷新其内部的传感器融合模型（以 1000Hz 或更高的频率采样 IMU），以便为预测的显示时间给出最准确的外推。

== 一致性之问：`vkFlushMappedMemoryRanges`

在某些硬件上（尤其是独立的桌面 GPU），CPU 和 GPU 拥有各自独立的缓存。即便我们用 `memcpy` 写入了数据，GPU 仍可能在它的缓存中看到「陈旧」的版本。

如果我们的内存堆没有 `VK_MEMORY_PROPERTY_HOST_COHERENT_BIT` 标志，就必须调用 `vkFlushMappedMemoryRanges`。这会强制 CPU 缓存把数据写回到物理 VRAM，GPU 才能看到它。

== 进阶：推测性渲染与传输队列

Vulkan 让我们能够把后期更新的边界推得更远：

*   **推测性渲染**：你可以用 Vulkan 针对不同的预测位姿录制多个小的「潜在」命令缓冲区，再用时间线信号量在最后一刻选出正确的那一个——即使 CPU 的更新稍有延迟，也能保证零延迟的对齐。
*   **异步传输队列**：延迟锁存严格来说只适用于变换矩阵这类极小的数据。如果你需要更新更大的数据集（比如动画的骨骼变换），可以用 Vulkan 的**异步传输队列**在渲染工作之外并行流式传输这些数据，绕过 OpenXR 主循环的单线程瓶颈。

== 延迟锁存的局限

这项技术对头部位姿或手部追踪数据这类「快速变化」的数据最为有效。

*   **数据规模**：让延迟锁存的更新保持小规模（通常只有几个矩阵）。
*   **时序**：如果更新耗时过长，GPU 会在等待信号量时闲置，从而拉低整体帧率。
