= 动作空间与输入到管线的流程

在传统的 PC 或移动游戏中，我们常常把输入看作原始物理设备的问题：「A 键被按下了吗？」或者「鼠标的位移是多少？」然而在空间计算中，这套模型并不成立。VR 与 AR 控制器的种类繁多——从标准游戏手柄和 6DoF 手部控制器，到手部追踪和眼动追踪——这意味着我们的引擎永远不该关心用户按下的是*哪个*具体按键。

于是 OpenXR 改用了**基于动作的输入系统**。这层抽象让我们可以定义希望用户*做什么*（比如「抓取」「传送」「菜单」），之后再把这些动作映射到各种硬件配置上。这保证了引擎的前瞻性，兼容当前以及未来的所有设备。

但在空间计算中，输入不只是按键，它还关乎**位姿动作**。当用户移动手部时，我们得到的不只是一个按键事件，而是一整个空间变换——3D 空间中的一个位置和一个朝向。这些动作在**空间**中追踪，前面我们已经简单提到过。

本章我们将探讨：
1. 如何定义 OpenXR 动作，并把它们映射到物理控制器配置上。
2. **动作空间**的概念，它在输入与渲染管线之间架起桥梁。
3. 如何把原始的 XrSpace 位姿转换成 4x4 变换矩阵，供 Vulkan 着色器用于交互。

到本节结束时，我们将拥有一个健壮的系统，能以清晰、模块化且高性能的方式同时处理数字输入（按键点击）与空间输入（手部位置）。
