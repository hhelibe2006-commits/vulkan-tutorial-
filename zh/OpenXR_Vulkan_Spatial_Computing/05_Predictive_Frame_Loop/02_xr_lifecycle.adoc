= XR 生命周期

把引擎主循环迁移到 OpenXR 生命周期涉及三个主要函数：`xrWaitFrame`、`xrBeginFrame` 和 `xrEndFrame`。这几个函数充当空间应用的「心跳」，取代了标准的无节流循环或基于 `glfwPollEvents` 的旧式节拍。

== 生态视角

本章属于类别：**使用 Vulkan 与 OpenXR 运行时**。

要让光子与动作对齐，把引擎主循环与 OpenXR 生命周期同步是硬性要求。你必须使用运行时提供的预测显示时刻，才能获得流畅稳定的体验。

== 时间悖论：渲染未来

要理解 XR 生命周期，你必须先接受一个基本事实：**你始终在渲染一个尚未发生的未来。**

在桌面游戏里，你渲染的是「现在」正在发生的事。而在 XR 中，由于录制命令、提交给 GPU 并真正点亮显示器像素都需要时间，等用户看到时，「现在」早已变成过去。如果我们渲染「当前」的头部位姿，世界看起来就会「游移」，或滞后于用户的头部运动。

XR 生命周期正是通过提供**预测显示时刻**来解决这个问题的。

== 1. `xrWaitFrame`：节拍心跳

`xrWaitFrame` 函数是引擎的主要同步点。调用它时，运行时可能会阻塞我们的执行，以保持与头显刷新率（例如 90Hz）同步。

[source,cpp]
----
// Sync with the runtime heartbeat and retrieve the predicted display time
XrFrameState frameState{XR_TYPE_FRAME_STATE};
XrFrameWaitInfo frameWaitInfo{
    .type = XR_TYPE_FRAME_WAIT_INFO
};
xrWaitFrame(xrSession, &frameWaitInfo, &frameState);
----

*   **预测**：`frameState` 里含有 `predictedDisplayTime`。这精确到纳秒，指出我们即将渲染的像素真正显示在头显屏幕上的时刻。
*   **要不要渲染？**：`frameState.shouldRender` 告诉我们运行时是否真的需要一帧。如果头显已摘下或用户待在系统菜单里，我们仍会「等待」，但可以跳过「渲染」工作以省电。

== 2. `xrBeginFrame`：打开窗口

等待满足之后，我们调用 `xrBeginFrame`。这标志着本帧 GPU 工作的开始。

[source,cpp]
----
XrFrameBeginInfo frameBeginInfo{
    .type = XR_TYPE_FRAME_BEGIN_INFO
};
xrBeginFrame(xrSession, &frameBeginInfo);
----

重要的是让 `xrWaitFrame` 与 `xrBeginFrame` 之间的间隔尽可能短，因为我们要在这段时间里完成模拟更新和视图预测。

== 3. `xrEndFrame`：提交给合成器

最后一步是 `xrEndFrame`，它相当于空间世界里的 `vkQueuePresentKHR`。

[source,cpp]
----
XrFrameEndInfo frameEndInfo{
    .type = XR_TYPE_FRAME_END_INFO,
    .displayTime = frameState.predictedDisplayTime,
    .environmentBlendMode = chosenBlendMode,
    .layerCount = 1,
    .layers = &layerPtr
};
xrEndFrame(xrSession, &frameEndInfo);
----

`xrEndFrame` 并不是简单地「呈现」一张图像，而是接收一个**合成层**数组。运行时的合成器会在最后一微秒把这些层叠加起来；如果你渲染完成后用户头部又动了，它甚至可以执行**晚期重投影（LSR）**来「微调」你的最终图像。

== 进阶：子帧工作负载与延迟监测

OpenXR 负责帧节拍，而 Vulkan 允许你实现更细粒度的控制：

*   **协调子帧工作负载**：你可以用 Vulkan 的**时间线信号量**实现与主 XR 生命周期异步运行的工作负载。例如，在调用 `xrWaitFrame` 之前先启动一趟复杂的可见性计算或光照烘焙计算通道，让 CPU 等待心跳时 GPU 依然忙碌。
*   **预测 GPU 侧延迟**：运行时提供了显示时刻，但你也可以用 Vulkan 的**查询池**测量自己 GPU 侧的延迟。有了这些数据，你就能动态调整引擎内部的预测偏移，获得比运行时通用预测更紧密的对齐。

== 引擎循环小结

我们引擎的主循环现在遵循这样精确的节奏：

1.  **轮询事件**：检查系统消息（例如「头显已连接」）。
2.  **等待**：与运行时心跳同步，取得未来的 `displayTime`。
3.  **开始**：启动本帧的工作。
4.  **渲染**：用未来时刻预测位姿，录制 Vulkan 命令并提交。
5.  **结束**：把已完成（或已排队）的层交回运行时用于显示。
