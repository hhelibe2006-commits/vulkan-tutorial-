= 预测式帧循环与时间计算

在传统的桌面应用中，引擎的主循环通常由简单的垂直同步（**VSync**）控制。我们尽可能快地渲染，显示器则在扫描线允许时把结果显示出来。然而在空间计算中，这种「渲染并显示」的模型不够用。如果用户在你开始渲染到光子抵达视网膜之间哪怕只轻微动了动头，场景看起来就会游移或滞后，立刻带来不适甚至晕动症。

为了解决这个问题，OpenXR 采用**预测式帧循环**。我们渲染的不再是世界的*当前*状态，而是显示器真正点亮那一刻世界*将会*是什么样子。

== 空间计算的节奏

OpenXR 帧循环是引擎与 XR 运行时之间的一场对话。它要决定的不仅是何时绘制，更是如何预测未来。这场对话建立在三个支柱之上：

1.  **严格节拍**：运行时通过 `xrWaitFrame` 规定应用精确的心跳。这不仅是帧率限制，更是一个同步点，让引擎与显示器真实的刷新周期对齐。
2.  **预测显示时刻**：我们处理的每一帧都带有一个 `predictedDisplayTime`。这是引擎中最重要的数字。它精确告诉我们用户将在何时看到我们正在构建的这一帧。
3.  **模拟对齐**：我们必须用这个预测时刻来推进物理、动画，以及最关键的头部追踪。我们不问头*现在*在哪，而是问在 `predictedDisplayTime` 时头*将在*哪。

== 为什么时间计算很重要

在本章中，我们会把引擎的主循环从旧的 `glfwWindowShouldClose` 逻辑迁移到 OpenXR 帧生命周期。我们将学会如何：

-   让 CPU 与 GPU 的工作与 XR 运行时的心跳同步。
-   利用预测的时间数据计算出准确的视图矩阵与投影矩阵。
-   理解「游移」效应，以及预测性计算如何消除它。

到本章结束时，你的引擎不再是对用户动作做出「反应」，而是「预判」它，从而提供高质量空间计算所必备的那种流畅、低延迟的体验。
