= OpenXR 与 Vulkan 1.3 空间计算：简介

欢迎来到空间计算的前沿。在本教程系列中，我们要弥合传统 2D 引擎架构与虚拟现实（VR）、增强现实（AR）、混合现实（MR）——这三者统称 XR——所提出的沉浸式、低延迟要求之间的鸿沟。

== 前置条件

在开始本教程之前，你应当对 Vulkan API 和引擎架构都有扎实的基础。具体来说，我们假设你已完成：

1.  **xref:00_Introduction.adoc[Khronos Vulkan^®^ 教程]**：你应当熟悉 Vulkan 的核心概念，包括实例创建、物理设备、逻辑设备以及基本的图形管线。
2.  **xref:Building_a_Simple_Engine/introduction.adoc[构建简易引擎：简介]**：本系列直接建立在引擎教程所确立的代码与架构模式之上。我们将以 `Simple Engine` 代码库作为起点。
3.  **现代 C{pp} 与 RAII**：整个系列中我们都会使用 `vulkan-hpp` 与 RAII（资源获取即初始化）。你应当熟悉这些模式，才能跟上 C{pp} 集成部分。

== OpenXR 生态：运行时与加载器

在深入代码之前，先理解让 OpenXR 运转起来的两个核心组件很重要：**加载器（Loader）**与**运行时（Runtime）**。

1.  **OpenXR 加载器**：这是一个小巧的、厂商中立的库，你的应用链接它。它的主要职责是充当交通警察。引擎启动时，加载器会查看系统注册表或环境变量，找到当前激活的 XR 运行时，并把你所有的 API 调用重定向过去。
2.  **OpenXR 运行时**：这是硬件厂商（例如 Meta、Valve、Microsoft，或开源的 Monado 项目）提供的苦力。运行时包含 OpenXR 规范的实际实现，包括摄像头、显示器和追踪传感器的驱动。

要跟随本教程，你需要在开发机上搭好一个兼容 OpenXR 的环境。这通常包括安装 SDK 并确保有一个运行时处于激活状态。

== 为什么用 OpenXR？

在 XR 的早期，开发者不得不为市面上每一款头显编写定制的后端。OpenXR 改变了这一切：它提供一个跨平台的高性能 API，让单个应用就能跑在从 Meta Quest 到 Valve Index，再到 Microsoft HoloLens 的各种设备上。

但 OpenXR 并不只是一层包装。它是一台精密的状态机，负责管理硬件位姿、预测式帧时序，以及由 XR 运行时自己拥有的专用交换链。要用好它，我们必须重新思考引擎如何处理主循环、内存与同步。

== Vulkan 1.3 的优势

Vulkan 1.3 带来了若干关键特性，对空间计算尤为强大：

* **时间线信号量**：引擎与 XR 合成器之间所需的复杂跨进程同步离不开它。
* **动态渲染**：为立体视图提供了灵活轻量的渲染路径，避开传统渲染通道的僵硬状态。
* **同步 2**：简化低延迟的延迟锁存所需的属主转移与屏障。
* **维护性扩展**：让你更好地控制跨硬件边界的内存与资源可见性。

== 我们将构建什么

在整个系列中，我们将覆盖 XR 帧的完整生命周期：

1.  **握手**：用运行时强制的物理设备与必需扩展，把 OpenXR 连接到我们的 Vulkan 上下文。
2.  **资源管理**：把运行时拥有的图像包装进基于 RAII 的引擎抽象。
3.  **预测式循环**：掌握帧时序，确保用户看到的画面与显示瞬间头部所在的位置完全一致。
4.  **空间着色器**：用 Slang 编写高效的多视图与注视点渲染着色器。
5.  **高级感知**：导入环境网格，并用 ML 推理细化空间数据。

学完本教程，你得到的不仅是一个能跑的 XR 应用，还会深入理解在现代 Vulkan 生态中实现高性能空间计算所需的架构模式。
