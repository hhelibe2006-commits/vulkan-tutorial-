= CAVE 架构与多 GPU 同步：简介

到目前为止，我们的关注点大多是头戴式显示器（HMD），但空间计算同样涵盖 **CAVE**（Cave Automatic Virtual Environment，洞穴式自动虚拟环境）这样的大规模环境。CAVE 是一个房间，其墙壁、地板、有时还有天花板都是高分辨率投影表面。用户通常戴着轻量的快门眼镜，并受到一套相机系统的追踪，从而形成一个共享的、沉浸式的 3D 空间。

为 CAVE 设计引擎，与为单 GPU 头显设计引擎有本质区别。要以 120Hz 驱动六台或更多 4K 投影仪，我们往往需要由多台强力工作站组成的**网络集群**，每台工作站配备一块或多块高端 GPU。这就带来了巨大的同步挑战：每一帧都必须在完全相同的微秒内显示在所有屏幕上，否则房间的转角处就会出现「撕裂」。

在本章中，我们将深入探讨房间级空间技术所需的工程实现：

1.  **基于投影仪的空间技术**：理解 CAVE 的几何结构，以及如何设计引擎来处理多个非标准投影表面。
2.  **硬件同步**：利用 **VK_NV_present_barrier** 扩展与**交换组**，确保跨网络集群节点达到帧级精确的同步。
3.  **分布式渲染**：设计一种数据并行架构，让集群中的每个节点渲染 3D 世界中属于自己的那一部分，同时与主仿真保持步调一致。

== 房间级空间技术的挑战

在 HMD 中，屏幕物理上固定在你头上。而在 CAVE 中，屏幕就是墙壁。这意味着当你在房间里走动时，每个投影表面的**不对称视锥**都必须根据被追踪的眼睛位置实时重新计算。

此外，由于图像是由多台投影仪拼接而成的，我们必须处理**几何校正**与**边缘融合**——这些概念我们将在下一章探讨——以确保虚拟世界绕过房间的物理转角时看起来严丝合缝。

== 同步集群

CAVE 工程的「圣杯」是 **Genlock**（Generator Lock，同步锁相）与 **Swaplock**（交换锁定）。Genlock 确保每块 GPU 的视频信号在完全相同的时间点送达投影仪。Swaplock 则确保交换前台与后台缓冲区的命令在整个集群中同时发生。

没有这些硬件层面的保证，CAVE 的「沉浸感」很快就会被抖动与视觉上的不连续破坏。我们将看看 Vulkan 1.3 的特性与专门的硬件扩展如何让我们达到这种精度。

到本章结束时，你将理解如何把空间引擎从单用户头显扩展到多节点的房间级沉浸式环境。
