= GPU 上的高级数据结构

== 简介

在本教程的前半部分，我们关注的是如何执行计算派发，以及如何管理内存。我们主要使用线性数组（缓冲区）和二维/三维网格（纹理）这类简单数据结构。虽然它们是 GPU 编程的看家本领，但许多现实问题需要更复杂的组织方式。

在本章中，我们将从「数据并行」的数组转向「驻留 GPU」的数据结构。我们会探讨如何完全在设备上构建和遍历诸如**树（BVH/八叉树）**（BVH 表示包围盒，八叉树用于三维空间划分）、**链表**和**工作队列**这样的复杂结构。

== 把数据结构搬到 GPU 上

传统做法是在 CPU 上构建复杂的数据结构，再把它们「拍平」成数组供 GPU 读取。这种做法虽然可行，却造成了一个巨大的瓶颈：对结构的任何更新都需要一次 CPU 与 GPU 之间的往返。

现代 Vulkan 计算让我们可以把这些结构的*构建*与*管理*搬到 GPU 上，从而消除这个瓶颈。这得益于三项关键技术：

1.  **64 位原子操作**：允许在整个 GPU 范围内线程安全地更新全局计数器与指针。这对**无锁**数据结构至关重要，我们将会详细探讨。
2.  **缓冲区设备地址**：摆脱复杂的描述符集，获得类似指针的原始灵活性，用来构建图状结构。
3.  **子组操作**：用我们在第 4 章学到的波前感知逻辑，通过**合并**（combining）多次操作为一次原子更新，以快得多的速度构建这些结构。

== 为什么这很重要

驻留 GPU 的数据结构是现代高性能渲染与模拟的基础：

*   **光线追踪**：包围体层次结构（BVH）用于快速找出光线可能命中的三角形。
*   **物理与机器人**：八叉树或基于网格的哈希这类空间划分结构用于碰撞检测。
*   **顺序无关透明度（OIT）**：一种无需在 CPU 上预先排序就能渲染透明物体的技术；它用逐像素链表在 GPU 上存储并排序透明片元。
*   **GPU 驱动的管线**：工作队列让 GPU 生成自己的工作，我们将在下一章探讨。

读完本章，你将明白如何不再把 GPU 当作「笨拙的数组处理器」，而是把它当作一个能自主完成复杂数据管理的平台。
