= 间接派发与 GPU 驱动管线

== 简介

在传统的 Vulkan 应用里，CPU 是乐团的「指挥」。它决定要绘制什么、派发多少线程、绑定哪些资源。GPU 只是一个「演奏者」，执行 CPU 交给它的命令。

然而，随着场景变得越来越复杂——包含数以百万计的动态对象与复杂的物理运算——CPU 已经跟不上了。CPU 先算出哪些对象可见、再录制成千上万个命令缓冲区，这部分开销成了主要瓶颈。

本章我们将探索 **GPU 驱动管线**，在这里 GPU 接过了指挥的角色。

== 超越静态派发

静态派发（`vkCmdDispatch`）要求 CPU 确切知道要运行多少个工作组。如果你做的是对象剔除之类的工作，那么在 GPU 完成自己的工作之前，CPU 并不知道有多少对象能通过剔除。

使用**间接派发**（`vkCmdDispatchIndirect`）时，CPU 不提供派发尺寸，而是提供一个**Vulkan 缓冲区**，其中存放着派发参数。于是 GPU 自己就能写入这个缓冲区，实际上等于自己决定需要做多少工作。

== 自主的 GPU

GPU 驱动管线借助下面这些特性把这一点推得更远：

1.  **GPU 侧命令生成**：利用现代引擎特性在 GPU 上构建整条命令链，让它「决定」自己的执行路径。
2.  **多绘制间接（MDI）**：这一特性允许单次计算派发生成数千个绘制调用，从而在没有任何 CPU 侧循环的情况下渲染整个场景。
3.  **可变大小的工作负载**：从粒子系统到高保真剔除，一切都能在没有 CPU 侧干预的情况下处理。

== 为什么这很重要

把「决策」交给 GPU 之后，我们可以：

*   **消除 CPU 瓶颈**：把 CPU 解放出来去做 AI、游戏逻辑和其它任务。
*   **最小化延迟**：消除 GPU 的计算分析与随后的渲染之间的往返延迟。
*   **扩展到数百万**：处理传统 CPU 受限管线无法企及的场景复杂度。

本章我们将学习如何构建这些自主管线，从最基础的构件开始：**间接派发**。
