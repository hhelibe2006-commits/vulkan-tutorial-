= GPU 侧命令生成：自主执行

== 在 GPU 上构建命令链

在典型的 Vulkan 应用里，CPU 会录制一串命令：`vkCmdBindPipeline`、`vkCmdBindDescriptorSets`、`vkCmdDispatch` 等等。这些命令被「烤」进命令缓冲区。

借助 **GPU 侧命令生成**（通常利用引擎内置的间接缓冲区与 BDA），我们可以更进一步。整套命令序列不再由 CPU 决定，GPU 可以自己构建一份它想要执行的「命令」列表。

这是 **GPU 驱动管线**的关键组件。GPU 能分析自身状态，并决定去：

1.  派发一个计算着色器来更新一组物理模拟。
2.  派发另一个计算着色器来构建 BVH。
3.  生成一系列绘制调用，渲染更新后的场景。

== 工作原理：缓冲区优先的做法

在 GPU 驱动管线中，CPU 通常只录制一个「主」计算派发。这次派发遍历你的对象或任务，并写入一系列**间接命令缓冲区**：

*   **派发间接缓冲区**：存放供后续计算着色器使用的 `x, y, z` 参数。
*   **绘制间接缓冲区**：存放供后续渲染使用的 `vertexCount`、`instanceCount` 等。
*   **资源缓冲区**：存放那些着色器和绘制将要使用的原始指针（缓冲区设备地址）。

== 为什么这对性能很重要

当 GPU 自己生成命令时，CPU 完全被排除在循环之外。于是不再需要：

*   **重新录制命令缓冲区**：每帧都不产生 CPU 开销。
*   **CPU 侧剔除**：没有「来回」的数据交换。
*   **同步开销**：同步完全发生在 GPU 的命令流内部。

== 自主的力量

这种自主模型让**单趟渲染**成为可能（在单次 GPU 趟次中完成剔除与绘制）。CPU 不必再等待 GPU 的剔除结果才知道该画什么，GPU 可以在同一个命令流里先剔除对象、再绘制它们。

这是许多现代高端渲染引擎的标准架构。它能扩展到数百万个对象，因为「剔除与绘制」的成本与 CPU 的性能无关。
