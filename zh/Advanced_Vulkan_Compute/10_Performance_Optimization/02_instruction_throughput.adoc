= 分析指令吞吐量：计算受限与内存受限

每个 GPU 内核都有自己的"心跳"——它处理指令和访问内存的速率。理解这个心跳是有效优化的关键。为此，我们需要区分两类主要的瓶颈：**计算受限**与**内存受限**。

== Roofline 模型

一种强大的可视化方法是 **Roofline 模型**。想象一张图：x 轴是**算术强度**（数学运算次数与访问的内存字节数之比），y 轴是**性能**（GFLOPS）。

这个模型的"屋顶"由硬件的峰值理论性能决定。

* 如果你的内核算术强度低（访存多、数学少），它就被困在屋顶的"斜坡"上——属于**内存受限**。
* 如果你的内核算术强度高，它就会撞上屋顶的平坦部分——属于**计算受限**。

== 识别瓶颈

要识别这些瓶颈，你需要借助 NVIDIA Nsight、AMD Radeon GPU Profiler（RGP）或 Intel VTune 等性能分析工具查看**硬件指标**。在移动和嵌入式目标上，你要使用一套不同但类似的工具——Arm Performance Studio（Streamline）、Qualcomm Snapdragon Profiler、Imagination PVRTune，或厂商中立的 Android GPU Inspector——而且必须在*真实设备*上运行，因为桌面 GPU 会误导你对手机行为的判断。移动端的性能分析流程在 xref:Advanced_Vulkan_Compute/12_Mobile_and_Embedded_Compute/03_mobile_optimization.adoc[针对移动 GPU 的优化] 中有详细介绍。

=== 计算受限的内核
**计算受限**的内核，是指硬件的算术单元（**ALU**）被完全占满。这类内核的特征是：

* **ALU 利用率高**：ALU 在大部分时间里都在工作。
* **内存吞吐量低**：内存总线相对空闲。
* **解决办法**：简化数学运算、使用**混合精度**，或者利用**协作矩阵**这类专用单元。

=== 内存受限的内核
**内存受限**的内核，是指 ALU 常常闲置、在等待来自 VRAM 的数据。这类内核表现为：

* **ALU 利用率低**：算术单元"停顿"在等待内存上。
* **VRAM 吞吐量高**：你已经顶到硬件的带宽上限。
* **解决办法**：改善**内存合并**，用**共享内存（LDS）**复用数据，或者用**子组操作**在不触碰 VRAM 的情况下共享数据。

== 理解停顿原因

现代性能分析器能告诉你波前*为什么*停顿。常见原因包括：

* **取指停顿**：硬件取不到下一条指令（在计算中很少见）。
* **执行停顿**：ALU 正忙于一条耗时很长的指令（比如复杂的超越函数）。
* **内存依赖停顿**：最常见的一种——波前正在等待来自 VRAM 的 `load` 完成。

== 延迟隐藏与占用率

正如第 2 章所讨论的，GPU 通过在活跃波前之间切换来隐藏内存延迟。这就是**占用率**如此重要的原因。如果占用率很低，GPU 在等待内存时可能没有足够的"活"可干，导致 ALU 闲置、性能变差。

不过要小心！占用率并非越高越好。如果占用率过高，你可能会加重**缓存争用**：不同的波前不断把彼此的数据从 L1 或 L2 缓存中挤出去。找到占用率的"甜点"是调优过程中的关键一环。

优化是一个迭代过程：先做性能分析，找出瓶颈，实施有针对性的修复，然后再次分析。这样才能最终得到一个真正优化、充分利用 GPU 海量并行潜力的方案。
