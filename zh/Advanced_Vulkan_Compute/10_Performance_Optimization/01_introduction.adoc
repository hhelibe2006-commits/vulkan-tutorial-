= 性能审计与优化

我们已经覆盖了广泛的高级 Vulkan 计算主题——从底层架构与内存模型，到 GPU 驱动管线和异步计算。但每个开发者最终都会面对一个问题："这已经是最快了吗？"回答这个问题靠的不是猜测或直觉，而是一套严谨、有条理的**性能审计（Performance Auditing）**方法。

在 GPU 计算的世界里，一个"快"的内核可能被许多因素拖住。它可能在等内存（**内存受限**），可能被复杂的算术压垮（**计算受限**），也可能正遭受"发散"之苦——**子组**（或 **warp/波前**）中不同的调用被迫走不同的执行路径，硬件不得不把它们的工作串行化。

优化不只是写出"聪明"的代码，而是要理解**瓶颈**在哪里。如果你的内核是内存受限的，多加算术运算既不会让它变慢，也不会让它变快。反过来，如果你的内核是计算受限的，优化访存模式可能也带不来任何明显的收益。

== 走出朴素的优化思路

在 Vulkan 这样的大规模并行环境中谈优化，我们需要一套标准的度量指标和模型来指引方向。本章将介绍：

* **Roofline 模型**：一种基础的分析工具，让我们能直观判断一个内核是受限于 **VRAM**（显存）的峰值带宽，还是受限于 **ALU**（算术逻辑单元）的峰值吞吐量。
* **指令吞吐量分析**：理解单条 **ISA**（指令集架构）指令的开销，以及如何识别双精度浮点、复杂超越函数这类"重"操作。
* **发散审计**：一套找出 **SIMD**（单指令多数据）执行在何处失效、导致部分通道闲置而另一部分在干活的方法。

我们将不再只盯着高层的 Slang 或 GLSL 代码，而是开始思考硬件实际看到的东西。这包括理解 **CU**（计算单元）或 **SM**（流式多处理器）的**占用率**，以及如何减少由内存延迟引起的**管线停顿**。

到本章结束时，你将掌握一套方法，把项目从"能跑起来"推进到"跑得飞快"。

== 本章路线图

1. **指令吞吐量分析**：学习使用 Roofline 模型区分计算受限与内存受限的内核。
2. **发散审计**：可视化并重构发散分支逻辑的技术。
