= 计算架构与执行模型：简介

== 概述

要写出高效的计算内核，你必须看穿「工作组」和「调用」这种抽象的执行模型，理解这些概念如何映射到真实硬件。Vulkan 提供的是跨厂商的 API，但它底下的 AMD、NVIDIA 和 Intel 硬件各有自己处理数据的方式。Arm（Mali/Immortalis）、Qualcomm（Adreno）和 Imagination（PowerVR）的**移动** GPU 也是如此——它们构成了 Vulkan 设备中最大的装机量，其基于瓦片的设计把这些相同的概念映射到非常不同的硅片上，我们在 xref:Advanced_Vulkan_Compute/12_Mobile_and_Embedded_Compute/01_introduction.adoc[移动与嵌入式计算：简介] 中详细讨论。

本章要在你的着色器代码和硅片之间搭一座桥。我们会探讨你在 `vkCmdDispatch` 中定义的三维网格系统，是如何被切分、分割并分配到 GPU 的**计算单元（CU）**或**流式多处理器（SM）**上的。

=== 硬件的行话

正式开讲之前，先统一一下词汇。不同厂商对相同的概念用了不同的名字：

*   **工作组**（Vulkan/OpenCL）通常对应 **线程块**（CUDA）。
*   **调用**（Vulkan）就是 **线程**。
*   **子组**（Vulkan）在 AMD 叫 **波前**，在 NVIDIA 叫 **warp**。在移动端，Arm 也把对应物称为 **warp**，而实际大小差异很大（4–128），必须在运行时查询。
*   **计算单元**（AMD）相当于 NVIDIA 的 **流式多处理器**，也相当于 Arm Mali 或 Qualcomm Adreno 上的**着色器核心**。

理解这些对应关系，能让你无论面向哪种 GPU——桌面*还是*移动——都读得懂硬件相关的文档和性能指南。

== 硬件映射

当你派发一个工作负载时，GPU 的硬件命令处理器会把全局网格拆成一个个工作组。工作组是调度的基本单位。

GPU 执行模型有一条关键规则：**工作组原子性**——一个工作组一旦被分配到某个物理计算单元，它的所有调用都会留在该单元上，直到工作组完成。它们不能被拆到多个单元上。正是这种局部性，才使**共享内存（LDS，本地数据共享）**成为可能：工作组内的所有线程物理上位于同一个硬件块，因此可以共享一块专用的、极快的缓存。

=== 调用与 SIMD

工作组是调度单位，而**调用**是执行的最小单位。不过，GPU 是 **SIMD（单指令多数据）**机器。它们不会逐个执行调用，而是把调用分成一个个小束（子组）。

在这些束里，每个调用在同一时刻执行完全相同的指令，只是数据不同。这对数学运算极其高效，但也带来一个大坑：**分支发散**。如果你的代码里有一个 `if` 语句，一部分线程走左边、另一部分走右边，硬件就必须把*两条*路径都执行一遍，并在每条路径上屏蔽掉不活跃的线程。

== 性能指标

本节我们会重点关注两个关键指标，它们决定了你对硬件的利用程度：

1.  **占用率**：这是「并发度」指标。它表示一个计算单元上驻留的活跃工作组数量相对于理论最大值的比例。高占用率有助于**隐藏延迟**——如果一个束正在等待从缓慢的 VRAM 取数据，调度器可以立刻切换到另一个准备好做运算的束。
2.  **带宽效率**：这是「吞吐量」指标。现代 GPU 的内存带宽非常可观，但糟糕的数据对齐很容易把它浪费掉。我们会看到 Vulkan 1.4 的**标量布局**如何让我们紧密地打包数据，确保着色器真正用上从 VRAM 取回的每一个字节。
