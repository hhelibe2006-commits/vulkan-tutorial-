= 异步计算编排

在前面的章节里，我们主要关注如何让单个内核尽可能快。我们优化了内存访问、利用了子组，甚至在 GPU 上构建了完整的数据结构。但还有更高一层的优化常常被忽视：如何把这些派发与引擎其余的工作负载安排在一起。

现代 GPU 并不是单一的整体处理器，而是由多个能够并行工作的硬件引擎组成的复杂系统。要理解异步计算，首先得理解物理硬件。一块典型的高性能 GPU 有几个专门的引擎：

* **图形引擎**：主引擎，能进行顶点处理、光栅化和片元着色，也能做通用计算。
* **异步计算引擎（ACE）**：专门为计算派发服务的调度器与硬件通路。它们常常能与图形引擎完全并行地运行，使用那些尚未被图形工作负载充分利用的计算单元（CU）或流式多处理器（SM）。
* **传输/拷贝引擎**：专用的 DMA（直接内存访问）引擎，用于在主机内存与设备内存之间搬运数据，不消耗任何计算资源。

Vulkan 通过**队列族**来暴露这些硬件引擎。每个队列族都有一组**能力**（例如 `VK_QUEUE_GRAPHICS_BIT`、`VK_QUEUE_COMPUTE_BIT`、`VK_QUEUE_TRANSFER_BIT`）。主图形队列族通常支持所有功能，而一个「专用计算」或「异步计算」队列族可能*只*支持计算与传输。

通过使用来自这些专门队列族的独立计算队列，我们可以把沉重的计算派发——比如路径追踪降噪、物理模拟或复杂的 AI 寻路——与主图形渲染趟次重叠起来。当图形硬件忙于处理几何体、光栅化三角形时，计算单元可以同时为你的模拟进行运算。

在本章，我们要超越简单的「一个队列包办一切」模型。我们会探索如何用 Vulkan 的 **Synchronization 2**（`VK_KHR_synchronization2`）来编排复杂的并发工作负载，同时不引起**管线停顿**（GPU 空等着某个资源）。我们还会看**队列优先级**，这一特性让我们能告诉硬件哪些任务才是真正的延迟敏感任务，确保后台模拟不会拖慢对时间敏感的物理更新。

编排这些工作负载，要求我们改变对 GPU 时间线的思考方式。它不再只是一条线性的命令序列，而是一条多车道高速公路：不同类型的交通可以以不同的速度行驶，偶尔并线或让行，以保证整体吞吐量最大。
