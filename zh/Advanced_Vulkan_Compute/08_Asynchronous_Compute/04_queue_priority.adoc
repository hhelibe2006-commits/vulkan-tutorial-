= 队列优先级：管理延迟敏感型工作负载

当你面对多个队列时，本质上是在把多条工作流交给 GPU，让它的硬件调度器决定如何安排优先级。默认情况下，调度器尽量做到公平，但在高性能引擎里，「公平」并不总是你想要的。你可能有一个关键的物理更新*必须*在下一帧之前完成，而后台的路径追踪降噪器多花几毫秒也无所谓。

Vulkan 通过**队列优先级**提供了影响这一点的方式。创建逻辑设备（`VkDeviceCreateInfo`）时，你为队列族中的每个队列指定一个 `priority`。该值是 0.0 到 1.0 之间的浮点数，其中 1.0 表示最高优先级。

[source,cpp]
----
// Setting up high-priority compute queues
float priorities[] = { 1.0f, 0.1f }; // High priority for physics, low for denoising
vk::DeviceQueueCreateInfo queueCreateInfo {
    .queueFamilyIndex = computeQueueFamilyIndex,
    .queueCount = 2,
    .pQueuePriorities = priorities
};
----

== 调度器如何使用优先级
要理解一点：队列优先级是**提示**，不是保证。具体行为在很大程度上取决于硬件内部的调度器。大多数现代 GPU 采用两种主要策略之一：

1.  **严格优先级**：只要高优先级队列有任务就绪，调度器总是先取它。这对响应性很好，但如果高优先级队列持续繁忙，就可能导致低优先级任务**饥饿**。
2.  **加权轮询**：调度器按优先级给每个队列分配一定比例的执行时间。例如，优先级 1.0 的队列可能获得两倍于优先级 0.5 队列的「调度槽位」。

高端桌面 GPU 往往具有复杂的硬件，能够**抢占**一个低优先级任务（例如中断一个长时间运行的计算着色器），为高优先级任务腾出空间。然而抢占不是免费的；它涉及保存和恢复 GPU 状态，可能需要几微秒。

== 全局队列优先级
如果你构建的系统里延迟是唯一重要的事——比如 VR（虚拟现实）合成器或 AR（增强现实）空间追踪器——你可能需要更强的控制力。这就是 `VK_EXT_global_priority` 的用武之地。该扩展允许你为队列请求**实时**优先级。

标准队列优先级只在你设备上的各个队列之间相对生效，而全局优先级告诉驱动（以及操作系统）：你的工作负载比同一块 GPU 上运行的其它应用更重要。请谨慎使用，用错了会导致系统其余部分卡顿。

== 避开「单队列陷阱」
一个常见错误是在同一个队列族里创建多个高优先级队列。若这么做，你实际上又回到了「先来先服务」的模型。只有提供清晰、有区分度的优先级，硬件调度器才能发挥作用。

另一个关键考虑是**队列族**（一组能力相似的队列）的选择。有些 Vulkan 实现提供多个队列族，各自能力不同。例如，一个「专用计算」队列族可能拥有专门用于计算派发的硬件，与图形引擎不共享任何资源，因此效率更高，也更不容易造成**管线气泡**（GPU 执行时间线上的空隙）。始终检查 `VkQueueFamilyProperties`，弄清每个队列族能提供什么。

在实践中，管理队列优先级是一门平衡术。用得对，它是强大的工具，能确保引擎保持响应，并让最关键的任务总能以所需的紧迫性得到处理。这种编排正是真正先进的 Vulkan 引擎的标志——从「把活干完」迈向「在正确的时间以正确的顺序把活干完」。
