= 子组操作：隐藏的力量

== 简介

前几章我们看了如何使用**共享内存（LDS）**和显式屏障，在工作组的数百甚至数千个线程之间共享数据。这种方法虽然强大，但代价显著：每次屏障都迫使 GPU 暂停等待，每次访问共享内存都消耗宝贵的带宽。

如果数据能以更快的速度共享呢？如果你能在完全不碰 VRAM 甚至不碰 LDS 的情况下交换数值呢？这正是**子组操作**的用武之地。它们是当今许多最高度优化的 GPU 算法背后的「秘方」。

== 为什么子组很重要

**子组**是硬件层面的线程批（NVIDIA/Intel 上通常是 32，AMD 上为 32/64），它们在同一个 SIMD 单元上完全同步地执行。由于硬件已经在物理上同步了这些线程，它们可以用专门的指令互相通信，速度往往只需一个时钟周期。

这并非桌面端专属的特性。来自 Arm、Qualcomm 和 Imagination 的移动端 GPU 也提供子组操作，但它们的宽度变化大得多（从 4 到 128 个通道不等），*必须*在运行时查询而不能假定——参见 xref:Advanced_Vulkan_Compute/12_Mobile_and_Embedded_Compute/02_android_compute.adoc[Android 上的计算]。在这类基于块的芯片上，把数据留在子组寄存器里而不是内存里，不只是速度上的收益；它直接省电并减少热降频。

本章我们将探索子组隐藏的力量：

1.  **跨调用通信**：利用子组洗牌、广播与算术运算，直接通过寄存器交换数据，完全绕开内存。
2.  **子组划分**：实现「Ballot」与「Match」操作，在整个批上做复杂的分支与数据筛选。
3.  **非一致索引**：借助现代 Vulkan 特性，安全地访问那些对子组中每个线程可能都不同的资源数组。

== 超越屏障

子组操作让你能为小规模数据交换写出「无屏障」内核。不必让工作组里每个线程都在屏障处等待，只为共享一个 float，你可以用子组洗牌把这个值瞬间传出去。

这带来：

*   **更高性能**：没有等待线程造成的管线停顿。
*   **更低延迟**：数据交换以寄存器速度完成。
*   **更大灵活性**：算法可以更「波前感知」，适应硬件原生的执行宽度。
