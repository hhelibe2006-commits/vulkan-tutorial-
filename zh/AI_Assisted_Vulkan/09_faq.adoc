= 常见问题与故障排查（FAQ）

== 引言

在实践 AI 辅助的 Vulkan 开发过程中，你会遇到的问题不只是技术 bug——隐私顾虑、编造的代码、硬件资源争抢，都会在实操中出现。本章介绍最常见的问题以及如何绕过它们。

== 隐私与知识产权安全

**Q：“我在开发一个专有的渲染引擎。我怎样才能确保源代码不外泄，也不会被拿去训练其他模型？”**

**A：** 让代码保持私密最可靠的办法，是把本地推理（Ollama、LM Studio）当作日常主力。在自己的硬件上运行 Qwen 3-Coder 这类模型，意味着你的着色器和 C{pp} 文件从不离开本机。一种常见做法是：日常实现用本地模型，而把 Claude、GPT 这类云端模型留给更高层的系统设计，并且通过 API 访问（而不是消费级聊天产品），这样你的数据就不会被用于训练。

== 准确性与幻觉

**Q：“AI 总是建议一些凭空发明的扩展或者 Vulkan 1.0 的过时写法。我花在修 AI 代码上的时间比自己写还多。”**

**A：** 这几乎总是上下文问题——模型没有所需的信息，就拿训练数据里听起来合理的东西来填补空缺。通过模型上下文协议（MCP）把助手接到 `vk.xml` 注册表，它就能查阅当前的结构体和扩展定义，而不是靠猜。在会话开头明确设定基线也很有帮助，例如：*“我们用的是启用动态渲染的 Vulkan 1.3。除非我明确要求兼容旧写法，否则不要建议 `VkRenderPass` 或 `VkFramebuffer`。”* 对于有强烈自有风格的项目，一个小型 LoRA 适配器能让模型默认遵循你的引擎约定和分配模式——参见 xref:AI_Assisted_Vulkan/03_model_selection_specialization/05_fine_tuning_lora.adoc[第 3.5 章]。

== 多模态与视觉能力的局限

**Q：“我把天空盒上一处细微的色带问题截图发了过去，AI 却说图像很清楚。为什么它看不到这个 bug？”**

**A：** 大多数多模态模型在处理输入图像之前会先缩小尺寸，常常缩到 1024x1024 甚至更小。在 4K 画面里只占几个像素的瑕疵，很可能被这种缩小直接抹平。发送前先把截图裁剪好，让瑕疵占据画面的大部分——如果问题占图像的 80% 而不是 2%，模型抓到的可能性就大得多。

== 硬件与 VRAM 管理

**Q：“每当 AI 开始生成代码，我的 Vulkan 应用就带着‘设备丢失’（TDR）错误崩溃。我需要换新 GPU 吗？”**

**A：** 你很可能撞上了超时检测与恢复（TDR）事件，因为 AI 和渲染器在同时争抢整块 GPU。试试 4 位（Q4_K_M）量化来缩小模型的 VRAM 占用，并限制推理引擎（Ollama、LM Studio）卸载到 GPU 的层数，给渲染器留出余量。如果你经常做这类工作，用一块较旧的第二块 GPU 专门跑模型（哪怕只能装下 7-8B 的模型），就能把主卡完全让给 Vulkan。

**Q：“我在 Ollama 里下载了一个模型，但它跑不起来，甚至把系统搞崩了。这是怎么回事？”**

**A：** 下载了模型，并不代表它就能塞进你的 VRAM。如果你加载的是超出可用 VRAM 的 30B 级模型，Ollama 可能把一些层卸载到系统内存，这会慢得多，并可能导致整个系统卡死，或者让你的 Vulkan 应用报设备丢失。加载之前，先拿模型大小对照你的 VRAM 预算（参见 xref:AI_Assisted_Vulkan/03_model_selection_specialization/03_hardware_vram.adoc[第 3.3 章]）。

**Q：“我该用 Ollama 的 WebUI（localhost），还是原生应用？”**

**A：** 对图形开发来说，原生应用（或 CLI）通常更合适。它能直接利用操作系统的硬件调度，在与 IDE 扩展和 Goose 这类代理通信时延迟往往更低。基于浏览器的 WebUI 用来管理和浏览模型没问题，但如果你发现渲染器运行时 AI 响应变慢，就换回原生后台服务。

**Q：“我给 Goose 加了一个扩展（比如文件系统访问），但它不工作。怎么启用？”**

**A：** 在某些版本的 Goose 里，只把扩展写进配置还不够——还得在当前的 recipe 中启用它。检查 Goose 设置，确认该扩展已被勾选，或者对你正在使用的任务配置文件放开。否则，代理可能知道这个工具存在，却无权在当前会话里调用它。

== 小结

上面这些问题，大多归结为同样的几件事：给模型准确的上下文，给它足够的视觉细节，别让它（或你的渲染器）缺 GPU 资源。这些都不需要你放弃自己思考 Vulkan 规范——恰恰相反，理解这些失败模式，才能让你用这些工具而不被它们坑。
