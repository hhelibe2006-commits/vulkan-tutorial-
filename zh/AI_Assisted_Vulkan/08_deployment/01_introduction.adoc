= 桌面、移动与嵌入式部署

== 引言：多平台链路

Vulkan 最大的优势在于可移植性。一个写得好的应用，既能跑在高端的 Windows 桌面上，也能跑在三星智能手机和树莓派上。而每个平台在内存管理、资产加载和性能优化方面都有自己的约束。

AI 助手在这里之所以有用，主要是因为它可以预先拿到这些平台约束并一直记着：它能帮你编写移动端那些繁琐的 JNI 样板代码，给出适合基于瓦片的 GPU 的优化建议，并在你即将超出嵌入式目标的资源上限时提醒你。

== 为助手提供平台上下文

本章的做法是：在向助手索要代码之前，先把你目标平台的具体硬件约束交给它，用的还是本系列前面介绍过的 MCP/RAG 配置：

1.  **移动端：** 让它关注基于瓦片的延迟渲染（TBDR）。有了这个上下文，它就更擅长优先考虑子通道依赖和无内存附件，从而把数据留在片上的瓦片内存里。
2.  **桌面端：** 把相关厂商扩展的取舍交给它，这样它才能告诉你——比如什么时候 `VK_NV_ray_tracing` 值得用来替代跨厂商的 `VK_KHR_ray_tracing_pipeline`。
3.  **嵌入式：** 把你的 VRAM 和 CPU 预算交给它，这样它给出的着色器与纹理量化策略才真正适配你的目标，而不是泛泛而谈。

== 为什么这里特别需要 AI

部署代码大多是胶水：仅仅为了在某个平台上让窗口表面和资产加载器跑起来，就要写上几百行 JNI 或 Objective-C{pp}。手写这些很枯燥，而只要你把引擎的资产结构和目标平台描述清楚，AI 助手很容易就能正确地起草出来——但你仍然需要审阅，因为恰恰是这类平台相关的代码，一个细微的错误（生命周期搞错、线程假设搞错）要等到真机上才会暴露。
