= 设定合理预期：视觉能力的边界

== 简介

到这一步，你已经有一个能相当快速地识别阴影痤疮、Z-fighting 和色带的助手了。值得把它的能力边界讲清楚：它是诊断辅助工具，不是编译器，而且它看不到你真实的 GPU 状态——只看到你给它的那些像素。

== 像素不是状态

多模态模型只看得到截图中的二维像素数组。除非你把上下文直接交给它，否则它接触不到你实际的 Vulkan 对象。

例如，一个闪烁的画面可能被诊断为 Z-fighting，而真正的原因却是同步危险——一种竞争条件：在上一次写入完成之前你就从图像读取。仅凭像素来看，深度冲突与同步相关的闪烁几乎一模一样。请把视觉诊断当作需要用验证层和 RenderDoc 核对的假设，而不是已确认的答案。

== 分辨率限制

多数多模态模型在处理前会先缩小图像——一张 4K 截图可能在视觉编码器看到它之前就被压缩了不少。这恰恰会抹掉你想诊断的高频细节：亚像素走样、微小闪烁、细窄的纹理接缝。如果明明有一个肉眼可见的闪烁伪影，模型却说图像看起来没问题，那就先紧贴着受影响区域裁剪——这样伪影能占据模型更多有效分辨率。

== 硬件差异

Vulkan 是显式的，同一个缺陷在不同厂商硬件上可能表现不同——一个在 NVIDIA 上出现的伪影，在 AMD 上或移动端 Adreno GPU 上可能呈现为另一副样子。除非你告诉模型，否则它无从知道你面向哪种硬件。如果你在做移动端，就直接说明：「我在基于分块延迟渲染器（TBDR）架构上调试。」这一句话就能把合理的下一步从「检查你的屏障」变成「检查你的子通道依赖以及 load/store 操作」。

== 小结

多模态模型有助于快速缩小范围，判断你看到的是哪一类常见嫌疑对象。它不能替代你亲自验证同步、内存安全或驱动相关的行为。
