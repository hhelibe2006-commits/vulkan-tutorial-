= 逻辑设备与队列

== 简介

选定要使用的物理设备之后，我们需要创建一个 *逻辑设备* 来与它交互。逻辑设备的创建过程与实例的创建过程类似，同样描述了我们要使用的特性。既然已经查询了有哪些队列族可用，我们还需要指定要创建哪些队列。如果你的需求各不相同，甚至可以从同一个物理设备创建多个逻辑设备。

首先添加一个新的类成员来保存逻辑设备句柄。

[,c++]
----
vk::raii::Device device = nullptr;
----

接下来添加一个 `createLogicalDevice` 函数，在 `initVulkan` 中调用它。

[,c++]
----
void initVulkan() {
    createInstance();
    setupDebugMessenger();
    pickPhysicalDevice();
    createLogicalDevice();
}

void createLogicalDevice() {

}
----

== 指定要创建的队列

创建逻辑设备同样要通过一系列结构体指定许多细节，其中第一个是 `vk::DeviceQueueCreateInfo`。这个结构体描述我们希望从单个队列族中获取多少个队列。目前我们只关心一个具备图形能力的队列。

[,c++]
----
std::vector<vk::QueueFamilyProperties> queueFamilyProperties = physicalDevice.getQueueFamilyProperties();
auto graphicsQueueFamilyProperty = std::ranges::find_if(queueFamilyProperties, [](auto const &qfp) { return (qfp.queueFlags & vk::QueueFlagBits::eGraphics) != static_cast<vk::QueueFlags>(0); });
auto graphicsIndex = static_cast<uint32_t>(std::distance(queueFamilyProperties.begin(), graphicsQueueFamilyProperty));
vk::DeviceQueueCreateInfo deviceQueueCreateInfo { .queueFamilyIndex = graphicsIndex };
----

目前可用的驱动只允许你为每个队列族创建少量队列，而你实际上并不需要多于一个。因为你可以在多个线程上创建所有命令缓冲区，然后在主线程上用一次低开销的调用把它们全部提交。

Vulkan 允许你用 `0.0` 到 `1.0` 之间的浮点数给队列指定优先级，以影响命令缓冲区执行的调度。即使只有一个队列，这也是必需的：

[,c++]
----
float queuePriority = 0.5f;
vk::DeviceQueueCreateInfo deviceQueueCreateInfo { .queueFamilyIndex = graphicsIndex, .queueCount = 1, .pQueuePriorities = &queuePriority };
----

== 指定使用的设备特性

接下来要指定的是我们要使用的设备特性集合。这些就是我们在上一章用 `vk::raii::PhysicalDevice::getFeatures` 查询过支持情况的特性，比如几何着色器。目前我们不需要任何特殊特性，所以直接定义它、把所有项都留作 `vk::False` 即可。等我们准备用 Vulkan 做更有意思的事情时，再回头处理这个结构体。

[,c++]
----
vk::PhysicalDeviceFeatures deviceFeatures;
----

== 启用额外的设备特性

Vulkan 在设计上保持向后兼容，这意味着默认情况下你只能访问 Vulkan 1.0 就已具备的基础特性。要使用更新的特性，你需要在创建设备时显式请求它们。

在 Vulkan 中，特性按引入时间或所属功能被组织到不同的结构体中。例如：

- 基础特性在 `vk::PhysicalDeviceFeatures` 中
- Vulkan 1.3 特性在 `vk::PhysicalDeviceVulkan13Features` 中
- 扩展专属特性位于各自的结构体中（如 `vk::PhysicalDeviceExtendedDynamicStateFeaturesEXT`）

要启用多组特性，Vulkan 使用了称为“结构体链式串联”的概念。每个特性结构体都有一个 `pNext` 字段，可以指向另一个结构体，从而形成一条特性请求链。

C++ 的 Vulkan API 提供了一个辅助模板 `vk::StructureChain`，让这个过程更简单。看看怎么用它：

[,c++]
----
// Create a chain of feature structures
vk::StructureChain<vk::PhysicalDeviceFeatures2,
                   vk::PhysicalDeviceVulkan11Features,
                   vk::PhysicalDeviceVulkan13Features,
                   vk::PhysicalDeviceExtendedDynamicStateFeaturesEXT>
    featureChain = {
        {},                                    // vk::PhysicalDeviceFeatures2 (empty for now)
        {.shaderDrawParameters = true},        // Enable shader draw parameters from Vulkan 1.1
        {.dynamicRendering = true},            // Enable dynamic rendering from Vulkan 1.3
        {.extendedDynamicState = true}         // Enable extended dynamic state from the extension
    };
----

这段代码做了以下几件事：

1. 我们创建一个包含三种不同特性结构体的 `vk::StructureChain`。
2. 为链中的每个结构体提供一个初始化器：
   - 第一个结构体（`vk::PhysicalDeviceFeatures2`）用 `{}` 留空
   - 在第二个结构体中，我们启用 Vulkan 1.1 的 `shaderDrawParameters` 特性
   - 在第三个结构体中，我们启用 Vulkan 1.3 的 `dynamicRendering` 特性
   - 在第四个结构体中，我们启用某个扩展的 `extendedDynamicState` 特性

`vk::StructureChain` 模板会通过在结构体之间设置 `pNext` 指针，自动把它们连接起来。这样我们就不必手动把每个结构体链接到下一个。

稍后创建逻辑设备时，我们会传入指向这条链中第一个结构体的指针，这样 Vulkan 就能看到我们想启用的所有特性。

== 指定设备扩展

为了让应用正常工作，我们需要启用某些设备扩展。这些扩展提供我们在教程后面会用到的额外功能。

[,c++]
----
std::vector<const char*> requiredDeviceExtension = {
    vk::KHRSwapchainExtensionName};
----

`VK_KHR_swapchain` 扩展是把渲染出的图像呈现到窗口所必需的。其他扩展提供的额外功能会在教程后面的部分用到。

== 创建逻辑设备

所需信息都准备好之后，我们就可以创建逻辑设备了。需要填充 `vk::DeviceCreateInfo` 结构体，并把我们的特性链连接到它上面：

[,c++]
----
vk::DeviceCreateInfo deviceCreateInfo{
    .pNext = &featureChain.get<vk::PhysicalDeviceFeatures2>(),
    .queueCreateInfoCount = 1,
    .pQueueCreateInfos = &deviceQueueCreateInfo,
    .enabledExtensionCount = static_cast<uint32_t>(requiredDeviceExtension.size()),
    .ppEnabledExtensionNames = requiredDeviceExtension.data()
};
----

回顾一下我们是如何把特性链接入设备创建过程的：

1. `featureChain.get<vk::PhysicalDeviceFeatures2>()` 方法取得链中第一个结构体（即 `vk::PhysicalDeviceFeatures2` 结构体）的引用。

2. 我们把这个引用赋给 `deviceCreateInfo` 结构体的 `pNext` 字段。

3. 由于特性链中的所有结构体已经连接好（这归功于 `vk::StructureChain`），Vulkan 沿着 `pNext` 指针链就能看到我们想启用的所有特性。

这种方式让我们能以清晰、有条理的方式请求多组特性。Vulkan 会处理链中的每个结构体，并在创建设备时启用所请求的特性。

其余信息与 `vk::InstanceCreateInfo` 结构体类似，需要你指定扩展。区别在于这次是设备专属的扩展。

设备专属扩展的一个例子是 `VK_KHR_swapchain`，它允许你把该设备渲染出的图像呈现到窗口。系统中可能存在缺少这一能力的 Vulkan 设备，比如只支持计算操作的设备。我们会在交换链一章回头讨论这个扩展。

以前版本的 Vulkan 实现区分实例验证层和设备专属验证层，但 link:https://docs.vulkan.org/spec/latest/chapters/raytracing.html#extendingvulkan-layers-devicelayerdeprecation[现在已经不是这样了]。这意味着 `vk::DeviceCreateInfo` 的 `enabledLayerCount` 和 `ppEnabledLayerNames` 字段会被最新的实现忽略。

`vk::DeviceCreateInfo` 填好之后，我们就可以继续创建逻辑设备了。

[,c++]
----
device = vk::raii::Device(physicalDevice, deviceCreateInfo);
----

传入的参数是要与之交互的物理设备，以及我们刚才指定的创建信息。额外的可选参数包括分配回调指针，以及指定在何处保存所创建逻辑设备句柄的指针。在我们的用法中，函数调用直接返回 `vk::Device` 句柄。与实例创建函数类似，如果启用了不存在的扩展或指定使用不受支持的特性，这个调用会抛出错误。

逻辑设备不直接与实例交互，因此实例没有作为参数包含进来。

== 获取队列句柄

队列会随逻辑设备一起自动创建，但我们还没有可以用来访问它们的句柄。首先添加一个类成员来保存图形队列的句柄：

[,c++]
----
vk::raii::Queue graphicsQueue = nullptr;
----

设备队列在设备销毁时会被隐式清理，所以我们不需要在 `cleanup` 中做任何事。

我们可以用 `vk::raii::Queue` 构造函数来获取某个队列族的队列句柄。参数是逻辑设备、队列族索引和队列索引。因为这个队列族中我们只创建一个队列，所以直接用队列索引 `0`。

[,c++]
----
graphicsQueue = vk::raii::Queue(device, graphicsIndex, 0);
----
