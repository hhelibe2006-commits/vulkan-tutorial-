= 基础代码

== Vulkan-hpp 与指定初始化器

NOTE: 我们将使用 C++ 20 引入的指定初始化器。
默认情况下，Vulkan-hpp 使用另一种初始化方式，我们需要通过 `VULKAN_HPP_NO_STRUCT_CONSTRUCTORS` 宏显式启用这一特性。

这样能更清楚地表达每个选项对应我们所依赖的结构体中的哪一项。
在本教程中，该宏在 xref:../../02_Development_environment.adoc#cmake[CMake 构建配置] 中声明。

如果你使用不同的构建配置，或者想从头编写代码，就需要在包含 Vulkan-hpp 头文件之前
像这样手动定义它：
[,c++]
----
#define VULKAN_HPP_NO_STRUCT_CONSTRUCTORS
#include <vulkan/vulkan.hpp>
// or
#include <vulkan/vulkan_raii.hpp>
----

== 总体结构

在上一章中，你已经创建了一个配置齐全的 Vulkan 工程，并用示例代码测试过。
本章我们将从零开始，使用下面的代码：

[,c++]
----
#if defined(__INTELLISENSE__) || !defined(USE_CPP20_MODULES)
#include <vulkan/vulkan_raii.hpp>
#else
import vulkan_hpp;
#endif
#include <GLFW/glfw3.h>

#include <iostream>
#include <stdexcept>
#include <cstdlib>

class HelloTriangleApplication {
----

`#if defined(\\__INTELLISENSE__) || !defined(USE_CPP20_MODULES)` 这个块在两种引入 Vulkan-Hpp API 的
方式之间做选择，两者提供的函数、结构体和枚举都相同。默认情况下我们包含传统的
`<vulkan/vulkan_raii.hpp>` 头文件。如果你启用 C{pp}20 模块
（`-DENABLE_CPP20_MODULE=ON`），CMake 设置的 `USE_CPP20_MODULES` 宏会让代码改为
`import vulkan_hpp;`。无论哪种方式，Visual Studio 和 VS Code 的 IntelliSense 引擎目前
都不理解模块的 `import`，即使代码能正常编译也会把它标为错误，所以只要定义了
`\\__INTELLISENSE__`（IntelliSense 自身在分析代码时会定义它），或者完全关闭了模块，
我们就回退到头文件方式。

[,c++]
----
public:
    void run() {
        initVulkan();
        mainLoop();
        cleanup();
    }

private:
    void initVulkan() {

    }

    void mainLoop() {

    }

    void cleanup() {

    }
};

int main()
{
    try
    {
        HelloTriangleApplication app;
        app.run();
    }
    catch (const std::exception& e)
    {
        std::cerr << e.what() << std::endl;
        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}
----

包含 `stdexcept` 和 `iostream` 头文件是为了报告和传播错误。
`cstdlib` 头文件提供 `EXIT_SUCCESS` 和 `EXIT_FAILURE` 宏。

程序本身被封装在一个类里，我们会把 Vulkan 对象作为类的私有成员保存，
并添加用于初始化每个对象的函数，这些函数将从 `initVulkan` 函数中调用。
一切准备就绪后，我们进入主循环开始渲染帧。
稍后我们会为 `mainLoop` 函数填充一个循环，反复迭代直到窗口关闭。
窗口关闭且 `mainLoop` 返回后，我们会在 `cleanup` 函数中释放用过的资源。

如果执行过程中发生任何致命错误，我们会抛出一个带描述信息的 `std::runtime_error` 异常，
它会传播回 `main` 函数并打印到命令行。为了也能处理各种标准异常类型，
我们还捕获更通用的 `std::exception`。我们很快就会遇到的一个错误示例，
是发现某个必需的扩展不受支持。

大致上，本章之后的每一章都会新增一个由 `initVulkan` 调用的函数，
以及一个或多个新的 Vulkan 对象，作为私有类成员在最后由 `cleanup` 释放。

== 资源管理

就像每次用 `malloc` 分配的内存都需要调用 `free` 一样，
我们创建的每个 Vulkan 对象在不再需要时都必须显式销毁。
在 c{pp} 中，可以用
https://en.wikipedia.org/wiki/Resource_Acquisition_Is_Initialization[RAII]
或者 `<memory>` 头文件提供的智能指针来实现自动资源管理。
本教程试图让 Vulkan 更易用，并展示现代 Vulkan 编程。
本教程不仅会使用 RAII，还会努力演示最新的方法和扩展，希望能让使用 Vulkan 成为一件愉快的事。
仅仅因为我们自己喜欢与底层图形 API 打交道，不应该把学习它的门槛设得太高。
在合适的地方，我们会讨论释放资源时的资源管理问题。
不过在本教程中，我们将演示用一个基本的析构函数就能走得很远，完成收尾工作。

Vulkan 对象要么用 `vkCreateXXX` 这类函数直接创建，
要么通过另一个对象用 `vkAllocateXXX` 这类函数分配。
在确认某个对象不再被任何地方使用后，需要用对应的 `vkDestroyXXX` 和 `vkFreeXXX` 销毁它。
这些函数的参数通常因对象类型而异，但有一个参数是所有函数共有的：`pAllocator`。
这是一个可选参数，允许你为自定义内存分配器指定回调。
本教程将忽略这个参数，始终传入 `nullptr` 作为实参。

使用 Vulkan_hpp 的 RAII 模块，我们可以依赖库来处理
`vkCreateXXX` `vkAllocateXXX` `vkDestroyXXX` 和 `vkFreeXXX`，
所以像这样的代码块：

[,c++]
----
VkInstance instance;
VkApplicationInfo appInfo{};
appInfo.sType = VK_STRUCTURE_TYPE_APPLICATION_INFO;
appInfo.pApplicationName = "Hello Triangle";
appInfo.applicationVersion = VK_MAKE_VERSION(1, 0, 0);
appInfo.pEngineName = "No Engine";
appInfo.engineVersion = VK_MAKE_VERSION(1, 0, 0);
appInfo.apiVersion = VK_API_VERSION_1_0;

VkInstanceCreateInfo createInfo{};
createInfo.sType = VK_STRUCTURE_TYPE_INSTANCE_CREATE_INFO;
createInfo.pApplicationInfo = &appInfo;
createInfo.enabledExtensionCount = 0;
createInfo.ppEnabledExtensionNames = nullptr;
createInfo.enabledLayerCount = 0;
createInfo.ppEnabledLayerNames = nullptr;

if (vkCreateInstance(&createInfo, nullptr, &instance) != VK_SUCCESS) {
    throw std::runtime_error("failed to create instance!");
}

vkDestroyInstance(instance, nullptr);
----

可以直接替换为：

[,c++]
----
constexpr vk::ApplicationInfo appInfo{.pApplicationName   = "Hello Triangle",
                                      .applicationVersion = VK_MAKE_VERSION( 1, 0, 0 ),
                                      .pEngineName        = "No Engine",
                                      .engineVersion      = VK_MAKE_VERSION( 1, 0, 0 ),
                                      .apiVersion         = vk::ApiVersion14};

vk::InstanceCreateInfo createInfo{
    .pApplicationInfo = &appInfo
};

instance = vk::raii::Instance(context, createInfo);
----

== 集成 GLFW

如果你想用 Vulkan 做离屏渲染，那么完全不创建窗口也没问题，
但实际显示出东西来会令人兴奋得多！
首先，我们加入 GLFW：注意，我们会继续使用 GLFW_INCLUDE_VULKAN，因为 GLFW 的设计是获取 Vulkan
表面，但它直接使用 C 的表面。除了这个用途之外，我们可以使用 GLFW_INCLUDE_NONE
或者不作这项指定，其它一切都能正常工作。

[,c++]
----
#define GLFW_INCLUDE_VULKAN
#include <GLFW/glfw3.h>
----

这样，GLFW 会包含它自己的定义，并随之自动加载 Vulkan 的 C 头文件。
添加一个 `initWindow` 函数，并在 `run` 函数中于其它调用之前调用它。
我们将用这个函数初始化 GLFW 并创建窗口。

[,c++]
----
void run() {
    initWindow();
    initVulkan();
    mainLoop();
    cleanup();
}

private:
    void initWindow() {
    }
----

`initWindow` 中的第一个调用应该是 `glfwInit()`，它初始化 GLFW 库。
由于 GLFW 最初是为创建 OpenGL 上下文而设计的，我们需要通过后面的调用来告诉它不要创建 OpenGL 上下文：

[,c++]
----
glfwWindowHint(GLFW_CLIENT_API, GLFW_NO_API);
----

因为处理窗口大小变化需要额外的处理，我们稍后再研究，所以现在用另一个窗口提示调用把它禁用：

[,c++]
----
glfwWindowHint(GLFW_RESIZABLE, GLFW_FALSE);
----

现在剩下的就是创建实际的窗口。添加一个 `GLFWwindow* window;` 私有类成员来保存对它的引用：

[,c++]
----
private:
    GLFWwindow *window = nullptr;
----

然后用以下代码初始化窗口：

[,c++]
----
window = glfwCreateWindow(800, 600, "Vulkan", nullptr, nullptr);
----

前三个参数指定窗口的宽度、高度和标题。
第四个参数允许你选择在哪个显示器上打开窗口，最后一个参数只与 OpenGL 相关。

用常量代替硬编码的宽度和高度数值是个好主意，因为以后我们会多次引用这些值。
我在 `HelloTriangleApplication` 类定义上方添加了以下代码行：

[,c++]
----
constexpr uint32_t WIDTH = 800;
constexpr uint32_t HEIGHT = 600;
----

并把窗口创建调用替换为

[,c++]
----
window = glfwCreateWindow(WIDTH, HEIGHT, "Vulkan", nullptr, nullptr);
----

现在你的 `initWindow` 函数应该长这样：

[,c++]
----
void initWindow() {
    glfwInit();

    glfwWindowHint(GLFW_CLIENT_API, GLFW_NO_API);
    glfwWindowHint(GLFW_RESIZABLE, GLFW_FALSE);

    window = glfwCreateWindow(WIDTH, HEIGHT, "Vulkan", nullptr, nullptr);
}
----

为了让程序一直运行，直到发生错误或窗口关闭，我们需要在 `mainLoop` 函数中加入如下事件循环：

[,c++]
----
void mainLoop() {
    while (!glfwWindowShouldClose(window)) {
        glfwPollEvents();
    }
}
----

这段代码应该相当直观。它循环检查诸如点击 X 按钮之类的事件，直到用户关闭窗口。
稍后我们也会在这个循环里调用函数来渲染单帧。

窗口关闭后，我们需要销毁窗口并终止 GLFW 本身来清理资源。这将是我们最初的 `cleanup` 代码：

[,c++]
----
void cleanup() {
    glfwDestroyWindow(window);

    glfwTerminate();
}
----

注意，在本教程中，这是我们最后一次需要在 cleanup() 函数里做任何事。
这段代码以后再也不需要改动。

现在运行程序，你应该能看到一个标题为 `Vulkan` 的窗口，直到你关闭窗口终止程序。

NOTE: 在 Wayland 上，合成器直到窗口的第一个缓冲区被呈现后才会真正映射（显示）窗口。
由于我们还没有创建交换链，也没有绘制任何东西，如果你在 Wayland 下运行时此刻看不到窗口，
不必惊讶——这是预期行为，等教程后面进行到呈现图像时窗口就会出现。
这是 Wayland 特有的行为；如上所述，X11 会立即显示窗口。
